## ex121 位掩码三个操作

**输出**：

```text
  x              = 00001010  (10)
置位 bit0 后 = 11
    二进制    = 00001011  (11)
清位 bit3 后 = 3
    二进制    = 00000011  (3)
测试 bit1 = 1
测试 bit2 = 0
```

**关键点**

```c
unsigned int setBit(unsigned int x, int n)   { return x | (1u << n); }
unsigned int clearBit(unsigned int x, int n) { return x & ~(1u << n); }
int          testBit(unsigned int x, int n)  { return (int)((x >> n) & 1u); }
```

> ⭐ **用 `1u` 不用 `1`。**
> `1` 是 `int`，`1 << 31` 会让符号位变 1，属于有符号溢出（未定义行为）。
> `1u` 是无符号，`1u << 31` 得到 `2147483648`，正确。

## ex122 统计 1 的个数与 2 的幂

**输出**：

```text
数值   1 的个数  是否 2 的幂
0        0            不是
1        1            是
2        1            是
3        2            不是
7        3            不是
8        1            是
16       1            是
100      3            不是
255      8            不是
1024     1            是
```

**关键点**

```c
int countOnes(unsigned int x) {
    int cnt = 0;
    while (x) { x &= x - 1; cnt++; }
    return cnt;
}

int isPowerOfTwo(unsigned int x) {
    return x != 0 && (x & (x - 1)) == 0;
}
```

> ⚠️ **`x != 0` 不能省。** `0 & (0-1)` = `0 & 0xFFFFFFFF` = `0`，会把 0 误判成 2 的幂。

> ⭐ 注意 `255` 的 1 的个数是 **8**，不是 7 —— 手算时容易差错。
> 验证：`255 = 1111 1111`，确实是 8 个。

## ex123 三个位运算技巧

**输出**（节选）：

```text
7 是奇数
-4 是偶数
0 是偶数
3 是奇数
-9 是奇数

-7 % 2 = -1，不是 1

交换前 a=5 b=9
交换后 a=9 b=5

|7| = 7
|-7| = 7
|0| = 0
```

**关键点**

1. **判奇偶用 `x & 1`**，因为负数取余是负数：

```c
-7 % 2 == -1     /* 不是 1 */
```

写成 `x % 2 == 1` 的话，`-7` 会被判成偶数。

2. **异或交换**的三行：

```c
*a ^= *b;  *b ^= *a;  *a ^= *b;
```

> ⚠️ `a` 和 `b` 是同一变量时，`a ^= a` 会清零。工程上别用。

3. **位运算求绝对值**：

```c
int mask = x >> 31;          /* 负数得 -1，正数得 0 */
return (x + mask) ^ mask;
```

以 `x = -7` 为例：`mask = -1`，`x + mask = -8`，`-8 ^ -1 = 7`。

> ⚠️ `INT_MIN`（-2147483648）没有对应的正数，任何写法都会溢出。

## ex124 安全的宏

**输出**：

```text
MAX(3, 4) = 4
2 * MAX(3, 4) = 8   ← 如果宏没外层括号会变成 3*2=6
MIN(3, 4) = 3
MAX(a + 1, b) = 4   ← 参数括号的作用
SQUARE(1 + 2) = 9   ← 不带括号会算成 1+2*1+2=5
CLAMP(15, 0, 10)  = 10
CLAMP(-5, 0, 10)  = 0
CLAMP(5, 0, 10)   = 5
```

**关键点**

```c
#define MAX(a, b)         ((a) > (b) ? (a) : (b))
#define MIN(a, b)         ((a) < (b) ? (a) : (b))
#define SQUARE(x)         ((x) * (x))
#define CLAMP(x, lo, hi)  (MIN(MAX((x), (lo)), (hi)))
```

> ⭐ `CLAMP` 是「宏套宏」，能成立是因为宏展开是递归的：
> `CLAMP(15,0,10)` → `(MIN(MAX((15),(0)),(10)))` → `(((15)>(0)?(15):(0)) < (10) ? ... )`

> ⚠️ 这些宏仍然有副作用问题：`MAX(i++, j)` 会让 `i` 自增两次。
> 绝对安全要用 `static inline` 函数。

## ex125 条件编译

**不带任何 `-D`**：

```text
result = 3

本次编译的开关状态：
  DEBUG    = 关
  VERBOSE  = 关
  LANG_CN  = 关（英文）
```

**全开（`-DDEBUG -DVERBOSE -DLANG_CN`）**：

```text
[调试] 程序开始运行
[详细] 正在计算 1 + 2
结果 = 3
[调试] 程序结束
```

**关键点**

1. `#ifdef LANG_CN` 选语言，`#else` 分支给英文。
2. `#define DBG(...) ((void)0)` 把调试输出变成空语句 —— **不产生任何运行时代价**。
3. 每个 `#ifdef` 都要有 `#endif`，漏了会报 `unterminated #ifdef`。

> ⭐ **核心理解：宏没定义时那一段代码根本不参与编译**，不是 `if (0)` 那种「编译了但不执行」。
> 所以 `#if` 里的代码即使有语法错误，只要不开这个宏就不会报错。

## ex126 位域压缩 RGB

**输出**：

```text
=== struct RGB（每通道 8 位）===
  sizeof = 4 字节
  r=200 g=150 b=100

=== struct RGB16（RGB565）===
  sizeof = 4 字节
  r=8 g=22 b=4
```

**为什么被截断**

| 原值 | 二进制 | 位数 | 保留低位 | 结果 |
|---|---|---|---|---|
| 200 | `1100 1000` | 5 | `01000` | 8 |
| 150 | `1001 0110` | 6 | `010110` | 22 |
| 100 | `0110 0100` | 5 | `00100` | 4 |

验算：`200 & 31 = 8`，`150 & 63 = 22`，`100 & 31 = 4`。

**两个 `sizeof` 都是 4 的原因**

不是位数相同，而是**声明类型是 `unsigned int`**，编译器按 `int` 分配存储单元。

用 `unsigned short` 作位域类型，16 位正好装满：

```c
struct RGB16s {
    unsigned short r : 5;
    unsigned short g : 6;
    unsigned short b : 5;
};
/* sizeof = 2 字节 */
```

> ⭐ 这才是 RGB565 的正确写法 —— 真的省一半内存。

## 汇总：本周六个坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 用 `1` 而不是 `1u` 做移位 | `1<<31` 有符号溢出 |
| 2 | `if (perm & need)` 当「都有」 | 只有一个也通过 |
| 3 | `isPowerOfTwo` 不排 0 | 0 被判成 2 的幂 |
| 4 | 带参宏少括号 | `SQ(1+2)` 得 5 不是 9 |
| 5 | 多语句宏不用 `do-while(0)` | `if/else` 编译失败 |
| 6 | 以为位域按位精确分配 | 以为 3 个 1 位字段占 1 字节 |
