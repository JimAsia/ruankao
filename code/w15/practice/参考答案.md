## ex151 判断三段代码的复杂度

**实测输出**：

```text
=== 段 1（i += 3）===
  n=9    3 次
  n=27   9 次
  n=81   27 次
  我的判断：O(n)

=== 段 2（i *= 3）===
  n=9    2 次
  n=27   3 次
  n=81   4 次
  我的判断：O(log n)

=== 段 3（内层 j 从 n 到 i）===
  n=9    45 次
  n=27   378 次
  n=81   3321 次
  我的判断：O(n^2)
```

**三段解析**

**段 1：`i += 3` → O(n)**
n 变 3 倍，次数也变 3 倍。步长 3 只让次数除以 3，**除以常数不改变量级**。

**段 2：`i *= 3` → O(log n)**
n 变 3 倍，次数只多 1。次数是 `log₃n`，**底数不影响量级**。

**段 3：内层递减 → O(n²)**

> ⚠️ **这题最容易错。** 内层次数在变（n, n-1, n-2, ...），很多人以为是 O(n log n)。
>
> 正确做法是**求和**：
> ```text
> sum(n - i) for i = 0..n-1
> = n + (n-1) + (n-2) + ... + 1
> = n(n+1)/2
> ```
> 验证：n=9 → 45，n=27 → 378，n=81 → 3321，全部吻合 `n(n+1)/2`。

> ⭐ **口诀：内层边界依赖外层时，一律求和，不要凭感觉。**

## ex152 顺序查找 vs 二分查找

**实测输出**：

```text
n          顺序查找     二分查找     快多少倍
100        100          12           8 倍
1000       1000         18           56 倍
10000      10000        26           385 倍
100000     100000       32           3125 倍
```

**关键点**

1. 测的是**最坏情况**（找不存在的 `-1`），顺序查找要走完全程。
2. 二分每次循环算 2 次比较（`a[mid]==key` 和 `a[mid]<key`），所以次数约 `2×log₂n`。
3. n 涨 1000 倍，顺序查找涨 1000 倍，二分只从 12 涨到 32。

**必考前提**

| 前提 | 原因 |
|---|---|
| 数据必须**有序** | 二分靠「中间值比大小」来决定往哪半走 |
| 必须能**随机访问** | 数组可以，链表不行（找中间要 O(n)） |

> ⭐ 无序数组想用二分要先排序（O(n log n)），只查一次反而更慢。
> 二分的价值在「查很多次」：排一次序，以后每次 O(log n)。

**`mid` 的写法**

```c
int mid = lo + (hi - lo) / 2;      /* ✅ 不会溢出 */
int mid = (lo + hi) / 2;           /* ⚠️ lo+hi 可能超过 INT_MAX */
```

## ex153 空间复杂度

**三个答案**

```text
f1 求和      ：时间 O(n)   空间 O(1)
f2 复制数组  ：时间 O(n)   空间 O(n)
f3 递归求和  ：时间 O(n)   空间 O(n)
```

**关键点**

1. **输入不算额外空间。** `f1` 的参数 `a[]` 有 n 个元素，但那是调用者的，f1 自己只开了 `sum` 和 `i`。
2. `f2` 用 `malloc` 申请了 n 个 int，所以要 `free`（本题已释放）。
3. `f3` 的递归深度是 n，每层一个栈帧 → 空间 O(n)。

**为什么递归的空间是 O(n)**

```text
f3(a, 1000)  ← 栈底，等待
  f3(a, 999)
    f3(a, 998)
      ...
        f3(a, 1)   ← 栈顶
```

这 1000 个帧**同时存在**（下面的还没返回）。所以是 1000 个栈帧的空间。

> ⚠️ n = 100000、每层 48 字节 = 4.8 MB，超过默认栈大小（1~8 MB）→ **栈溢出**。
> 这是「递归不能太深」的真正原因，不是「递归慢」。

**常见算法的空间复杂度**

| 算法 | 空间 | 额外用了什么 |
|---|---|---|
| 冒泡/选择/插入 | O(1) | 只要临时变量 |
| 归并排序 | O(n) | 合并要临时数组 |
| 快速排序 | O(log n) | 递归栈深度 |
| 堆排序 | O(1) | 原地调整 |
| 二分（迭代） | O(1) | 只要 lo/hi/mid |
| 二分（递归） | O(log n) | 递归栈 |

## ex154 三种排序的次数对比

**乱序数据 `64 25 12 22 11 90 45 33`**

```text
冒泡     比较 25   交换 14
选择     比较 28   交换  6
插入     比较 18   交换 14
```

**已排好序 `11 12 22 25 33 45 64 90`**

```text
冒泡     比较  7   交换  0
选择     比较 28   交换  0
插入     比较  7   交换  0
```

**三条结论**

**① 选择排序的比较次数与数据完全无关**

两种数据都是 **28** = `n(n-1)/2`。因为无论数据怎样，内层都要扫完才能确定最小值。

**② 冒泡加了提前退出，有序时只跑 1 趟**

7 次就结束（`n-1`）。不加优化的版本永远 28 次。

**③ 插入排序在近乎有序的数据上退化成 O(n)**

比较 7 次、移动 0 次。

> ⭐ 所以「数据基本有序」时应该选**插入排序**。

**三者对比**

| 算法 | 比较次数 | 交换次数 | 稳定性 |
|---|---|---|---|
| 冒泡 | `n(n-1)/2` | 逆序对个数 | 稳定 |
| 选择 | `n(n-1)/2` | ≤ n-1 | 不稳定 |
| 插入 | ≤ `n(n-1)/2` | 逆序对个数 | 稳定 |

## ex155 三个递归的复杂度

**实测输出**：

```text
n      r1 调用次数  r2 调用次数  r3 调用次数
8      4            15           9
16     5            31           17
32     6            63           33
64     7            127          65
```

**答案**

| 函数 | 形式 | 复杂度 |
|---|---|---|
| r1 | `T(n) = T(n/2) + 1` | **O(log n)** |
| r2 | `T(n) = 2T(n/2) + 1` | **O(n)** |
| r3 | `T(n) = T(n-1) + 1` | **O(n)** |

**r2 为什么是 O(n) 而不是 O(2ⁿ)**

这是本周最重要的一题。

```text
T(n) = 2T(n/2) + 1
T(1) = 1
→ T(n) = 2n - 1
```

验证：n=16 → 31 = 2×16-1 ✓，n=64 → 127 = 2×64-1 ✓

**直观理解**：画递归树

```text
层数 = log₂n
每层节点数：1, 2, 4, ..., n
叶子数 = 2^(log₂n) = n
总节点数 = 1 + 2 + 4 + ... + n = 2n - 1
```

> ⭐ **关键：看叶子数，不是看分支数。**
> - 「分 2 支 + 规模减半」→ 叶子 n 个 → O(n)
> - 「分 2 支 + 规模只减 1」→ 叶子 2ⁿ 个 → O(2ⁿ)

**一句话口诀**

```text
规模怎么变 × 分几支 = 复杂度
减 1 + 1 支  → O(n)
减半 + 1 支  → O(log n)
减半 + 2 支  → O(n)      ← 本题的坑
减 1 + 2 支  → O(2ⁿ)    ← 才会爆炸
```

## ex156 用复杂度预测耗时

**实测输出**：

```text
n          O(n)        O(n log n)   O(n^2)      O(2^n)
1000       0.0000秒    0.0001秒     0.0100秒    算不完
10000      0.0001秒    0.0013秒     1.00秒      算不完
100000     0.0010秒    0.0160秒     1.7分钟     算不完
1000000    0.0100秒    0.1900秒     2.8小时     算不完

=== 具体数字（n = 10^6）===
  O(n)       = 1000000 次操作  → 0.0100 秒
  O(n log n) = 19000000 次操作  → 0.19 秒
  O(n^2)     = 1000000000000 次操作  → 2.8 小时
```

**关键点**

1. `opsOf('b', n)` 里 `log₂n` 用循环算：`while (x > 1) { x /= 2; lg++; }`
2. `O(2ⁿ)` 在 n > 62 时 `long long` 就装不下了，直接返回 -1 表示「算不完」
3. 时间格式化要分段：秒 / 分钟 / 小时 / 天

**做题时的经验值（背下来）**

| n | 可用复杂度 |
|---|---|
| ≤ 10 | O(n!)、O(2ⁿ) |
| ≤ 1000 | O(n²) |
| ≤ 10⁵ | O(n log n) |
| ≤ 10⁷ | O(n) |
| 任意 | O(log n)、O(1) |

**三个常见误区**

1. 「O(n log n) 只比 O(n) 多一点」—— n=10⁶ 时差 20 倍
2. 「都是 O(n) 就一样快」—— 常数可能差 100 倍
3. 「小数据测过能跑就行」—— n=100 时 O(n²) 只要 0.1 毫秒，看不出问题

## 汇总：本周六个易错点

| # | 易错点 | 正确做法 |
|---|---|---|
| 1 | 内层边界依赖外层 → 以为 O(n log n) | **求和**，通常是 O(n²) |
| 2 | `2T(n/2)+1` 以为是指数级 | 看**叶子数**，是 O(n) |
| 3 | 忘了递归的空间是 O(深度) | 每层都有栈帧，同时存在 |
| 4 | 把输入数组算进额外空间 | 只算算法自己申请的 |
| 5 | 写 O(log₂ n) | 统一写 **O(log n)** |
| 6 | `O(n·m)` 合并成 O(n²) | 两个参数不能合并 |
