## ex181 顺序栈

**实测输出**：

```text
初始       栈底[]栈顶   top=-1  size=0
入栈后     栈底[1]栈顶   top=0  size=1
入栈后     栈底[1 2]栈顶   top=1  size=2
入栈后     栈底[1 2 3]栈顶   top=2  size=3

栈顶 = 3
```

**关键点**

```c
判空：top == -1
判满：top == MAXSIZE - 1        /* ⚠️ 不是 MAXSIZE */
个数：top + 1

入栈：S->data[++S->top] = v;     /* 先加后赋值 */
出栈：v = S->data[S->top--];     /* 先取值后减 */
```

> ⚠️ 判满写成 `top == MAXSIZE` 时，那一刻 `top` 已指向数组外，`data[top]` 就是越界写。

## ex182 括号匹配

**实测输出**：

```text
{[()()]}         → 匹配 ✓
(a+b)*[c-d]      → 匹配 ✓
((()))           → 匹配 ✓
{[(])}           → 不匹配 ✗  第 4 个字符 ']' 与栈顶 '(' 不配对
(()              → 不匹配 ✗  扫描完还有 1 个左括号没闭合
())              → 不匹配 ✗  第 3 个字符 ')' 多余（栈已空）
(空串)           → 匹配 ✓
```

**三种失败情况**

| 情况 | 判断位置 | 例子 |
|---|---|---|
| 右括号多余 | 出栈时栈空 | `())` |
| 类型不配对 | 栈顶和当前括号不是一对 | `{[(])}` |
| 左括号多余 | 扫完栈非空 | `(()` |

**为什么用栈**：括号匹配的本质是「最近打开的最先关闭」，正是后进先出。
所有嵌套结构（HTML 标签、JSON、函数调用）都能这么查。

复杂度：时间 O(n)，空间 O(n)。

## ex183 后缀求值 + 中缀转后缀

**后缀求值实测**：

```text
3 4 +                = 7
5 1 2 + 4 * + 3 -    = 14
2 3 *                = 6
8 2 /                = 4
1 2 + 3 *            = 9
6 2 - 3 +            = 7
3 4 -                = -1
```

**中缀转后缀实测**：

```text
1+2*3          → 1 2 3 * +
(1+2)*3        → 1 2 + 3 *
1+2+3          → 1 2 + 3 +
2*(3+4)-5      → 2 3 4 + * 5 -
((1+2)*(3+4))  → 1 2 + 3 4 + *
```

**关键点**

1. **求值时先弹出的是【右】操作数**：

```c
pop(&S, &b);        /* 右 */
pop(&S, &a);        /* 左 */
result = a - b;     /* ⚠️ 不是 b - a */
```

`3 4 -` 应得 `-1`，写反了得 `1`。

2. **转换时用 `>=` 不用 `>`**：

```text
>= ：1+2+3 → 1 2 + 3 +     左结合 ✓
>  ：1+2+3 → 1 2 3 + +     右结合 ✗
```

减法除法必须左结合，所以同优先级要弹出。

3. **`')'` 处理**：弹到 `'('` 为止，`'('` 本身不输出。

## ex184 循环队列

**实测输出（关键片段）**：

```text
入队后    front=0 rear=4 size=4 [1 2 3 4]
第 5 个失败 → 入队失败：队列满

出队后    front=2 rear=4 size=2 [3 4]
入队后    front=2 rear=0 size=3 [3 4 5]    ← rear 从 4 绕回 0
入队后    front=2 rear=1 size=4 [3 4 5 6]
```

**三个公式（默写）**

```c
判空：front == rear
判满：(rear + 1) % MAXSIZE == front
个数：(rear - front + MAXSIZE) % MAXSIZE
```

MAXSIZE=5 最多存 **4** 个（少用一个单元）。

**两个陷阱**

1. **遍历不能写 `for (i = front; i < rear; i++)`**
   `rear` 可能比 `front` 小，这样会一个都读不到。
   正确：`for (i = 0; i < size; i++) 读 data[(front+i)%MAXSIZE]`。

2. **个数公式的 `+MAXSIZE` 不能省**
   `rear - front` 可能是负数，C 里负数取模还是负数。

## ex185 滑动窗口最大值

**实测输出**：

```text
数组         [1 3 -1 -3 5 3 6 7]
暴力法       [3 3 5 5 6 7]
单调队列     [3 3 5 5 6 7]
两者一致 ✓
```

**单调队列四步**

```c
for (i = 0; i < n; i++) {
    ① 队尾所有 a[dq[tail-1]] <= a[i] 的出队
    ② dq[tail++] = i
    ③ 队头下标 < i-k+1 的出队（滑出窗口）
    ④ i >= k-1 时，a[dq[head]] 就是答案
}
```

**为什么被踢掉的永远不可能成为答案**

因为它们「又小又旧」：
- 值更小 → 后面有更大的会挡住它
- 下标更小 → 会先滑出窗口

> ⭐ 本质是队列（FIFO），但两端都要出队，所以严格说是**双端队列 deque**。

复杂度：暴力 O(n·k)，单调队列 O(n)（每个元素最多进出各一次）。

## ex186 栈与队列互转

**实测输出**：

```text
两个栈实现队列：入队 1 2 3 → 出队 1 2 3 ✓（FIFO）
混合操作：入 4 5 → 出 4 → 入 6 → 出 5 6 ✓
两个队列实现栈：入栈 1 2 3 → 出栈 3 2 1 ✓（LIFO）
```

**两个栈实现队列**

```text
inStack 压入 1 2 3（栈顶 3）
倒进 outStack 后栈顶变 1
依次弹出 → 1 2 3
⭐ 倒了两次，负负得正
```

关键：`transfer` 只在 `outStack` 空时做，否则顺序会乱。

**两个队列实现栈**

```text
入栈进 q1
出栈时把 q1 前 n-1 个搬到 q2，剩下那个弹出，再把 q2 搬回 q1
```

**复杂度对比（重点）**

| 实现 | 操作 | 复杂度 |
|---|---|---|
| 两个栈 → 队列 | 入队 | O(1) |
| 两个栈 → 队列 | 出队 | **均摊 O(1)** |
| 两个队列 → 栈 | 入栈 | O(1) |
| 两个队列 → 栈 | 出栈 | **O(n)** |

> ⭐ 为什么不对称？
> 栈→队列：倒一次能连续出队很多次，成本被摊掉。
> 队列→栈：每次出栈都要搬 n-1 个，摊不掉。

## 汇总：本周六个坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 判满写 `top == MAXSIZE` | 越界写 |
| 2 | 判满忘取模 `(rear+1) == front` | 到末尾就误判为满 |
| 3 | 个数忘 `+MAXSIZE` | 负数或算错 |
| 4 | 遍历用 `i < rear` | 绕回后一个都读不到 |
| 5 | 后缀求值先弹 a 后弹 b | 减法除法结果反了 |
| 6 | 链队列出队最后一个不收敛 rear | 野指针 |

## 记忆卡：三个必背

**① 顺序栈**

```text
空：top == -1        满：top == MAXSIZE-1      个数：top+1
入：data[++top] = v   出：v = data[top--]
共享栈满：top1 + 1 == top2（top2 初值 MAXSIZE）
```

**② 循环队列**

```text
空：front == rear
满：(rear + 1) % MAXSIZE == front
个数：(rear - front + MAXSIZE) % MAXSIZE
容量：MAXSIZE - 1
```

**③ 后缀求值**

```text
数字入栈；运算符弹两个（先右后左）；扫完栈里剩的那个就是答案
```
