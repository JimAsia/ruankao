# S3-03 考点手册 数据库系统

> 数据库是 S3 里「性价比最高」的一块：考点集中、题型固定、分值不低。
> 核心就四件事：**三级模式**、**ER 转换**、**关系代数**、**范式判定**。

## 二、必背考点

### 2.1 三级模式与两级映像 ⭐

| 模式 | 别名 | 面向 | 内容 |
|---|---|---|---|
| **外模式** | 子模式、用户模式 | **用户** | 用户能看到的那部分数据（视图） |
| **模式** | 概念模式、逻辑模式 | **全体数据** | 全部数据的逻辑结构 |
| **内模式** | 存储模式 | **物理存储** | 数据在磁盘上怎么存 |

**两级映像保证两种独立性**：

```text
外模式/模式映像  →  逻辑独立性（模式变了，外模式不用改，应用程序不用改）
模式/内模式映像  →  物理独立性（存储结构变了，模式不用改）
```

> ⭐ 这是必考的一对。记法：**外层管逻辑，内层管物理**。

### 2.2 ER 模型与转换规则

**三种联系**：

```text
1:1   一个班主任管一个班
1:n   一个班有多个学生
m:n   一个学生选多门课，一门课被多个学生选
```

**ER 图 → 关系模式的转换**（必考）：

| 联系类型 | 转换方法 |
|---|---|
| **1:1** | 可以合并到任意一端（在那一端加另一端的码），也可以单独成表 |
| **1:n** | **在 n 端加外键**（不需要新表） |
| **m:n** | **必须单独建一张表**，主键 = 两端主键的组合 |

> ⭐ m:n 一定要新建表，这是最常考的一条。忘记建表就没有成绩表了。

### 2.3 关系代数

**五种基本运算**（其余都能由它们导出）：

```text
并 ∪    差 −    笛卡尔积 ×    选择 σ    投影 π
```

**导出运算**：

```text
交 ∩ = R − (R − S)
连接 ⋈（自然连接：按同名属性相等连接，并去掉重复列）
除 ÷（"对所有" 的查询）
```

**运算符对照**：

| 符号 | 名称 | 作用 |
|---|---|---|
| σ | 选择 | 选**行**（WHERE） |
| π | 投影 | 选**列**（SELECT） |
| ⋈ | 自然连接 | 按同名属性连接 |
| × | 笛卡尔积 | 无条件全组合 |
| ÷ | 除 | 「选修了全部课程」这类查询 |
| ∪ − ∩ | 并差交 | 要求**同元、同属性域** |

**实例验证**（`303` 实际算出来的结果）：

```text
S(学号, 姓名, 系名)：S1 张三 计算机 / S2 李四 数学 / S3 王五 计算机
SC(学号, 课程号, 成绩)：S1C1(90) S1C2(85) S1C3(88) S2C1(70) S3C3(95)
C(课程号)：C1 C2 C3

① π姓名(σ系名='计算机'(S))          → 张三、王五
② π姓名(σ课程号='C1'(S ⋈ SC))       → 张三、李四
③ π学号,课程号(SC) ÷ π课程号(C)      → S1（张三）
④ π学号(S) − π学号(SC)              → 空（每个学生都选了课）
```

> ⭐ 第 ③ 题是除法的典型用法：**「选修了全部课程的学生」= 选课关系 ÷ 课程关系**。

### 2.4 SQL 分类

| 类别 | 全称 | 语句 |
|---|---|---|
| **DDL** | 数据定义 | `CREATE`、`ALTER`、`DROP` |
| **DML** | 数据操纵 | `SELECT`、`INSERT`、`UPDATE`、`DELETE` |
| **DCL** | 数据控制 | `GRANT`、`REVOKE` |

**几个常考细节**：

```text
视图对应【外模式】
索引的作用是加快查询，但会减慢插入/删除
DROP 删表结构，DELETE 只删数据
```

### 2.5 函数依赖与范式 ⭐

**四个范式的判定标准**：

| 范式 | 要求 | 一句话 |
|---|---|---|
| **1NF** | 每个属性都不可再分 | 没有"表中有表" |
| **2NF** | 1NF + 非主属性完全依赖候选键 | 消除**部分**依赖 |
| **3NF** | 2NF + 非主属性不传递依赖候选键 | 消除**传递**依赖 |
| **BCNF** | 所有决定因素都是超键 | 消除**主属性**间的依赖 |

**判定口诀**：

```text
看非主属性：
  有没有只依赖候选键一部分的？  → 有，就不是 2NF
  有没有通过别的属性间接依赖的？ → 有，就不是 3NF
看所有决定因素：
  有没有不是超键的？            → 有，就不是 BCNF
```

**四个实例**（`303` 用属性闭包算出来的结论）：

| 例子 | 函数依赖 | 候选键 | 最高范式 | 卡在哪 |
|---|---|---|---|---|
| 学生选课(学号,姓名,系名,系主任,课程号,成绩) | 学号→姓名,学号→系名,系名→系主任,(学号,课程号)→成绩 | (学号,课程号) | **1NF** | 学号→姓名 是部分依赖 |
| 选课成绩(学号,课程号,成绩) | (学号,课程号)→成绩 | (学号,课程号) | **BCNF** | — |
| R3(A,B,C) | A→B, B→C | A | **2NF** | B→C 是传递依赖 |
| R4(A,B,C) | AB→C, C→B | AB、AC | **3NF** | C→B 中 C 不是超键 |

> ⭐ 第 4 个例子最能体现 3NF 与 BCNF 的差别：
> C→B 的 B 是**主属性**，所以 3NF 允许；但 C 不是超键，所以 BCNF 不允许。

### 2.6 事务与并发

**ACID 四个特性**：

| 特性 | 含义 |
|---|---|
| **原子性** Atomicity | 要么全做，要么全不做 |
| **一致性** Consistency | 从一个一致状态到另一个一致状态 |
| **隔离性** Isolation | 并发事务互不干扰 |
| **持久性** Durability | 提交后永久生效 |

**三类并发问题**：

| 问题 | 场景 |
|---|---|
| **丢失修改** | 两个事务同时改同一数据，后写的覆盖先写的 |
| **不可重复读** | 同一事务内两次读同一数据，结果不同（别人改了） |
| **读"脏"数据** | 读到了别人**未提交**的数据 |

**封锁与三级协议**：

```text
X 锁（排他锁）：加了就不能被别人读也不能被别人写
S 锁（共享锁）：加了别人还能加 S 锁读，但不能加 X 锁写

一级封锁协议：修改前加 X 锁，到事务结束才释放 → 防丢失修改
二级封锁协议：一级 + 读前加 S 锁，读完就放 → 再防读脏数据
三级封锁协议：一级 + 读前加 S 锁，到事务结束才放 → 再防不可重复读
```

> ⭐ 记法：一级防丢，二级防脏，三级防重读。**层层叠加，不是各管一个**。

## 三、计算题模板

### 模板 1：求候选键（属性闭包法）

```text
① 把只出现在 FD 左边的属性记为 L，只出现在右边的记为 R
② L 中的属性一定属于候选键（它不能被别的属性推出）
③ 从 L 出发求闭包，若闭包 = 全体属性，则 L 就是候选键
④ 若不够，依次加入其他属性再试，直到闭包 = 全体
```

**例**：R(学号,姓名,系名,系主任,课程号,成绩)
FD：学号→姓名，学号→系名，系名→系主任，(学号,课程号)→成绩

```text
只在左边出现：学号、课程号   ← 这两个一定在候选键里
(学号,课程号)+ = {学号,课程号,姓名,系名,系主任,成绩} = 全体 ✓
所以候选键 = (学号, 课程号)
```

### 模板 2：范式判定

```text
① 求候选键 → 定出主属性（所有候选键的并）
② 标出非主属性
③ 逐条 FD 检查：
   · 非主属性只依赖候选键的一部分 → 不是 2NF
   · 非主属性通过别的属性间接依赖 → 不是 3NF
   · 决定因素不是超键 → 不是 BCNF
```

### 模板 3：ER 图转关系模式

```text
① 每个实体 → 一张表
② 1:n 联系 → 在 n 端表里加外键
③ m:n 联系 → 新建一张表，主键 = 两端主键的组合
④ 1:1 联系 → 合并到任一端，或单独建表
```

## 四、自测 15 题

**1.** 数据库三级模式中，视图对应哪一级？

**2.** 逻辑独立性由哪个映像保证？

**3.** 一个学生可以选多门课，一门课可以被多个学生选，这种联系在转关系模式时要怎么处理？

**4.** 1:n 联系转关系模式时，外键加在哪一端？

**5.** 关系代数的五种基本运算是哪五个？

**6.** 查询「选修了全部课程的学生」用哪种关系运算？

**7.** `GRANT` 和 `REVOKE` 属于 SQL 的哪一类？

**8.** 1NF 的要求是什么？

**9.** R(A,B,C)，FD 为 A→B、B→C，候选键是谁？最高满足第几范式？

**10.** R(A,B,C)，FD 为 AB→C、C→B，候选键是谁？最高满足第几范式？

**11.** 事务的 ACID 分别指什么？

**12.** 「读脏数据」是什么？哪种封锁协议能防止？

**13.** 一级封锁协议能防止哪种并发问题？

**14.** 索引的优缺点？

**15.** `DELETE` 和 `DROP` 的区别？

---

### 答案与解析

**1.** **外模式**（也叫子模式、用户模式）。

**2.** **外模式/模式映像**。模式改变时只改映像，应用程序不用改。

**3.** 这是 **m:n** 联系，**必须单独建一张表**（如选课表），
主键 = 学号 + 课程号 的组合。

**4.** 加在 **n 端**（如"学生"属于"班级"，外键"班级号"加在学生表里）。

**5.** **并、差、笛卡尔积、选择、投影**。交、连接、除都可以由它们导出。

**6.** **除法（÷）**。选课关系 ÷ 课程关系 = 选了全部课程的学生。

**7.** **DCL**（数据控制语言）。

**8.** 每个属性都是**不可再分的原子值**，不能有"表中有表"。

**9.** 候选键 = **A**；最高满足 **2NF**。
A→B 是直接依赖（A 是键），B→C 使 C 传递依赖于 A，所以不满足 3NF。

**10.** 候选键 = **AB 和 AC**；最高满足 **3NF**。
C→B 中 B 是主属性（属于候选键 AB），3NF 允许；但 C 不是超键，所以不满足 BCNF。

**11.** 原子性、一致性、隔离性、持久性。

**12.** 一个事务读到了另一个事务**尚未提交**的修改。
**二级封锁协议**（读前加 S 锁，读完释放）能防止。

**13.** **丢失修改**。

**14.** 优点：**加快查询**（尤其是等值查询和范围查询）。
缺点：**减慢插入/删除/更新**（要维护索引），并且占额外空间。

**15.** `DELETE` 只删**数据**，表结构还在；`DROP` 连**表结构**一起删掉。

## 五、易错清单

1. 视图 = **外模式**，不是模式。
2. 逻辑独立性靠**外模式/模式**映像，物理独立性靠**模式/内模式**映像。
3. **m:n 必须新建表**，主键是两端主键的组合。
4. **1:n 不新建表**，在 n 端加外键。
5. 关系代数基本运算只有**五个**，交和连接不是基本的。
6. 除法对应"**全部**"这类查询。
7. 2NF 消除**部分**依赖，3NF 消除**传递**依赖，别记反。
8. 3NF 允许主属性之间有依赖，BCNF 不允许 —— 这是两者的唯一差别。
9. 一级防丢失修改、二级防读脏、三级防不可重复读，**是叠加关系**。
10. `GRANT`/`REVOKE` 属于 DCL，不是 DML。
