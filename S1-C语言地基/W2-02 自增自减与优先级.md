## 一、`++` 和 `--` 到底在干什么

`i++` 不是「i 加 1」这一件事，它是**两件事**：

1. 算出表达式的值
2. 修改 i 本身

这两件事的**顺序**不同，就有了前置和后置的区别。

| 写法 | 名字 | 表达式取的值 | 之后 i | 记忆法 |
|---|---|---|---|---|
| `++i` | 前置 | **加完之后**的值 | i+1 | 先加再取 |
| `i++` | 后置 | **加之前**的值 | i+1 | 先取再加 |
| `--i` | 前置 | 减完之后的值 | i-1 | 先减再取 |
| `i--` | 后置 | 减之前的值 | i-1 | 先取再减 |

**真实运行 `13_incdec.c` 的结果：**

```text
初始 i = 5
++i 这个表达式的值 = 6
执行后 i         = 6

初始 i = 5
i++ 这个表达式的值 = 5      ← 取的是旧值
执行后 i         = 6        ← 但 i 确实加了
```

### 1.1 单独成句时，两者完全等价

```c
i++;        /* i 变成 i+1 */
++i;        /* i 也变成 i+1 */
```

因为你没有用表达式的值，先后顺序就无所谓了。**所以当 `i++;` 单独占一行时，纠结前置后置没有意义。**

### 1.2 混进表达式，区别立刻显现

```c
i = 5;
a = i++ + 10;      /* a = 15, i = 6 */
```

拆解：先拿 i 的**旧值 5** 参与加法得 15，然后把 i 变 6。a 拿到的是 15。

```c
i = 5;
b = ++i + 10;      /* b = 16, i = 6 */
```

拆解：先把 i 变 6，再拿 **6** 参与加法得 16。b 拿到的是 16。

> 💡 这两行的差别就是软考读程序题里最爱考的那种。别背结论，**按"谁先谁后"推一遍**。

## 二、副作用与未定义行为

### 2.1 什么是副作用

**副作用** = 表达式除了算出值之外，还改变了外部状态。

| 表达式 | 有副作用吗 | 副作用是什么 |
|---|---|---|
| `a + b` | 没有 | 只算值 |
| `i++` | **有** | 改了 i |
| `x = 5` | **有** | 改了 x |
| `printf(...)` | **有** | 输出了东西 |

### 2.2 红线：同一表达式里多次修改同一变量

```c
i + i++          /* ❌ 未定义行为 */
i++ + ++i        /* ❌ 未定义行为 */
a[i] = i++       /* ❌ 未定义行为 */
```

为什么？C 标准只保证「副作用在下一次序列点之前完成」，但没说这一句里 `i` 的读取和 `i++` 的写入谁先发生。既然没规定，编译器怎么干都合法。

**结果**：同一段代码，gcc 和 clang 可能给出不同答案，换个编译选项又是另一个答案。

> ✅ 好消息：**软考不会考这种题**，因为标准根本没规定答案，出题人没法给唯一解。
> 考试只考「`i++` 和 `++i` 各自的值」这种**有确定答案**的。
> 你需要记住的是「这类写法不能写」，而不是「这类写法等于几」。

## 三、运算符优先级全表

从高到低，同级的看结合性：

| 级别 | 运算符 | 结合性 | 说明 |
|---|---|---|---|
| 1 | `()` `[]` `->` `.` 后缀`++` `--` | 左 | 最高，括号永远第一 |
| 2 | `!` `~` 一元`+` `-` `*`(解引用) `&`(取址) `sizeof` `(类型)` 前缀`++` `--` | **右** | 一元运算符 |
| 3 | `*` `/` `%` | 左 | 乘除取余 |
| 4 | `+` `-` | 左 | 加减 |
| 5 | `<<` `>>` | 左 | 移位 |
| 6 | `<` `<=` `>` `>=` | 左 | 大小比较 |
| 7 | `==` `!=` | 左 | 相等比较 |
| 8 | `&` | 左 | 按位与 |
| 9 | `^` | 左 | 按位异或 |
| 10 | `\|` | 左 | 按位或 |
| 11 | `&&` | 左 | 逻辑与 |
| 12 | `\|\|` | 左 | 逻辑或 |
| 13 | `?:` | **右** | 条件运算符 |
| 14 | `=` `+=` `-=` `*=` `/=` `%=` `&=` `^=` `\|=` `<<=` `>>=` | **右** | 赋值，倒数第二 |
| 15 | `,` | 左 | 逗号，最低 |

> 📝 这张表不用背。**记住三条铁律就够了**，其余考试时现推或加括号。

### 3.1 三条铁律

**铁律一：括号最高。**
**铁律二：算术 > 关系 > 逻辑 > 赋值。**
**铁律三：赋值最低（除逗号），且从右往左。**

```text
1 + 2 * 3       = 7          乘法先于加法
3 > 2 + 1       = 0          先算 2+1=3，再比 3>3
1 + 1 == 2      = 1          先加，再判断相等
1 || 0 && 0     = 1          && 高于 ||，等价于 1 || (0&&0)
a = b = c = 5   从右往左：c=5 → b=c → a=b
```

### 3.2 结合性的作用：同级谁先算

```text
10 - 3 - 2      = 5          左结合，(10-3)-2，不是 10-(3-2)=9
100 / 10 / 2    = 5          左结合
2 * 3 % 4       = 2          乘和取余同级，从左到右
```

## 四、最容易踩的三个优先级坑

### 坑 1：位运算的优先级低于比较运算

这是**所有人**都会踩的坑。`&` `|` `^` 的优先级竟然比 `==` 和 `<` 还低。

```c
int x = 2, y = 5;

x & y == 0        /* 被理解成 x & (y == 0) */
                  /* 实际是 2 & 0 = 0 */

(x & y) == 0      /* 这才是你想表达的 */
                  /* 2 & 5 = 0，0 == 0 → 1 */
```

同一个意思，加不加括号结果完全不同。

> 💡 记忆：**位运算比比较运算「松」**。写位运算和比较混在一起时，一律加括号。
> 好消息：gcc 的 `-Wparentheses` 会警告你 —— `suggest parentheses around comparison in operand of '&'`。这就是为什么我说「警告一定要看」。

### 坑 2：`&&` 和 `||` 混用

```c
a || b && c       /* 等价于 a || (b && c)，因为 && 高于 || */
```

逻辑上也许你想表达 `(a || b) && c`，那就得加括号。

### 坑 3：`=` 与 `==`

```c
if (n == 3)       /* 判断 n 是不是 3 */
if (n = 3)        /* 把 3 赋给 n，表达式的值是 3，永远为真 */
```

**编译器不报错**（`-Wall` 下可能给警告），逻辑全错，而且极难发现。

防御写法：`if (3 == n)`，少写一个等号会直接编译失败，问题立刻暴露。

## 五、实战建议：一律加括号

考试时按优先级表算，**平时写代码一律加括号**：

```c
(a & b) == 0                   比  a & b == 0         清楚一万倍
((x > 0) && (y > 0))           虽然啰嗦但绝不出错
((a + b) * c) / 2              一眼看清顺序
```

括号不要钱，bug 很贵。

## 六、软考怎么考这部分

| 考点 | 位置 | 典型问法 |
|---|---|---|
| `i++` 与 `++i` 的值 | 应用技术 | 给一段代码问最后 i、a、b 各是多少 |
| 表达式的值 vs 变量的值 | 应用技术 | 「`i++` 表达式的值是多少，此后 i 是多少」 |
| 运算符优先级 | 基础知识 | 「`a = b = 3` 的执行顺序」 |
| 结合性 | 基础知识 | 「`10-3-2` 等于 5 还是 9」 |
| 位运算优先级 | 基础知识 | 「`x & y == 0` 怎么理解」 |
| 未定义行为 | 基础知识 | 「`i = i++` 的结果是否确定」（答：不确定） |

**读程序题的做法**：把每个变量当前值列成表，逐句更新。不要心算跳步，跳步必错。
