# W13-02 宏与预处理

> 一句话记住：**宏不是函数，是预处理阶段的文本替换。编译器根本没见到宏。**
> 这句话解释了宏的所有优点（无开销）和所有缺点（无类型检查、参数重复求值）。

---

## 一、预处理阶段做了什么

编译分四个阶段，预处理是第一个：

| 阶段 | 做什么 |
|---|---|
| **预处理** | 去注释、展开 `#include`、替换宏、处理条件编译 |
| 编译 | 语法检查、生成汇编 |
| 汇编 | 生成目标文件 `.o` |
| 链接 | 合并库，生成可执行文件 |

想看预处理后的代码：

```bash
gcc -E 122_macro.c -o 122.i
```

打开 `122.i` 会发现**宏全都不见了**，已经被替换成实际文本，注释也没了。

## 二、常量宏

```c
#define PI       3.14159
#define MAXN     100
#define NAME     "软考程序员"
```

实测输出：`PI = 3.14159, MAXN = 100, NAME = 软考程序员`

> ❌ **不要加分号。**
> ```c
> #define MAXN 100;
> int a = MAXN * 2;    /* 展开成 100; * 2 —— 编译错误 */
> ```

> ✅ 现代 C 更推荐：
> ```c
> const double PI = 3.14159;    /* 有类型，能调试 */
> enum { MAXN = 100 };          /* 整型常量，能进符号表 */
> ```

## 三、带参宏：括号决定生死

这是宏最重要的一节。

```c
#define SQ_BAD(x)  x * x            /* ❌ */
#define SQ_OK(x)   ((x) * (x))      /* ✅ */
```

实测（`a = 3`）：

```text
SQ_BAD(a + 1) = 7    ← 展开成 a + 1 * a + 1 = 3 + 3 + 1
SQ_OK (a + 1) = 16   ← 展开成 ((a + 1) * (a + 1))
```

期望都是 16，但 `SQ_BAD` 给出 **7**。

### 只给参数加括号还不够

```c
#define ADD_BAD(x, y)   (x) + (y)      /* ❌ 只有参数括号 */
#define ADD_OK(x, y)    ((x) + (y))    /* ✅ 整体也裹住 */
```

实测：

```text
2 * ADD_BAD(1, 2) = 4   ← 展开成 2 * (1) + (2)
2 * ADD_OK (1, 2) = 6   ← 展开成 2 * ((1) + (2))
```

> ✅ **两条规矩，缺一不可：**
> 1. **每个参数**都用括号裹住
> 2. **整个表达式**再裹一层
>
> 第 2 条经常被忽略，因为大部分时候看不出来 —— 只有宏出现在更大的表达式里才暴露。

## 四、多语句宏必须用 do-while(0) 包裹

```c
#define SWAP(a, b) do {          \
    int _t = (a);                \
    (a) = (b);                   \
    (b) = _t;                    \
} while (0)
```

调用：

```c
if (m < n) SWAP(m, n);           /* 带分号，正常工作 */
```

实测：`m = 1, n = 2` → `m = 2, n = 1`。

### 为什么不能只用 `{}`

```c
#define SWAP_BAD(a, b) { int t = (a); (a) = (b); (b) = t; }

if (m < n) SWAP_BAD(m, n);       /* 展开后变成 if (...) { ... }; */
else printf("x");                /* ← else 找不到 if，编译错误 */
```

展开后是 `if (...) { ... } ;` —— 那个分号是一条**空语句**，`if` 语句到此结束，后面的 `else` 就孤立了。

`do { ... } while (0)` 让整体成为**一条完整语句**，调用处的分号正好结束它。这是 C 标准库和 Linux 内核里的标准写法。

## 五、`#` 转字符串、`##` 拼接

```c
#define STR(x)     #x
#define CAT(a, b)  a##b
```

实测：

```text
STR(hello)  = hello
STR(1 + 2)  = 1 + 2     ← 原样变字符串，不计算
STR(MAXN)   = MAXN      ← 不会展开成 100！这就是 # 的规矩
CAT(my, var) 拼出变量名 myvar = 42
```

> ⭐ `#` 的实际用途：调试时打印表达式本身
> ```c
> #define SHOW(x) printf(#x " = %d\n", x)
> SHOW(a + 1)    /* 输出：a + 1 = 4 */
> ```

> 📝 `#` 的参数**不会被宏展开**。想要「先展开再转字符串」，要绕一层：
> ```c
> #define STR_HELPER(x) #x
> #define STR(x) STR_HELPER(x)
> STR(MAXN)    /* 这样才得到 "100" */
> ```

## 六、参数被求值多次：宏的固有风险

```c
#define TWICE(x)  ((x) + (x))
```

实测（用一个计数器函数统计调用次数）：

```text
函数版：参数求值 1 次，结果 2
宏版  ：参数求值 2 次，结果 2
```

>` TWICE(bump())` 展开成 `bump() + bump()`，`bump` 被调用**两次**。

> ❌ 所以 `#define MAX(a,b) ((a)>(b)?(a):(b))` 是有风险的：
> `MAX(i++, j)` 会让 `i` 自增两次，标准里属于**未定义行为**。
>
> ✅ 需要这种功能，用 `static inline` 函数：
> ```c
> static inline int max(int a, int b) { return a > b ? a : b; }
> ```
> 没有调用开销，而且参数只求值一次。

## 七、条件编译

### ① 头文件保护（每个 `.h` 必写）

```c
#ifndef STUDENT_H
#define STUDENT_H

/* 声明放这里 */

#endif /* STUDENT_H */
```

防止同一个头文件被包含两次导致「重复定义」。

> 📝 `#pragma once` 也能做到，但不是标准的一部分。**软考题考的是 `#ifndef` 那三行。**

### ② 调试开关

```c
#ifdef DEBUG
    #define DBG(fmt, ...)  printf("[DEBUG] " fmt "\n", ##__VA_ARGS__)
#else
    #define DBG(fmt, ...)  ((void)0)
#endif
```

编译时加 `-DDEBUG` 打开：

```bash
gcc -std=c17 -DDEBUG -o prog prog.c
```

实测两种编译方式的差别：

```text
# 不带 -DDEBUG
DEBUG 未定义，DBG 展开成 ((void)0)，一行都不会输出

# 带 -DDEBUG
DEBUG 已定义，调试输出会生效
[DEBUG] x 的值 = 42
```

> ⭐ **`#ifdef` 和 `if` 的本质区别**：

| | `#ifdef` | `if` |
|---|---|---|
| 处理时机 | 预处理（编译前） | 运行时 |
| 不成立的代码 | **根本不进编译** | 编译了，只是不执行 |
| 类型检查 | 不做 | 做 |
| 运行开销 | 没有 | 一次判断 |

> ⭐ **所以平台相关代码必须用 `#if`：**
> Windows API 在 Linux 上不存在，写成 `if (isWindows) { 调WindowsAPI(); }` 会**编译失败**。

### ③ 预定义宏

实测输出：

```text
__FILE__  = 123_preprocess.c
__LINE__  = 59（这行的行号）
__DATE__  = Oct 24 2026
__TIME__  = 21:52:14
__func__  = main
__STDC__  = 1
__STDC_VERSION__ = 201710L（201710 = C17）
```

最有用的是 `__FILE__` 和 `__LINE__`：

```c
#define LOG(msg) printf("[%s:%d] %s\n", __FILE__, __LINE__, msg)
```

每条日志自动带文件名和行号，排查问题极其方便。

> 📝 `__DATE__` 和 `__TIME__` 是**编译时刻**，不是运行时刻。软考考过这个细节。

### ④ 编译期断言

```c
#define STATIC_ASSERT(cond, msg) typedef char static_assert_##msg[(cond) ? 1 : -1]
STATIC_ASSERT(sizeof(int) == 4, int_must_be_4_bytes);
```

如果条件不成立，`(0) ? 1 : -1` 得到 `-1`，数组长度为负，**编译直接失败**。

C11 起有标准写法 `_Static_assert`，但很多老代码还是用这个技巧。

## 八、宏 vs 函数

| 对比项 | 宏 | 函数 |
|---|---|---|
| 处理阶段 | 预处理（编译前替换） | 编译后调用 |
| 类型检查 | **没有** | 有 |
| 参数求值 | **可能多次** | 只一次 |
| 运行开销 | **无** | 有栈帧开销 |
| 调试 | 看不到符号 | 能打断点 |
| 代码体积 | 每次展开各一份 | 只一份 |

> ⭐ **现代 C 的取舍：**
> - 小工具（`MAX`、`SQ`）→ `static inline` 函数，安全且无开销
> - 需要文本能力（`#`、`##`）→ 只能用宏
> - 常量 → `const` 变量或 `enum`

## 九、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 宏的本质 | 宏在哪个阶段处理 | 预处理，不是编译 |
| 带参宏 | 给个宏和参数，问输出 | 手动展开，注意括号 |
| 宏无类型 | `#define SQ(x) x*x` 的问题 | 无类型检查、可能重复求值 |
| 条件编译 | `#ifdef` 和 `if` 的区别 | 前者不进编译 |
| 头文件保护 | 那三行怎么写 | `#ifndef / #define / #endif` |
| 预定义宏 | `__LINE__` 是什么 | 当前行号 |
| `__DATE__` | 编译时间还是运行时间 | **编译时间** |

> 📌 带参宏展开是软考的高频题。做法：**把参数原样文本替换进去，再按运算符优先级算**，不要凭直觉。
