## 一、变量的本质：一块有名字的内存

```text
内存条
┌────┬────┬────┬────┬────┬────┐
│ .. │ 00 │ 00 │ 00 │ 12 │ .. │   ← 物理上全是字节
└────┴────┴────┴────┴────┴────┘
              ▲
              └── 给它起个名字叫 age，规定按 int（4 字节）去解读
```

变量 = **名字 + 类型 + 值**。类型不改，名字可以随便取（但要用有意义的），值可以改。

> 💡 理解这一层，后面的指针、数组、函数传参全都能顺下来。指针不过是「直接拿着地址去找那块内存」。

## 二、三个动作必须分清

```c
int age;          /* ① 声明：申请一块 4 字节，起名 age。里面是垃圾值 */
age = 18;         /* ② 赋值：把 18 写进去 */
int score = 90;   /* ③ 初始化：声明的同时给值（推荐，最不容易出错） */
```

| 动作 | 写法 | 结果 |
|---|---|---|
| 声明 | `int age;` | 内存到手，内容是**不确定的** |
| 赋值 | `age = 18;` | 覆盖原有内容 |
| 初始化 | `int age = 18;` | 一步到位，值是确定的 |

**真实运行 `03_variable.c` 的结果：**

```text
age   = 18
score = 90
a = 1, b = 2, c = 0
score 加了 5 之后 = 95
score 再加 5 之后 = 100
```

### 「必须初始化」吗？—— 合法 ≠ 安全

这是最容易含糊过去的一个点，必须分清两层：

| 层面 | 结论 |
|---|---|
| **语法层面** | `int c;` **完全合法**，C 语言没有"必须初始化"这条强制要求，编译一定通过 |
| **使用层面** | 一旦**读取**未初始化的局部变量，就是未定义行为，拿到的是垃圾值 |

所以准确的表述不是"必须初始化"，而是 —— **必须初始化，才能安全地读**。

```c
int c;              /* 合法。此时不能读 */
c = 5;              /* 赋值之后就能读了 */
printf("%d", c);    /* 正确，输出 5 */

int d;              /* 合法。但下面这行就出事了 */
printf("%d", d);    /* ❌ 读到垃圾值，未定义行为 */
```

**未初始化变量的三种命运：**

| 变量种类 | 不初始化时的值 | 依据 |
|---|---|---|
| 普通**局部**变量 | **不确定**（垃圾值） | C 标准不作保证 |
| **全局**变量 | 0 | C 标准明确规定 |
| **static** 局部变量 | 0 | C 标准明确规定 |

`07_uninitialized.c` 的真实运行结果：

```text
g_count = 0   全局变量，标准保证为 0
s_count = 0   static 局部，标准保证为 0
local   = 173   普通局部，值不确定
```

那个 `173` 是栈上残留的旧数据，换机器、换编译优化级别都可能不同。编译器会提醒你：

```text
warning: 'local' is used uninitialized [-Wuninitialized]
```

> ⚠️ **警告不是错误。** 程序照样编译成功、照样跑出结果 —— 这正是它危险的地方：错误会让你停下来改，警告常常被忽略，然后你带着一个每次结果都不一样的 bug 继续往下写。

> ✅ 实践铁律：**局部变量声明时就给初值。** 成本几乎为零，能避开一大半莫名其妙的 bug。
> ❌ 别以为「没赋值就是 0」。只有全局变量和 static 变量才默认是 0，普通局部变量不是。

> 📌 软考视角：如果选择题问「未初始化的局部变量其值是什么」，标准答案是**不确定 / 随机值**，而不是 0。如果问「能不能编译通过」，答案是**能**。这两个问法经常一起出现，别混。

## 三、基本数据类型总表

下面这张表是 `04_types.c` 在你这台机器上的**真实输出**，不是抄来的：

| 类型             | 字节数 | 取值范围                                       |
| -------------- | --- | ------------------------------------------ |
| `char`         | 1   | -128 ~ 127                                 |
| `short`        | 2   | -32768 ~ 32767                             |
| `int`          | 4   | -2147483648 ~ 2147483647                   |
| `unsigned int` | 4   | 0 ~ 4294967295                             |
| `long long`    | 8   | -9223372036854775808 ~ 9223372036854775807 |
| `float`        | 4   | ±1.175×10⁻³⁸ ~ ±3.403×10³⁸                 |
| `double`       | 8   | ±2.225×10⁻³⁰⁸ ~ ±1.798×10³⁰⁸               |

**软考怎么记：**

| 要记的 | 结论 |
|---|---|
| `char` | 1 字节，`'A'` = 65，`'a'` = 97，`'0'` = 48 |
| `int` | 4 字节，约 ±21 亿 |
| `short` | 2 字节，约 ±3.2 万 |
| `long long` | 8 字节，约 ±9.2×10¹⁸ |
| `float` | 4 字节，**有效数字约 7 位** |
| `double` | 8 字节，**有效数字约 15~16 位** |

> ⚠️ 陷阱：C 标准**只保证** `int` 至少 2 字节。老教材会写「int 占 2 字节」（那是 16 位机的年代）。现代 x86/ARM 上都是 4 字节。**考试时以教材口径为准，做题时以 `sizeof` 为准。**

### float 和 double 的精度是怎么来的

IEEE 754 标准：

| 类型 | 总位数 | 符号位 | 阶码位 | 尾数位 | 有效十进制位 |
|---|---|---|---|---|---|
| `float`（单精度） | 32 | 1 | 8 | 23 | 约 7 位 |
| `double`（双精度） | 64 | 1 | 11 | 52 | 约 15~16 位 |

所以 `float` 存 `3.14159265` 会丢精度，`double` 不会。**做题一律用 double，除非题目明确要求 float。**

## 四、sizeof：让机器自己告诉你

```c
printf("%zu\n", sizeof(int));      /* 4 */
printf("%zu\n", sizeof(char));     /* 1 */
printf("%zu\n", sizeof(double));   /* 8 */
```

> 📝 `sizeof` 是**运算符**，不是函数。所以 `sizeof(int)` 和 `sizeof int` 都合法。
> `sizeof` 的结果类型是 `size_t`，打印时用 `%zu`，不要用 `%d`。

## 五、有符号与无符号

```c
int           a = -1;    /* 有符号：能存负数，最高位当符号位 */
unsigned int  b = 4294967295;  /* 无符号：只存非负，全部位都当数值 */
```

| 类型 | 修饰符 | 能否为负 |
|---|---|---|
| `signed int` | 默认 | 能 |
| `unsigned int` | 加 `unsigned` | 不能，负数会变成很大的正数 |

> ❌ 经典坑：`unsigned int x = -1;` 不报错，x 会变成 `4294967295`。
> 原因是 -1 的补码是全 1，按无符号解读就是最大值。

**补码速记**（详细在计算机基础模块讲）：负数在内存里用补码存，`-1` 的 32 位补码是 32 个 1。

## 六、类型转换

### 隐式转换（自动发生）

```c
int  a = 5, b = 2;
double r = a / b;      /* ❌ 结果是 2.0，不是 2.5！先算整数除法，再转 double */
double s = (double)a / b;   /* ✅ 结果是 2.5 */
```

**转换顺序（小 → 大，安全）：**

```text
char → short → int → unsigned → long → long long → float → double
```

> ✅ 一句话：**赋值给更大的类型安全，赋给小类型可能丢数据。**

### 强制转换（你主动要求）

```c
double pi = 3.9;
int n = (int)pi;       /* n = 3，直接截断小数部分，不四舍五入 */
```

| 写法 | 结果 |
|---|---|
| `(int)3.9` | 3（截断） |
| `(int)-3.9` | -3（向零截断，不是 -4） |
| `(double)5 / 2` | 2.5 |
| `5 / 2` | 2 |

> ❌ 新手最高频的 bug：**整数除法**。`9 / 5` 是 1，不是 1.8。要写 `9.0 / 5`。

## 七、溢出

```c
int max = 2147483647;
max = max + 1;        /* 溢出，变成 -2147483648 */
```

| 情况 | 结果 |
|---|---|
| 有符号整数溢出 | **未定义行为**，通常回绕成负数 |
| 无符号整数溢出 | 明确定义为对 2³² 取模，回绕成 0 附近 |

> ⚠️ 软考算法题里如果数据范围接近 21 亿，就要考虑用 `long long`。这是应用题常见的送分/失分点。
