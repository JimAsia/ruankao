# W12-03 二进制文件与随机访问

> 文本文件是「给人看的」，二进制文件是「给机器看的」。
> 这一节只讲三件事：怎么读写、和文本的差别、`fseek` 怎么定位。

---

## 一、fwrite / fread 的四个参数

```c
size_t fwrite(const void *ptr, size_t size, size_t n, FILE *fp);
size_t fread (void *ptr, size_t size, size_t n, FILE *fp);
```

| 参数 | 含义 | 结构体数组的典型写法 |
|---|---|---|
| `ptr` | 数据地址 | `a`（数组名） |
| `size` | **单个元素**多大 | `sizeof(Student)` |
| `n` | **几个元素** | `3`（不是总字节数！） |
| `fp` | 文件指针 | `fp` |

> ⚠️ 把 size 和 n 对调（`fwrite(a, 3, sizeof(Student), fp)`）会怎样？
> **实测：文件内容一模一样，两个文件用 `cmp` 比对完全相同。**
> 因为写入的总字节数都是 `3 × 32 = 96`，`fwrite` 只是把这块内存整片倒出去。
>
> 但**返回值变了**：正确写法返回 `3`（写了 3 条），对调后返回 `32`（写了 32 块）。
> 如果你写了 `if (fwrite(...) != 3)` 做检查，对调后就会**误判为失败**。
>
> 真正会写坏的情况是**条数不能被整除时**：比如只写 2 条，`fwrite(a, 3, 2, fp)` 只写 6 字节，
> 后面 58 字节全丢。所以参数顺序还是要记准：**第二个是单个元素大小，第三个是元素个数。**

返回值是**成功写入/读到的元素个数**，不是字节数。

```c
if (fwrite(src, sizeof(Student), 3, fp) != 3) {
    printf("写入不完整，可能磁盘满了\n");
}
```

## 二、完整流程（实测）

```c
Student src[3] = {
    {2026001, "张三", 92.5},
    {2026002, "李四", 78.0},
    {2026003, "王五", 96.5}
};

FILE *fp = fopen("students.dat", "wb");
fwrite(src, sizeof(Student), 3, fp);
fclose(fp);
```

真实输出：

```text
sizeof(Student) = 32 字节
3 条记录应占 96 字节
实际写入 3 条
```

读回：

```c
Student dst[3];
fp = fopen("students.dat", "rb");
size_t n = fread(dst, sizeof(Student), 3, fp);
fclose(fp);
```

真实输出：

```text
读到 3 条：
    2026001 张三 92.5
    2026002 李四 78.0
    2026003 王五 96.5
```

> ⭐ `double` 的 `92.5` 一位不差。
> 文本模式下 `printf("%.1f")` 只保留 1 位，`92.55` 会变成 `92.5` 或 `92.6`；二进制存的是**内存里的原始 8 字节**，没有任何精度损失。

## 三、二进制一定更小吗？不一定

实测同一个数据两种格式：

```text
二进制 students.dat: 96 字节
文本   students.txt: 63 字节
```

**二进制反而更大。**

原因：

```c
char name[20];        /* 定长 20 字节，但「张三」只用了 6 字节 */
```

| | 存法 | 3 条记录 |
|---|---|---|
| 二进制 | 每条固定 32 字节 | 96 字节 |
| 文本 | 只存实际字符 | 63 字节 |

> ⭐ **「二进制更省空间」是个常见误解。**
> 只有当数据是定长大块（图片、音频、传感器采样）时，二进制才明显更小。
> 二进制真正的优势是**速度**和**随机访问**，不是体积。

## 四、fseek：O(1) 定位任意记录

文本文件想找第 1000 条，只能从头一行一行数。二进制文件可以**直接算偏移**：

```c
/* 跳到第 2 条记录（下标 1） */
fseek(fp, (long)sizeof(Student), SEEK_SET);

Student one;
fread(&one, sizeof(Student), 1, fp);
```

真实输出：

```text
第 2 条：2026002 李四 78.0
```

偏移量 = `下标 × sizeof(Student)`。这就是「随机访问」。

### 三个定位基准

| 常量 | 含义 |
|---|---|
| `SEEK_SET` | 从**文件开头**算 |
| `SEEK_CUR` | 从**当前位置**算 |
| `SEEK_END` | 从**文件末尾**算（通常配合负偏移） |

### 用 fseek 求文件大小

一个非常实用的技巧（文本文件也能用）：

```c
fseek(fp, 0, SEEK_END);    /* 跳到末尾 */
long size = ftell(fp);     /* 当前位置 = 总字节数 */
fseek(fp, 0, SEEK_SET);    /* 记得跳回去，否则后面读不到东西 */
```

`ftell` 返回当前位置相对于开头的字节偏移。

> ⚠️ **`fseek` 之后一定要 `fseek(fp, 0, SEEK_SET)` 复位**，否则后续读取从末尾开始，什么都读不到。

## 五、二进制文件的三个坑

### ① 不可读

用记事本打开 `.dat` 是乱码。这不算 bug，但**调试时看不见内容，排查困难**。

### ② 不可跨平台

三件事可能导致读错：

| 因素 | 差异 |
|---|---|
| `int` 大小 | 32 位机通常 4 字节，但标准只保证 ≥ 2 |
| 字节序 | x86 小端，部分 ARM/网络 大端 |
| 结构体对齐 | 不同编译器填充规则可能不同 |

> 📝 W11 里我们实测过 `d.i = 0x41424344` 后用 `char` 读出来是 `DCBA` —— 这就是**小端序**。二进制文件跨平台时，这个字节序必须转换，否则全是乱码。

### ③ 结构体一变，旧文件全废

```c
typedef struct { int id; char name[20]; double score; } Student;   /* 32 字节 */
```

给 `Student` 加一个 `char gender;` 字段，`sizeof` 可能变成 40。这时读旧的 32 字节文件，**每条记录都会错位**，第二名学生的数据会从错误位置开始读。

> ⭐ 工程上的对策：二进制格式要带**版本号**，或者在文件头写一个魔数（magic number）。
> 软考只考概念，记住「二进制文件不可移植、结构体变更不兼容」这两条。

## 六、文本 vs 二进制：怎么选

| 场景 | 选择 | 理由 |
|---|---|---|
| 配置文件、日志 | **文本** | 人能读，出问题能直接看 |
| 成绩表、通讯录（小数据） | **文本** | 便于交换、编辑 |
| 大量数值、图像、音频 | 二进制 | 快、无精度损失 |
| 需要随机访问第 N 条 | 二进制 | `fseek` 直接定位 |
| 跨平台传输 | **文本** | 避开字节序和对齐问题 |

> 📌 **软考的文件大题几乎都用文本模式。** 二进制只在选择题里考「模式字符串的含义」和「fread/fwrite 的参数顺序」。

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| `fwrite` 参数 | 第二个和第三个参数是什么 | 单元素大小、元素个数 |
| 返回值 | `fwrite` 返回什么 | 成功写入的**元素个数** |
| `fseek` 基准 | 三个常量含义 | SET 开头 / CUR 当前 / END 末尾 |
| `ftell` | 返回什么 | 当前偏移字节数 |
| 模式字符串 | `"rb"` 和 `"r"` 的区别 | 二进制 / 文本（Windows 上换行转换） |
| 可移植性 | 二进制文件能否换机器用 | 不能，字节序和对齐都可能不同 |
