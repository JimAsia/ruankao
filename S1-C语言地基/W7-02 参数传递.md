> 🎯 这一节解决一个从 W1 就埋下的问题：**为什么 `swap(a,b)` 交换不了？**

## 一、C 语言只有一种传递方式：值传递

**调用时，实参的值被复制一份给形参。此后两者是两块独立的内存，互不影响。**

`62_value_passing.c` 的实测输出：

```text
  调用前：a = 10，地址 00000043A7DFF824
  函数内：收到 x = 10，地址 00000043A7DFF7F0
  函数内：改成 x = 999
  调用后：a = 10（没变！）
  原因：形参 x 是 a 的副本，存在另一个地址上，改它不影响 a
```

**注意两个地址不一样** —— 这就是最直观的证据。

```text
main 的 a 在 0x...824
函数内的 x 在 0x...7F0
两块不同的内存，各自存着自己的 10
```

## 二、⭐ 为什么 swap 交换不了

```c
void swapWrong(int x, int y)
{
    int t = x; x = y; y = t;    /* 函数内部确实换了 */
}
```

实测：

```text
  调用前：a = 1（地址 00000094271FF9EC），b = 2（地址 00000094271FF9E8）
    函数内：收到 x = 1（地址 00000094271FF9B0），y = 2（地址 00000094271FF9B8）
    函数内：交换后 x = 2，y = 1  ← 函数内部确实换了
  调用后：a = 1，b = 2  ← 外面根本没变
```

**函数里交换的是「复印件」，不是「原件」。** 函数一结束，`x`、`y` 就销毁了，`a`、`b` 从头到尾没被碰过。

> 📌 这是软考和面试的经典题，也是理解指针的必要前提。
> **修复方法：不传值，传地址**。这需要指针，W9 会讲。

## 三、那数组为什么能改

```c
void doubleAll(int arr[], int n)
{
    for (int i = 0; i < n; i++) arr[i] *= 2;
}
```

实测：

```text
  调用前：3 7 1 9 4 6
  调用后：6 14 2 18 8 12
  ← 每个元素都翻倍了，因为函数拿到的是首地址
```

**原因**：数组作参数时，传的不是整个数组的拷贝，而是**首地址**。函数拿着这个地址，就能直接改原数组。

但要注意 —— **仍然是值传递**！只是"值"变成了"地址"：

```text
传 int  →  拷贝的是整数本身
传数组  →  拷贝的是首地址（一个数字）
```

> 💡 一句话总结：**C 语言只有值传递。所谓「传地址」，也是把地址这个值复制过去。**

## 四、⚠️ 数组作参数的致命细节

```c
int sumArray(int arr[], int n)
{
    printf("%zu\n", sizeof(arr));    /* 结果是 8，不是 24！ */
}
```

实测：

```text
  main 里：sizeof(a) = 24 字节，n = 6
    函数内：sizeof(arr) = 8 字节（这是指针的大小，不是数组的）
```

**数组参数会「退化」成指针**，`sizeof` 拿到的是指针大小（64 位系统是 8 字节）。

编译器会警告：

```text
warning: 'sizeof' on array function parameter 'arr'
         will return size of 'int *' [-Wsizeof-array-argument]
```

**结论：数组作参数，必须额外传长度。**

```c
int sumArray(int a[], int n)        /* ✅ 标准写法 */
```

这就是为什么 C 标准库的函数都带长度参数（`strncpy(dst, src, n)`、`fread(ptr, size, n, fp)`）。

## 五、二维数组作参数：列数不能省

```c
int sumMatrix(int m[][4], int rows)     /* ✅ 第二维必须写 */
```

```c
int sumMatrix(int m[][], int rows)      /* ❌ 编译错误 */
```

**为什么**：编译器要靠列数算地址偏移，`m[i][j]` 的地址 = 首地址 + `(i × 列数 + j) × 元素大小`。列数不知道，就没法算。

实测：

```text
  sumMatrix(m, 2) = 36
  ⚠️ 参数必须写 int m[][4] —— 第二维（列数）不能省
```

> 📌 这是软考应用技术的常见考点：给一个函数头，问哪里写错了。

## 六、`const` 保护只读参数

```c
int sumReadOnly(const int arr[], int n)
{
    /* arr[i] = 0;   ❌ 编译错误 */
}
```

| 写法 | 含义 |
|---|---|
| `int arr[]` | 函数可以改数组内容 |
| `const int arr[]` | 函数承诺不改，改了编译失败 |

**好习惯**：只读的参数一律加 `const`。别人看函数头就知道它会不会动你的数据。

## 七、参数传递总表

| 参数类型 | 传的是什么 | 函数内能否改调用者的数据 |
|---|---|---|
| `int` / `double` / `char` | 值的副本 | ❌ 不能 |
| 数组 `int a[]` | 首地址 | ✅ 能改内容 |
| 结构体（W11） | 整个结构体副本 | ❌ 不能（除非传指针） |
| 指针（W9） | 地址 | ✅ 能改它指向的东西 |
