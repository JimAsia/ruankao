## 一、求和与平均

```c
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];
}
double avg = (double)sum / n;
```

实测（数据 72 45 91 38 66 88 55 79）：

```text
  总和 = 534
  平均 = 66.75
```

就是 W4 的累加范式，只是数据来源从「现算」变成「从数组取」。

## 二、最值及其下标

```c
int max = a[0];             /* ⚠️ 用第一个元素当擂主 */
int maxIdx = 0;

for (int i = 1; i < n; i++) {       /* 从 1 开始 */
    if (a[i] > max) {
        max = a[i];
        maxIdx = i;
    }
}
```

实测：

```text
  最大值 = 91，在下标 2
  最小值 = 38，在下标 3
```

**三个要点**：

| 要点 | 说明 |
|---|---|
| 初值用 `a[0]` | 比 `max = 0` 安全，全负数也不会错 |
| 循环从 `i = 1` | `a[0]` 已经当擂主了 |
| `>` 还是 `>=` | `>` 得**第一个**最大值的位置，`>=` 得**最后一个** |

> 📌 最后这一点软考读程序题会考：「如果有多个相同最大值，输出的是哪一个下标？」

## 四、顺序查找

```c
int pos = -1;               /* ⚠️ -1 表示"没找到" */
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        pos = i;
        break;              /* 找第一个就够了 */
    }
}
```

实测：

```text
  66 在下标 4
  100 不存在（返回 -1 表示没找到）
```

**为什么要用 -1 而不是 0**：0 是合法下标，用它表示「没找到」会混淆。**-1 是永远不可能是合法下标的数**，这是约定俗成的做法。

### 4.1 查找所有出现位置

```c
for (int i = 0; i < n; i++) {
    if (a[i] == key) {
        printf("%d ", i);
        cnt++;
    }
}
```

⚠️ **这时候不能 `break`**，必须扫完整个数组。实测（数组 5 3 5 7 5 9 1 5，查找 5）：

```text
  查找 5 出现的所有位置：0 2 4 7
  共出现 4 次
```

## 五、逆序：首尾交换

```c
for (int i = 0, j = n - 1; i < j; i++, j--) {
    int t = a[i];
    a[i] = a[j];
    a[j] = t;
}
```

实测：

```text
  逆序前：72 45 91 38 66 88 55 79
  逆序后：79 55 88 66 38 91 45 72
```

**⚠️ 条件是 `i < j`，不是 `i < n`。**

写成 `i < n` 的话，每个元素会被交换两次，等于又换回原样 —— 白干一遍，而且很难发现。

**为什么只需要 n/2 轮**：每轮同时处理首尾两个元素，走一半就全换完了。

### 5.1 另一种写法：另开一个数组

```c
int b[20];
for (int i = 0; i < n; i++) b[i] = a[n - 1 - i];
```

也对，但**多占一倍空间**。「原地逆序」是更优解，也是软考更喜欢的答案。

## 六、⭐ 删除元素：后面往前移

```c
/* 删除下标 k 的元素 */
for (int i = k; i < n - 1; i++) {
    a[i] = a[i + 1];        /* 后面的元素依次前移，覆盖要删的 */
}
n--;
```

实测（数组 15 28 37 42 58 63 71，删除下标 2）：

```text
  删除前：15 28 37 42 58 63 71
  删除后：15 28 42 58 63 71
  ⚠️ 原来最后一个位置还留着旧值，但它已经不算有效数据了
  代价：最坏要移动 n 个元素，所以顺序表删除是 O(n)
```

**关键理解**：删除不是「把那个位置抹掉」，而是**用后面的元素覆盖它，然后长度减 1**。

**为什么不是 O(1)**：数组内存连续，中间空一个洞是不允许的，必须把后面的全部搬过来。

## 七、⭐ 插入元素：从后往前移

```c
/* 在下标 k 处插入 newVal */
for (int i = n; i > k; i--) {       /* ⚠️ 从后往前！ */
    a[i] = a[i - 1];
}
a[k] = newVal;
n++;
```

实测（在下标 3 插入 99）：

```text
  插入前：15 28 42 58 63 71
  插入后：15 28 42 99 58 63 71
  ⚠️ 顺序不能反：从前往后移会把 a[3] 覆盖成 a[4]，数据就丢了
```

**⚠️ 为什么必须从后往前**：

```text
从前往后（错）：
  a[4] = a[3]    ← a[4] 原来的值没了
  a[3] = a[4]    ← 现在 a[3] 变成刚搬过来的值，原 a[3] 丢了

从后往前（对）：
  a[6] = a[5]
  a[5] = a[4]
  a[4] = a[3]
  a[3] = newVal  ← 最后才覆盖要插入的位置
```

> 📌 这个「从后往前」是软考应用技术的高频考点。凡是「插入 / 后移」的题，先检查循环方向。

## 八、⭐ 删除所有等于 x 的元素（覆盖法）

比「找到一个就整体前移」高效得多：

```c
int k = 0;                  /* k 是"新数组"下一个写入位置 */
for (int i = 0; i < n; i++) {
    if (a[i] != x) {
        a[k] = a[i];
        k++;
    }
}
n = k;                      /* k 就是新的元素个数 */
```

实测（数组 3 5 3 7 3 9 1，删除所有 3）：

```text
  删除后：5 7 9 1
  剩余个数 = 4
```

**正确性关键**：`k <= i` 恒成立，所以 `a[k] = a[i]` 不会覆盖掉还没读的数据。

| 方法 | 复杂度 |
|---|---|
| 每找到一个就整体前移 | O(n²) |
| **覆盖法（双指针）** | **O(n)** |

## 九、软考怎么考这部分

| 考点 | 位置 | 典型问法 |
|---|---|---|
| 最值下标 | 应用技术 | 读程序问输出的是哪个下标 |
| 逆序的交换次数 | 应用技术 | 「n 个元素逆序要交换几次」（n/2） |
| 删除的元素移动次数 | 基础知识 | 「删除第 i 个元素要移动几个」 |
| 插入的移动方向 | 应用技术 | 找错题（循环方向反了） |
| 顺序查找的比较次数 | 基础知识 | 平均 (n+1)/2 |
| 双指针覆盖法 | 应用技术 | 补全代码 |
