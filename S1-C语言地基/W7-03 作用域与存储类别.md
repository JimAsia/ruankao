## 一、两种"活着"：作用域 vs 生命周期

| 概念 | 问的是什么 |
|---|---|
| **作用域** | 这个名字在**代码的哪些地方**能用 |
| **生命周期** | 这块内存**什么时候存在、什么时候回收** |

两者经常一致，但 `static` 会让它们分离 —— 这是最容易绕晕的地方。

## 二、三种作用域

### 2.1 局部变量：出了大括号就没了

```c
{
    int inner = 10;
    printf("%d", inner);    /* ✅ 能用 */
}
printf("%d", inner);        /* ❌ 编译错误：inner 已经不存在 */
```

作用域是**离它最近的那对大括号**，包括 `for` 的循环体、`if` 的分支体。

### 2.2 全局变量：整个文件都能用

```c
int gCount = 0;             /* 定义在所有函数外面 */

void f(void) { gCount++; }  /* ✅ 能用 */
int main(void) { gCount++; } /* ✅ 也能用 */
```

实测：

```text
  gDefault = 0（没初始化，但自动是 0）
  调用 incrementGlobal 之前 gCount = 0
  调用两次后 gCount = 2
```

**⚠️ 全局变量的代价**：任何函数都能改它，项目一大就很难追踪「谁把它改成了这个值」。

> 💡 能用参数和返回值解决的，就别用全局变量。

### 2.3 变量遮蔽

```c
int shadow = 100;           /* 全局 */

void showShadow(void) {
    printf("%d\n", shadow); /* 100，全局 */
    int shadow = 50;        /* 局部把全局盖住 */
    printf("%d\n", shadow); /* 50，局部优先 */
}
```

实测：

```text
    全局 shadow = 100
    局部 shadow = 50（同名的局部优先）
    函数返回后，全局 shadow 仍是 100（没被改）
```

> ⚠️ C 语言**没有** `::` 作用域运算符（那是 C++ 的），变量被遮蔽后就没法直接访问全局那个了。只能改名字。

## 三、⭐ static 的两种含义

这是软考的高频考点，也是最容易搞混的地方。

### 3.1 `static` 修饰局部变量：记住值

```c
int nextId(void) {
    static int id = 0;      /* ⚠️ 只初始化一次 */
    id++;
    return id;
}
```

实测：

```text
  连续调用 nextId() 三次：1, 2, 3
  值是 1、2、3 —— 因为 static int id 只初始化一次，之后一直保留

  对比 nextIdBad() 三次：1, 1, 1
  永远是 1、1、1 —— 因为每次调用都重新执行 int id = 0
```

**关键区别**：

| | 普通局部变量 | static 局部变量 |
|---|---|---|
| 作用域 | 函数内 | 函数内（一样） |
| 生命周期 | 函数调用期间 | **整个程序**（不一样！） |
| 初始化 | 每次调用都执行 | **只执行一次** |
| 默认初值 | 不确定 | **0** |

> 💡 用途：计数器、缓存、只初始化一次的资源。

### 3.2 `static` 修饰全局变量/函数：只本文件可见

```c
static int fileOnly = 10;       /* 其他 .c 文件访问不到 */
static void helper(void) { }    /* 同样只本文件能用 */
```

这叫**内部链接**，作用是「隐藏实现细节」，避免不同文件里的同名函数冲突。

> 📌 考试问「static 有什么作用」，答这两条就够了：
> **① 修饰局部变量 → 值只初始化一次，生命周期延长到整个程序**
> **② 修饰全局变量/函数 → 仅本文件可见**

## 四、四种存储类别

| 类别 | 关键字 | 作用域 | 生命周期 | 默认初值 |
|---|---|---|---|---|
| 自动 | 无（默认） | 函数内 | 函数调用期间 | **不确定** |
| 静态 | `static` | 见上面两种 | 整个程序 | 0 |
| 全局 | 无（函数外） | 本文件全部 | 整个程序 | 0 |
| 外部 | `extern` | 跨文件 | 整个程序 | — |

实测输出：

```text
  类别         作用域      生命周期     默认初值
  局部变量     函数内      函数调用期间 不确定
  static 局部  函数内      整个程序     0
  全局变量     本文件全部  整个程序     0
  extern 全局  跨文件      整个程序     —
```

> 📌 **只记住两条**：
> ① 局部变量不初始化是垃圾值，全局和 `static` 是 0
> ② `static` 修饰局部 = 记住值；修饰全局/函数 = 只本文件可见

## 五、⚠️ 顺带一个求值顺序的坑

写 `64_scope_static.c` 时遇到的情况：

```c
printf("%d, %d, %d\n", nextId(), nextId(), nextId());   /* ❌ 危险 */
```

**同一个 printf 里多次调用有副作用的函数，谁先执行 C 标准没规定。**

三个 `nextId()` 都改同一个 `static id`，如果编译器从右往左求值，输出顺序就反了。

**正确做法**：拆成独立语句。

```c
int a1 = nextId();
int a2 = nextId();
int a3 = nextId();
printf("%d, %d, %d\n", a1, a2, a3);     /* ✅ 顺序确定 */
```

> 💡 这和 W2 讲的「同一表达式里多次修改同一变量是 UB」是同一类问题。
