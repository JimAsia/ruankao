## 一、递归 = 函数调用自己

```c
void countdown(int n)
{
    if (n == 0) { printf("发射！\n"); return; }   /* 出口 */
    printf("%d ", n);
    countdown(n - 1);                              /* 递推 */
}
```

实测：`5 4 3 2 1 发射！`

---

## 二、⭐ 三要素（缺一不可）

| 要素 | 作用 | 缺了会怎样 |
|---|---|---|
| **出口**（base case） | 什么时候停 | 无限递归 → 栈溢出 |
| **递推关系** | 大问题怎么化成小问题 | 算不出结果 |
| **规模缩小** | 每次调用更靠近出口 | 无限递归 |

**检查方法**：盯着递归调用那一行，问自己「它是不是比当前更接近出口？」

```c
countdown(n - 1)        /* ✅ n 每次减 1，最终会到 0 */
countdown(n)            /* ❌ 参数没变，永远到不了出口 */
countdown(n + 1)        /* ❌ 越走越远 */
```

## 三、调用栈：理解递归的关键

```c
void trace(int n)
{
    printf("[进栈] n = %d\n", n);
    if (n == 0) return;
    trace(n - 1);
    printf("[出栈] n = %d\n", n);     /* 递归返回后才执行 */
}
```

`trace(3)` 的实测输出：

```text
  [进栈] n = 3
  [进栈] n = 2
  [进栈] n = 1
  [进栈] n = 0
  [出口] n = 0，开始返回
  [出栈] n = 1
  [出栈] n = 2
  [出栈] n = 3
```

**两个阶段**：

```text
递推阶段（往下走）：3 → 2 → 1 → 0    每一层都停在递归调用那一行
回归阶段（往回收）：1 → 2 → 3        每层继续执行剩下的代码
```

> 💡 这就是「先进后出」—— 和 W4 的栈结构一样。最后一层先返回，第一层最后返回。

**这个顺序决定了输出顺序**：

```c
printf("A");        /* 递归之前 → 正序（从外往里） */
f(n-1);
printf("B");        /* 递归之后 → 倒序（从里往外） */
```

## 四、最简单的四个递归

| 函数 | 出口 | 递推 |
|---|---|---|
| `sumTo(n)` | `n == 1` | `n + sumTo(n-1)` |
| `power(x,n)` | `n == 0` | `x * power(x, n-1)` |
| `printDigits(n)` | `n < 10` | 先 `printDigits(n/10)` 再输出 `n%10` |
| `countdown(n)` | `n == 0` | `countdown(n-1)` |

实测：

```text
  sumTo(10) = 55
  power(2, 10) = 1024
  3725 → 3 7 2 5
```

**`printDigits` 值得细看**：

```text
先递归（处理高位）→ 再输出这一位
所以 3725 输出 3 7 2 5（正序）

如果反过来：先输出 → 再递归
会输出 5 2 7 3（倒序）
```

> 📌 软考读程序题常考「这段递归输出什么顺序」。判断方法：看 `printf` 在递归调用**之前**还是**之后**。

## 五、递归的思维方法

新手最容易犯的错：**试图在脑子里模拟每一步递归**。

```text
❌ 错误思路：hanoi(4) → hanoi(3) → hanoi(2) → ... 一个个跟踪
✅ 正确思路：相信 hanoi(n-1) 能正确完成任务，只关心怎么拆
```

这叫「递归的信仰之跃」（leap of faith）：

1. 先假设小规模的问题已经解决了
2. 只考虑「怎么用已解决的小问题拼出大问题」
3. 最后检查出口

| 考点 | 位置 | 典型问法 |
|---|---|---|
| 输出顺序 | 应用技术 | 「这段递归输出什么」 |
