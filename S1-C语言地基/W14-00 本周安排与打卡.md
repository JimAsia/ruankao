## 四、自测五题

**1. 为什么用 `Student g_stu[100]` + `int g_count`，而不是只用数组？**

**2. 添加学生时，新元素放在哪个下标？为什么？**

**3. 删除下标 1 的元素，循环边界为什么是 `i < g_count - 1` 而不是 `i < g_count`？**

**4. 统计最值时，为什么存下标而不是存数值？**

**5. 菜单程序里，`scanf` 失败后为什么必须清输入缓冲区？**

---

## 五、答案与解析

**1. 因为「数组容量」和「实际人数」是两件事。**

- `g_stu[100]` 的容量永远是 100
- `g_count` 是实际存了几个

遍历必须用 `i < g_count`。用 `i < 100` 会把后面 97 个**未初始化的垃圾数据**也处理掉（成绩是随机值，统计结果全错）。

**2. 放在 `g_stu[g_count]`，然后 `g_count++`。**

因为 `g_count` 同时是「当前人数」和「下一个空位的下标」。前 0..g_count-1 已占用，第一个空位就是 `g_count`。

> ⚠️ 顺序不能反：先赋值再 `g_count++`。反过来会覆盖上一个元素。

**3. 因为最后一次循环会访问 `g_stu[g_count]`。**

写 `i < g_count` 时，`i` 最大取到 `g_count - 1`，执行 `g_stu[g_count-1] = g_stu[g_count]` —— 把数组里**没意义的旧数据**搬进有效区。

而且这个错**不崩溃、不警告**，只是最后一条数据变得莫名其妙，极难排查。

**4. 因为输出时要打印姓名。**

只存数值只能得到 `92.0`；存下标 `idx` 就能拿到 `g_stu[idx].name`、`g_stu[idx].id` 全部信息。

这个设计在 W11 求最高分时已经用过 —— **凡是"要输出整条记录"的场景，都存下标**。

**5. 因为失败的输入会留在缓冲区，导致无限循环。**

```text
输入 "abc"
scanf("%d") 读到 'a' → 失败，返回 0，'a' 还在缓冲区
下一轮 scanf 又读到 'a' → 又失败
↓
无限打印菜单
```

清掉之后，程序能正常继续：

```c
static void clearInput(void) {
    int c;
    while ((c = getchar()) != '\n' && c != EOF) { }
}
```
