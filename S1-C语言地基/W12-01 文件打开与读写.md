# W12-01 文件打开与读写

> 前面所有程序的数据都活不过一次运行 —— 关掉窗口就全没了。
> 文件是让数据「留下来」的唯一手段，也是应用题里出现频率最高的场景之一。
>
> **C 的文件操作只有四步**：打开 → 读写 → 关闭 → 判错。记住这个骨架，剩下的都是细节。

---

## 一、FILE* 是什么

```c
FILE *fp = fopen("a.txt", "w");
```

`FILE` 是标准库定义的**结构体类型**（里面装着缓冲区地址、当前位置、错误标志等），`fp` 是指向它的指针。

我们不关心里面有什么，只把它当作一个「句柄」传来传去。所有文件函数第一个或最后一个参数都是它。

> 📝 **不要自己定义 `struct FILE`，也不要试图访问它的成员。** 不同平台的实现完全不同，标准只保证函数能用。

---

## 二、fopen 的 12 种模式

| 模式 | 含义 | 文件不存在时 | 文件已存在时 |
|---|---|---|---|
| `"r"` | 只读 | **失败，返回 NULL** | 从头读 |
| `"w"` | 只写 | 新建 | **清空！** |
| `"a"` | 追加 | 新建 | 从末尾写 |
| `"r+"` | 读写 | 失败 | 从头读写 |
| `"w+"` | 读写 | 新建 | **清空** |
| `"a+"` | 读写 | 新建 | 从末尾写，读从头 |
| `"rb"` `"wb"` `"ab"` 等 | 二进制版本 | 同上 | 同上 |

### 三个必须记住的点

**1. `"w"` 会立刻清空文件。**

哪怕你一个字都不写，只要 `fopen(path, "w")` 成功，文件就变成 0 字节。这是新手丢数据的头号原因。

```c
/* ❌ 想读却写了 "w"，文件当场被清空 */
FILE *fp = fopen("data.txt", "w");
fscanf(fp, "%d", &x);
```

**2. `"r"` 打不开不存在的文件。**

```c
FILE *fp = fopen("不存在.txt", "r");   /* fp == NULL */
```

所以**每个 fopen 后面必须判 NULL**。

**3. 文本模式和二进制模式在 Windows 上有差别。**

- 文本模式 `"w"`：写 `'\n'` 时自动变成 `"\r\n"`
- 二进制模式 `"wb"`：写什么就是什么

Linux 上两者没区别 —— 这是跨平台代码的经典坑。

---

## 三、判 NULL 与 perror

```c
FILE *fp = fopen(path, "w");
if (fp == NULL) {
    perror("fopen");          /* 会打印：fopen: No such file or directory */
    return 1;
}
```

`perror` 会读取系统最后一次错误的原因，拼在你给的字符串后面打印出来。

> ✅ **一个真实例子**：用 `"r"` 打开不存在的文件，`perror` 输出
> ```text
> fopen: No such file or directory
> ```
> 比你自己写「打开失败」有用得多 —— 它告诉你**为什么**失败。

## 四、写文件：fprintf / fputs / fputc

三个函数对应三种粒度：

```c
fprintf(fp, "%d %s %.1f\n", id, name, score);   /* 格式化，最常用 */
fputs("hello\n", fp);                           /* 整串，不加自动换行 */
fputc('A', fp);                                 /* 单字符 */
```

### 为什么不检查返回值会出事

`fprintf` 返回**成功写入的字符数**，失败返回负数。磁盘满了、权限不对，它都会返回负值，而不是崩溃。

```c
if (fprintf(fp, "%d\n", x) < 0) {
    perror("fprintf");
}
```

日常小作业可以不管，但软考题里如果问「怎么写才健壮」，答案就是**检查返回值**。

## 五、读文件：fgets / fscanf / fgetc

### ① fgets：逐行读（最推荐）

```c
char line[128];
while (fgets(line, sizeof(line), fp) != NULL) {
    /* 处理这一行 */
}
```

`fgets(buf, n, fp)` 读最多 `n-1` 个字符，遇到换行或 EOF 停下，**自动补 `'\0'`**。

> ⚠️ **fgets 会把换行符一起读进来。**
>
> 实测：读 `"2026001 张三 92.5\n"` 这一行，`strlen` 得到 **20**（内容 19 字节 + 1 个 `\n`），最后一个字符的 ASCII 是 **10**（就是 `'\n'`）。
>
> ```c
> size_t len = strlen(line);
> if (len > 0 && line[len - 1] == '\n') line[len - 1] = '\0';
> ```
>
> 不去掉的话，`strcmp(line, "abc")` 永远不相等 —— 因为实际是 `"abc\n"`。

> 📝 注意中文：`"张三"` 在 UTF-8 里占 **3 字节**，不是 1 个字符。所以 `strlen` 数的是字节数，不是「肉眼看到的字数」。

### ② fscanf：按格式读（适合结构化数据）

```c
int id; char name[32]; double score;
while (fscanf(fp, "%d %31s %lf", &id, name, &score) == 3) {
    /* 处理一条记录 */
}
```

> ⭐ **循环条件是 `== 3`，不是 `!= EOF`。**
>
> 因为 `fscanf` 返回的是「**成功读到的项数**」。如果最后一行只有两个字段，它返回 2，`!= EOF` 判断不出这种错，`== 3` 能。

### ③ fgetc：逐字符读

```c
int ch;
while ((ch = fgetc(fp)) != EOF) {
    /* 处理一个字符 */
}
```

> ❌ **`ch` 必须是 `int`，不能是 `char`。**
> `EOF` 通常是 `-1`。如果 `ch` 是 `unsigned char`，`-1` 会变成 `255`，永远不等于 `EOF`，**死循环**。

## 六、不要用 feof 做循环条件

这是 C 语言最经典的一类 bug。

```c
/* ❌ 错误写法 */
while (!feof(fp)) {
    fgets(line, sizeof(line), fp);
    /* 处理 line */
}
```

为什么错：`feof` 只有在**读操作失败之后**才返回真。所以最后一次循环会拿着「上一次的旧内容」或「空内容」再处理一遍。

如果是累加：

```c
while (!feof(fp)) {
    fscanf(fp, "%d", &x);
    sum += x;              /* ❌ 最后多加一次上一个 x */
}
```

实测中这个写法「碰巧」输出了正确的行数，因为 `fgets` 失败返回 NULL 被忽略了。**结果对不代表逻辑对** —— 换成 `sum += x` 就立刻出错。

> ✅ **正确原则：用读函数的返回值判断，不要用 feof。**

## 七、fclose：不关会丢数据

```c
fclose(fp);
```

`fprintf` 写的不是磁盘，是**内存缓冲区**。缓冲区满了（通常 4KB）或 `fclose` 时才真正落盘。

> ❌ 不 fclose 就退出：
> - 正常 `return` 时，进程退出会自动刷新，碰巧没事
> - 程序崩溃、`exit()` 前断电 → 缓冲区里的数据**全丢**
>
> ✅ 养成习惯：**打开就想着关，几条路径都要关。**

多文件时尤其容易漏：

```c
FILE *in = fopen(src, "r");
FILE *out = fopen(dst, "w");
if (out == NULL) {
    perror("open dst");
    fclose(in);              /* ⚠️ 这里必须关 in，否则句柄泄漏 */
    return 1;
}
```

## 八、和 scanf/printf 的对应关系

一旦看懂这张表，文件操作就没有新东西了：

| 屏幕 | 文件 | 差别 |
|---|---|---|
| `printf(fmt, ...)` | `fprintf(fp, fmt, ...)` | 多一个 `fp` |
| `scanf(fmt, ...)` | `fscanf(fp, fmt, ...)` | 多一个 `fp` |
| `getchar()` | `fgetc(fp)` | 多一个 `fp` |
| `putchar(c)` | `fputc(c, fp)` | 多一个 `fp` |
| `gets`（已废弃） | `fgets(buf, n, fp)` | 安全版 |
| — | `fputs(s, fp)` | 写整串 |

> 💡 **一个意外的等价**：`printf` 其实就是 `fprintf(stdout, ...)`；`scanf` 就是 `fscanf(stdin, ...)`。
> `stdout`/`stdin`/`stderr` 是三个默认为你打开的 `FILE*`。所以你的程序**一直在做文件操作**。

## 九、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 打开模式 | `"w"` 对已有文件做了什么 | **清空** |
| 打开失败 | `fopen` 返回值 | `NULL`，必须判 |
| 读一行 | 用哪个函数 | `fgets`（安全），不是 `gets` |
| 判断结束 | 用什么做条件 | 读函数的返回值，不是 `feof` |
| `fgetc` 返回类型 | 为什么用 `int` | 要能表示 EOF（-1） |
| 关闭 | 不 `fclose` 会怎样 | 缓冲区数据可能丢失 |
| 文本 vs 二进制 | Windows 上 `\n` 的变化 | 文本模式变成 `\r\n` |

> 📌 程序填空题常给出「打开—读—关」的骨架，让你补中间几行。判断空在哪：看前后变量名，基本能推出来。
