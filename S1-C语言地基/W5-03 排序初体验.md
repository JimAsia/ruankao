## 一、冒泡排序

**思路**：相邻两两比较，大的往后冒。每一轮结束，当前未排序部分的最大值被送到末尾。

```c
for (int i = 0; i < n - 1; i++) {
    for (int j = 0; j < n - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            int t = a[j];
            a[j] = a[j + 1];
            a[j + 1] = t;
        }
    }
}
```

### 1.1 逐轮过程（实测）

```text
排序前：72 45 91 38 66 88 55 79

第 1 轮后：45 72 38 66 88 55 79 91     ← 91 冒到最后
第 2 轮后：45 38 66 72 55 79 88 91     ← 88 就位
第 3 轮后：38 45 66 55 72 79 88 91     ← 79 就位
第 4 轮后：38 45 55 66 72 79 88 91     ← 全有序，后面的轮次不再变化
第 5~7 轮：结果不变（已有序，但没优化的话还会空跑）
```

> 💡 注意第 4 轮就已经排好了，但标准写法还会继续跑完 7 轮。这就是「优化」的价值。

### 1.2 ⭐ 两个边界为什么这样写

| 边界 | 原因 |
|---|---|
| 外层 `i < n - 1` | n 个元素最多比较 n-1 轮，最后剩下的一个元素自然就位 |
| 内层 `j < n - 1 - i` | 末尾已经有 i 个元素排好且是最大的，不用再碰 |

**比较总次数** = `(n-1) + (n-2) + ... + 1 = n(n-1)/2`，所以复杂度 **O(n²)**。

### 1.3 优化：提前结束

```c
for (int i = 0; i < n - 1; i++) {
    int swapped = 0;                    /* 本轮是否交换过 */

    for (int j = 0; j < n - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            /* 交换 */
            swapped = 1;
        }
    }
    if (!swapped) break;                /* 一趟没换 = 已有序 */
}
```

实测（已有序的数组 12 25 33 47 58 69）：

```text
  已有序的数组，加优化后只跑了 1 轮（没有优化要跑 5 轮）
  这就是冒泡排序最好情况是 O(n) 的原因
```

| 情况 | 复杂度 |
|---|---|
| 最好（已有序） | **O(n)**（加优化） |
| 最坏（逆序） | O(n²) |
| 平均 | O(n²) |

## 二、选择排序

**思路**：每轮从未排序部分选出最小的，与该轮首位交换。

```c
for (int i = 0; i < n - 1; i++) {
    int minIdx = i;
    for (int j = i + 1; j < n; j++) {       /* 找 [i,n-1] 里最小的 */
        if (a[j] < a[minIdx]) minIdx = j;
    }
    if (minIdx != i) {                       /* 不在原位才交换 */
        int t = a[i];
        a[i] = a[minIdx];
        a[minIdx] = t;
    }
}
```

### 2.1 逐轮过程（实测）

```text
第 1 轮：把 38 换到下标 0（交换 1 次）
         当前：38 45 91 72 66 88 55 79
第 2 轮：45 已经是最小，不用换
第 3 轮：把 55 换到下标 2（交换 1 次）
第 4 轮：把 66 换到下标 3（交换 1 次）
第 5 轮：72 已经是最小，不用换
第 6 轮：把 79 换到下标 5（交换 1 次）
第 7 轮：把 88 换到下标 6（交换 1 次）
```

共交换 **5 次**。

## 三、冒泡 vs 选择

| 维度 | 冒泡 | 选择 |
|---|---|---|
| 思路 | 边比边换，大的往后冒 | 先找最小的，最后换一次 |
| 比较次数 | n(n-1)/2 | n(n-1)/2 |
| **交换次数** | 最坏 O(n²) | **固定 O(n)** |
| 最好情况 | O(n)（加优化） | O(n²) |
| **稳定性** | ✅ **稳定** | ❌ **不稳定** |

真实输出：

```text
  选择排序总共只交换了 5 次
  冒泡排序同样 8 个数，交换次数通常要多得多
  原因：冒泡每发现一次逆序就换一次；选择每轮最多只换一次
```

### 3.1 ⭐ 为什么选择排序不稳定

**稳定** = 相等元素的相对次序在排序后不变。

```text
原数组：5a 5b 3 8 1        （5a、5b 是两个相等的值）
第 1 轮：最小是 1（下标 4），和下标 0 的 5a 交换
        变成：1 5b 3 8 5a

5a 跑到了 5b 后面 —— 相等元素的相对次序被改变了 → 不稳定
```

**判断稳定性的技巧**：如果算法会做**远距离交换**（把后面的元素直接换到前面），多半不稳定。冒泡、插入是相邻交换，所以稳定。

> 📌 这是 S2 排序总表的前置知识。完整的八种排序复杂度与稳定性对照，见 [[S2 考点手册 数据结构与算法]]。

## 四、什么时候用什么

| 场景 | 建议 |
|---|---|
| 学习 / 考试手写 | 冒泡（代码最短，最好记） |
| 数据基本有序 | 冒泡加优化（最好 O(n)） |
| 交换成本高（元素很大） | 选择（交换次数少） |
| 实际开发 | 用 `qsort` 库函数，别手写 |

## 五、软考怎么考这部分

| 考点 | 位置 | 典型问法 |
|---|---|---|
| 冒泡每轮后的结果 | 应用技术 | 「第 2 轮结束后数组是什么样」 |
| 比较次数 / 交换次数 | 基础知识 | 「n 个数冒泡要比较几次」 |
| 优化后的最好复杂度 | 基础知识 | 「冒泡最好情况是 O(n) 还是 O(n²)」 |
| 稳定性判断 | 基础知识 | 「冒泡和选择哪个稳定」 |
| 排序过程追踪 | 应用技术 | 给一组数据问第几轮后有序 |

**⚠️ 最常见的错**：把内层写成 `j < n - 1`（漏掉 `- i`）。虽然结果也对，但多做无用功，而且考试如果问「第 i 轮比较几次」就会答错。
