## 一、三种形态

```c
/* 单分支：条件成立才做事 */
if (score >= 60)
    printf("及格\n");

/* 双分支：二选一 */
if (score >= 60)
    printf("及格\n");
else
    printf("不及格\n");

/* 多分支：见下一篇 */
```

**执行流程**：条件成立 → 执行 if 后的语句；不成立 → 跳过（有 else 则执行 else）。

---

## 二、三条必须记住的规则

### 2.1 条件可以是任何标量，非 0 即真

```c
int n = -3;
if (n)                 /* ✅ -3 是非 0，判为真 */
    printf("真\n");

if (n != 0)            /* 同样效果，但啰嗦 */
    printf("真\n");
```

> 💡 所以不要写 `if (flag == 1)`，直接写 `if (flag)`。后者对任何非 0 值都正确，前者只认 1。

### 2.2 多条语句必须加大括号

```c
if (score >= 60)
    printf("及格\n");
    printf("恭喜\n");      /* ❌ 这句不受 if 控制，永远执行 */
```

编译器不报错，但逻辑完全错了。**建议无论几句都写大括号**——将来加一行代码时才不会踩坑。

### 2.3 ⭐ 悬空 else：else 就近匹配

```c
if (a > 0)
    if (b > 0)
        printf("both\n");
else
    printf("a <= 0\n");     /* ← 这个 else 属于内层 if，不是外层！ */
```

`21_if_else.c` 的真实输出（a = 1，b = -5）：

```text
a = 1, b = -5
实际输出：a <= 0
↑ 打印了 a <= 0，可 a 明明是 1！
  因为 else 就近匹配内层 if，不是外层。
```

**原理**：C 语言的 else 总是与**最近的、尚未配对的 if** 结合，跟缩进无关。缩进只是给人看的。

编译器其实也看出问题了，会警告：

```text
warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
```

**正确写法**：给外层加大括号，把意图写明确。

```c
if (a > 0) {
    if (b > 0)
        printf("both\n");
    else
        printf("a > 0 但 b <= 0\n");
} else {
    printf("a <= 0\n");
}
```

> 📌 悬空 else 是软考选择题的经典考点。给一段缩进骗人的代码问输出，按「就近匹配」推就对了。

## 三、浮点数不能直接用 `==` 比较

```c
double a = 0.1 + 0.2;
if (a == 0.3)          /* ❌ 结果大概率是假 */
    printf("相等\n");
```

原因：0.1、0.2、0.3 在二进制里都是无限循环小数，存进 double 有微小误差，`0.1 + 0.2` 得到的不是精确的 `0.3`。

**正确做法**：判断差值足够小。

```c
#include <math.h>
if (fabs(a - 0.3) < 1e-9)     /* ✅ 差值小于十亿分之一就认为相等 */
    printf("相等\n");
```

实测结果：

```text
0.1+0.2 == 0.3     = 0
0.1+0.2            = 0.30000000000000004
```

差在哪一目了然：`0.1+0.2` 得到的是 `0.30000000000000004`，不是 `0.3`。

⚠️ 整数比较没这个问题，可以放心用 `==`。

## 四、常见写法对照

| 场景 | 推荐写法 | 不推荐 |
|---|---|---|
| 判断真假 | `if (flag)` | `if (flag == 1)` |
| 判断非零 | `if (n)` | `if (n != 0)` |
| 判断空指针 | `if (p == NULL)` | `if (!p)`（可以，但 `NULL` 更明确） |
| 浮点相等 | `fabs(a-b) < 1e-9` | `a == b` |
| 范围判断 | `if (a > 0 && a < 10)` | `if (0 < a < 10)` ⚠️ 恒真 |

**⚠️ `0 < a < 10` 是经典错误**：C 里它会先算 `0 < a`（得 0 或 1），再算 `1 < 10`（恒真）。必须写成 `a > 0 && a < 10`。

实测（a = 15，明显不在 0~10 之间）：

```text
0 < 15 < 10        = 1      ← 假阳性，错了
15 > 0 && 15 < 10  = 0      ← 正确结果
```

编译器也看得出来，会给出两条警告：

```text
warning: comparisons like 'X<=Y<=Z' do not have their mathematical meaning [-Wparentheses]
warning: comparison of constant '10' with boolean expression is always true [-Wbool-compare]
```

看到这两条警告，说明你把数学写法直接搬进代码了。

## 五、软考怎么考这部分

| 考点 | 位置 | 典型问法 |
|---|---|---|
| 悬空 else 匹配 | 基础知识 | 给缩进骗人的代码问输出 |
| 非 0 即真 | 应用技术 | 给 `if (n)` 问在 n 取何值时执行 |
| 漏写大括号 | 基础知识 | 找错题里常见 |
| `0 < a < 10` 恒真 | 基础知识 | 「这个条件有什么问题」 |
| 浮点比较 | 基础知识 | 「能否用 == 判断浮点相等」 |
| 分支覆盖 | 应用技术 | 给流程图补全条件 |

📌 **应用技术的流程图题本质就是 if-else + 循环**。给定流程图能写代码、给定代码能画流程图，这是必练的基本功。
