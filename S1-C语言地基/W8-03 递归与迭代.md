## 一、递归的三个代价

| 代价 | 说明 |
|---|---|
| **栈空间** | 每层递归占一个栈帧，深度大就会栈溢出 |
| **函数调用开销** | 每次调用要保存/恢复现场，比循环慢 |
| **重复计算** | 子问题重叠时（斐波那契）会指数级爆炸 |

---

## 二、栈溢出

```c
int depthOf(int n)
{
    if (n == 0) return 0;
    return 1 + depthOf(n - 1);
}
```

实测：

```text
  depthOf(10) = 10
  depthOf(100) = 100
  depthOf(1000) = 1000
  depthOf(10000) = 10000
```

**为什么深度有上限**：每个栈帧要占内存（存参数、返回地址、局部变量），栈的总大小是固定的（通常几 MB）。深度太大就会写爆。

**栈溢出的两种原因**：

| 原因 | 例子 |
|---|---|
| 出口写错 / 没靠近出口 | `f(n) { return f(n+1); }` |
| 层数本身很大 | 递归遍历一个 10 万节点的链表 |

> 📌 软考问「递归的主要缺点」，答：**栈空间开销大，可能栈溢出**。

## 三、递归转迭代的三个套路

### 3.1 阶乘：从"链"到"循环"

```c
/* 递归：n * f(n-1) */
long long factRec(int n) {
    if (n <= 1) return 1;
    return n * factRec(n - 1);
}

/* 迭代：用一个变量累积 */
long long factIter(int n) {
    long long f = 1;
    for (int i = 1; i <= n; i++) f *= i;
    return f;
}
```

**转换方法**：递归里的「返回值累积」变成循环里的「变量累积」。

### 3.2 斐波那契：从"树"到"滚动变量"

```c
long long fibIter(int n) {
    if (n <= 2) return 1;
    long long a = 1, b = 1, c;
    for (int i = 3; i <= n; i++) {
        c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

实测对照：

```text
  n    递归        迭代        一致
  10   55          55          是
  20   6765        6765        是
  30   832040      832040      是
```

**性能差距**：n=30 时递归调用约 166 万次，迭代只跑 28 轮。

### 3.3 尾递归：理论上能优化

```c
/* 普通递归：递归返回后还要做加法 */
long long sumNormal(int n) {
    if (n == 0) return 0;
    return n + sumNormal(n - 1);        /* 递归不是最后一步 */
}

/* 尾递归：递归调用就是最后一步，结果直接往下传 */
long long sumTail(int n, long long acc) {
    if (n == 0) return acc;
    return sumTail(n - 1, acc + n);     /* 递归是最后一步 */
}
```

实测：两者结果都是 5050。

**尾递归的好处**：理论上编译器能把它优化成循环，不占额外栈空间。

> ⚠️ **但 C 标准不要求编译器做这个优化**。gcc 加 `-O2` 才会做，不加优化还是照样占栈。

## 四、⭐ 什么时候用递归

| 场景 | 建议 | 原因 |
|---|---|---|
| 树、图的遍历 | ✅ **递归** | 结构本身就是递归的 |
| 分治（快排、归并） | ✅ **递归** | 天然拆成两半 |
| 汉诺塔 | ✅ **递归** | 迭代写法极其晦涩 |
| 简单求和、阶乘 | ❌ **循环** | 递归没有优势，还多开销 |
| 斐波那契 | ❌ **循环**（或记忆化） | 朴素递归指数级爆炸 |
| 深度可能很大 | ❌ **循环** | 栈溢出风险 |

**判断口诀**：

```text
问题是"自己包含自己"的结构 → 递归
只是"重复做同一件事"      → 循环
```

## 五、递归 vs 迭代总表

| 维度 | 递归 | 迭代 |
|---|---|---|
| 代码 | 通常更短，贴合数学定义 | 通常更长 |
| 可读性 | 对递归结构友好 | 对线性流程友好 |
| 空间 | O(深度) 栈空间 | 通常 O(1) |
| 时间 | 有函数调用开销 | 更快 |
| 风险 | 栈溢出、重复计算 | 死循环 |
| 调试 | 难（跳来跳去） | 易（顺序执行） |
