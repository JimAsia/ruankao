## 一、算术运算符：`+ - * / %`

| 运算符 | 名称 | 例（a=17, b=5） | 结果 |
|---|---|---|---|
| `+` | 加 | `a + b` | 22 |
| `-` | 减 | `a - b` | 12 |
| `*` | 乘 | `a * b` | 85 |
| `/` | 除 | `a / b` | 3 |
| `%` | 取余（模） | `a % b` | 2 |

> ⚠️ `%` 只能用于**整数**。`5.0 % 2` 编译直接报错。

### 1.1 整数除法的两条铁律（软考高频）

**铁律一：向零截断，不是向下取整。**

```text
  7 /  2 = 3
 -7 /  2 = -3      ← 注意是 -3，不是 -4
  7 / -2 = -3
 -7 / -2 = 3
```

**铁律二：取余的符号跟着被除数走（C99 起）。**

```text
  7 %  3 = 1
 -7 %  3 = -1      ← 符号跟 -7
  7 % -3 = 1
 -7 % -3 = -1
```

> 💡 记忆法：`a % b` 的结果，`|a % b| < |b|` 且符号与 `a` 相同。
> 这条规则 C99 才明确下来，老教材可能写成「结果不确定」，以新标准为准。

### 1.2 想要小数，必须先变浮点

```c
int a = 17, b = 5;

a / b              /* ❌ 3，小数部分直接丢 */
(double)a / b      /* ✅ 3.40 */
a / (double)b      /* ✅ 3.40 */
a / 5.0            /* ✅ 3.40 */
```

关键点：**转换发生在除法之前**。`(double)(a / b)` 只是把已经算好的 3 转成 3.0，晚了。

### 1.3 混合运算自动提升

```c
5 + 2.0      /* 7.0，int 提升成 double */
'A' + 1      /* 66，字符当整数 */
```

提升方向：`char → short → int → unsigned → long long → float → double`

## 二、关系运算符：结果是 1 或 0

| 运算符 | 含义 | 例 | 结果 |
|---|---|---|---|
| `>` | 大于 | `3 > 2` | 1 |
| `>=` | 大于等于 | `3 >= 3` | 1 |
| `<` | 小于 | `3 < 2` | 0 |
| `<=` | 小于等于 | `3 <= 2` | 0 |
| `==` | 等于 | `3 == 3` | 1 |
| `!=` | 不等于 | `3 != 2` | 1 |

> ❌ 新手第一大坑：把 `==` 写成 `=`。
> `if (n = 0)` 把 0 赋给 n，表达式的值是 0，**永远为假**，编译器还不报错。
> 防御写法：`if (0 == n)`，万一少写一个等号会直接编译失败。

### 2.1 浮点数不能直接比相等

```c
double a = 0.1 + 0.2;
a == 0.3        /* ❌ 结果是 0（假） */
```

原因：0.1、0.2、0.3 在二进制里都是无限循环小数，存进 double 有微小误差，加起来不等于字面的 0.3。

正确做法是判断「足够接近」：

```c
#include <math.h>
fabs(a - 0.3) < 1e-9    /* ✅ 差值小于某个极小值就认为相等 */
```

> 📌 软考选择题喜欢问「浮点数能不能用 == 比较」，答案是**不能**。

## 三、逻辑运算符：`&& || !`

| 运算符    | 名称  | 规则      | 例          | 结果  |
| ------ | --- | ------- | ---------- | --- |
| `&&`   | 逻辑与 | 两边都真才真  | `1 && 0`   | 0   |
| `\|\|` | 逻辑或 | 一边真就真   | `1 \|\| 0` | 1   |
| `!`    | 逻辑非 | 真变假，假变真 | `!5`       | 0   |

### 3.1 C 语言没有专门的布尔类型

**非 0 即真，0 为假。** 任何非零值都算真，包括负数和小数。

```text
!5    = 0     5 是真
!0    = 1     0 是假
!(-1) = 0     -1 也是真
!0.5  = 0     0.5 也是真
```

> 📝 C99 引入了 `<stdbool.h>` 和 `bool`/`true`/`false`，但本质仍是 `0` 和 `1` 的宏。软考按「非 0 即真」答就对了。

### 3.2 短路求值（本节重点）

**`&&` 左边为假 → 右边不执行。**
**`||` 左边为真 → 右边不执行。**

怎么证明？用 `++` 的副作用观察 —— 如果右边执行了，变量会变：

```text
i = 0,  r = (0 && ++i)   →  r = 0, i = 0    ← i 没变，右边没执行
i = 0,  r = (1 || ++i)   →  r = 1, i = 0    ← i 没变，右边没执行
i = 0,  r = (1 && ++i)   →  r = 1, i = 1    ← i 变了，右边执行了
i = 0,  r = (0 || ++i)   →  r = 1, i = 1    ← i 变了，右边执行了
```

**短路不是"优化"，是语义保证。** 它让你能写出安全的代码：

```c
p != 0 && 10 / p > 2
```

`p` 为 0 时，左边为假，`10 / p` 压根不执行，不会除零。把可能出事的操作放右边，是 C 语言里非常常用的写法。

> ⚠️ 反过来，如果你希望右边**一定**执行（比如里面有个必须发生的函数调用），就别依赖 `&&`。

## 四、软考怎么考这部分

| 考点 | 位置 | 典型问法 |
|---|---|---|
| 整数除法与取余 | 应用技术 | 「7 / 2 和 7 % 2 分别是多少」 |
| 负数取余的符号 | 基础知识 | 「-7 % 3 等于多少」（-1） |
| 整数除法截断方向 | 基础知识 | 「-7 / 2 等于多少」（-3，不是 -4） |
| `==` 与 `=` 的区别 | 基础知识 | 找错题里最常见的错误 |
| 浮点数比较 | 基础知识 | 「能否用 == 判断两个浮点数相等」 |
| 短路求值 | 基础知识 | 给一段代码问 i 最终是多少 |
| 非 0 即真 | 应用技术 | 读程序判断分支走向 |

**读程序题的标准解法**：不要凭感觉。在草稿纸上一步一步写变量当前的值，每执行一句更新一次。
