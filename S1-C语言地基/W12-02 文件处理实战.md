# W12-02 文件处理实战

> 文件操作考的不是 API，是**三个固定套路**：
> 统计（wc）、复制（cp）、合并（cat）。
> 这三个写熟了，应用题换什么数据都不怕。

---

## 一、统计：行数、字符数、单词数

### 代码骨架

```c
int ch;
long chars = 0, lines = 0, words = 0;
int inWord = 0;

while ((ch = fgetc(fp)) != EOF) {
    chars++;
    if (ch == '\n') lines++;

    if (ch == ' ' || ch == '\n' || ch == '\t') {
        inWord = 0;
    } else if (!inWord) {
        inWord = 1;
        words++;
    }
}
```

### 真实输出

对两个测试文件和一个源码文件统计：

```text
part1.txt          行 2  字符 30  单词 6
part2.txt          行 2  字符 16  单词 4
113_file_process.c 行 171  字符 5520  单词 607
```

### `inWord` 标记为什么必须要有

新手常这样写：

```c
if (ch == ' ') words++;      /* ❌ */
```

这样 `"a    b"`（中间 4 个空格）数出 4 个单词，实际只有 2 个。

用 `inWord` 标记，逻辑是：

| 当前字符 | `inWord` | 动作 |
|---|---|---|
| 空白 | 任意 | `inWord = 0` |
| 非空白 | 0（刚离开空白） | `words++`，`inWord = 1` ← **新单词开始** |
| 非空白 | 1（单词进行中） | 什么都不做 |

> ⭐ **核心洞察：数的是「从空白进入非空白的次数」，不是空格数。**
> 这个模式在软考题里出现过，也常用于「统计句子中有多少个单词」。

### 行数的两种算法

```c
if (ch == '\n') lines++;          /* 数换行符 */
```

⚠️ 如果文件最后一行**没有换行**，这种数法会少 1 行。

更稳的做法是按 `fgets` 数：

```c
while (fgets(line, sizeof(line), fp) != NULL) lines++;
```

只要 `fgets` 能读到东西就算一行，不管末尾有没有 `\n`。

## 二、复制：两种写法，差 100 倍速度

### 逐字符（简单但慢）

```c
int ch;
while ((ch = fgetc(in)) != EOF) {
    fputc(ch, out);
}
```

每个字节调用两次函数。1MB 文件要调 200 万次。

### 逐块（工程做法）

```c
char buf[512];
size_t n;
while ((n = fread(buf, 1, sizeof(buf), in)) > 0) {
    fwrite(buf, 1, n, out);            /* ⚠️ 写 n 个，不是 sizeof(buf) */
}
```

> ❌ **`fwrite(buf, 1, sizeof(buf), out)` 是错的。**
> 最后一块可能只读了 100 字节，剩下 412 字节是**上一次的残留数据**，写进去文件就被写坏了。
> 必须写 `n` —— 实际读到的字节数。

`fread` 的返回值就是「实际读到的元素个数」，读到文件末尾返回 0。

## 三、合并：两个循环接起来

```c
int ch;
while ((ch = fgetc(fa)) != EOF) fputc(ch, fo);
while ((ch = fgetc(fb)) != EOF) fputc(ch, fo);
```

真实输出（`part1` 两行 + `part2` 两行 → 四行）：

```text
hello world
C language is fun
file io
the end
```

> 💡 更通用的写法是「遍历一个文件列表」，但两道题以内，两个循环最清楚。

### 合并时的一个坑

如果第一个文件末尾**没有换行**，合并后两行会粘在一起：

```text
...last line of ahello world
```

处理办法：合并前检查第一个文件的最后一个字符，不是 `\n` 就补一个。

## 四、文件 + 结构体：最实用的组合

这是应用题的核心模式 —— **一条记录 = 一行 = 一个结构体**。

### 写

```c
for (int i = 0; i < n; i++) {
    fprintf(fp, "%d %s %.1f\n", a[i].id, a[i].name, a[i].score);
}
```

### 读

```c
Student s;
while (fscanf(fp, "%d %19s %lf", &s.id, s.name, &s.score) == 3) {
    /* 用 s 做统计或存进数组 */
}
```

真实运行结果：

```text
读入：1 张三 85.5
读入：2 李四 92.0
读入：3 王五 78.0
读入：4 赵六 90.5

共 4 人，总分 346.00，平均 86.50
```

### 三个对应关系

| 内存 | 文件 |
|---|---|
| 结构体变量 | 一行 |
| 结构体数组 | 整个文件 |
| `fscanf` 一次 | 读一条记录 |
| `fprintf` 一次 | 写一条记录 |

> ⭐ 想清楚这三行对应，文件大题就没有难度了。
> 「读入所有学生」= 循环 `fscanf` 进数组；「保存」= 循环 `fprintf`。

### `%19s` 的宽度限制不能省

```c
char name[20];
fscanf(fp, "%19s", name);      /* ✅ 最多读 19 个字符，留 1 位给 '\0' */
fscanf(fp, "%s", name);        /* ❌ 文件里一个超长单词就写爆内存 */
```

> 📝 文件内容你自己控制时可以不管，但**处理别人给的文件时这是必须的** —— 软考题目里出现 `%s` 读文件，往往就是让你改错。

## 五、写出错时怎么排查

| 现象 | 原因 | 检查 |
|---|---|---|
| 文件是空的 | 没 `fclose`，或程序中途 `return` | 加 `fclose` 并检查每个返回路径 |
| 文件被清空了 | 用了 `"w"` 打开想读 | 改成 `"r"` |
| 读不到内容 | `fopen` 返回 NULL 没判，或路径错 | 打印 `perror` 看原因 |
| 多读一行/多算一次 | 用 `feof` 做循环条件 | 改用读返回值 |
| 中文乱码 | 编码不一致（GBK vs UTF-8） | 本讲义全部用 UTF-8 |
| 数字读错位 | `fscanf` 格式串和文件不匹配 | 对照文件内容逐字段核对 |

## 六、软考怎么考

| 考点 | 典型问法 |
|---|---|
| 统计 | 补全循环，求行数/字符数/单词数 |
| 复制 | 补全 `fgetc`/`fputc` 循环 |
| 结构体存取 | 补全 `fprintf`/`fscanf` 的格式串 |
| 读取终止 | 循环条件怎么写 |
| 追加 | `"a"` 和 `"w"` 的区别 |

> 📌 **应用题给分是按步骤的**。写不出完整代码时，至少写出：
> 1. `FILE *fp = fopen(...)` 和判 NULL
> 2. 循环骨架 `while (... != EOF)`
> 3. `fclose(fp)`
>
> 这三步就有分。
