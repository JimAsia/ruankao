## 二、从源码到程序：四个阶段

这是《基础知识》「程序语言基础」的固定考点，也是你读懂报错的钥匙。

```text
hello.c  ──预处理──▶  hello.i  ──编译──▶  hello.s  ──汇编──▶  hello.o  ──链接──▶  hello.exe
  源码                 预处理后            汇编代码            目标文件              可执行文件
```

| 阶段 | 谁干的 | 干什么 | 产物 | 这里出错长什么样 |
|---|---|---|---|---|
| 预处理 | 预处理器 | 展开 `#include`、替换 `#define`、删注释 | `.i` | `No such file or directory`（头文件找不到） |
| 编译 | 编译器 | C 代码 → 汇编代码，同时做语法检查 | `.s` | `error: expected ';' before ...`（语法错） |
| 汇编 | 汇编器 | 汇编代码 → 机器指令 | `.o` / `.obj` | 一般不会出错 |
| 链接 | 链接器 | 把多个 `.o` 和库拼成一个可执行文件 | `.exe` | `undefined reference to 'foo'`（函数只有声明没有定义） |

> ✅ **一句口诀**：**语法错在编译阶段，找不到函数在链接阶段。**
> ❌ 软考选择题最爱问：「代码能编译通过但运行时崩溃，属于哪个阶段的问题？」——都不是，是**运行时**问题，编译和链接都已经成功了。

## 三、第一个程序，逐行拆开

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, Programmer!\n");
    return 0;
}
```

| 行 | 作用 | 注意 |
|---|---|---|
| `#include <stdio.h>` | 把标准输入输出的「说明书」搬进来 | 预处理指令，**行末不加分号** |
| `int main(void)` | 主函数，程序唯一入口 | 名字必须是 `main`；`int` 是返回类型；`void` 表示不收参数 |
| `{ }` | 函数体，括起来的部分归它管 | 成对出现，漏一个就是编译错误 |
| `printf(...)` | 格式化输出到屏幕 | **每句语句必须以分号结尾** |
| `"Hello, Programmer!\n"` | 要打印的内容，`\n` 是换行 | 没有 `\n`，后续输出会接在同一行 |
| `return 0;` | 告诉系统「正常结束」 | 返回非 0 表示出错；`main` 里可省略，但写上更规范 |

## 四、跑起来（三条命令）

在 `code\w1` 目录下打开终端：

```bash
# 1. 编译：把 .c 变成 .exe
gcc -std=c17 -Wall -Wextra -o 01_hello 01_hello.c

# 2. 运行
./01_hello

# 3. 一条命令搞定编译 + 运行（调试期最省事）
gcc -std=c17 -Wall -Wextra -o 01_hello 01_hello.c && ./01_hello
```

**编译参数的含义（别当黑盒用）：**

| 参数            | 作用                                     |
| ------------- | -------------------------------------- |
| `-std=c17`    | 使用 C17 标准。软考教材的语法以 C89/C99 为主，C17 完全兼容 |
| `-Wall`       | 打开所有常用警告。**警告一定要看，很多 bug 在警告里写着**      |
| `-Wextra`     | 再打开一些额外的警告                             |
| `-o 01_hello` | 指定输出文件名。不加就默认叫 `a.exe`                 |

**真实运行结果：**

```text
$ gcc -std=c17 -Wall -Wextra -o 01_hello 01_hello.c
$ ./01_hello
Hello, Programmer!
```

> 📝 编译成功时 gcc **什么都不输出**。没输出就是好消息。这是 C 语言给新手的第一个反直觉体验。

## 五、报错速查表

| 报错关键字 | 真实原因 | 怎么改 |
|---|---|---|
| `expected ';' before 'return'` | 上一行漏了分号 | 报错行往往不是出错行，**看上一行** |
| `'printf' undeclared` | 忘了 `#include <stdio.h>` | 补上头文件 |
| `expected declaration or statement at end of input` | 大括号没配对 | 数一遍 `{` 和 `}` |
| `undefined reference to 'xxx'` | 函数只有声明、没有定义；或没参与链接 | 检查函数有没有实现 |
| `ld returned 1 exit status` | 链接阶段的总结行，**真正原因在上面几行** | 往上翻，找 `undefined reference` |
| `warning: 'x' is used uninitialized` | 用了没赋初值的变量 | 声明时就给初值 |

> ⚠️ 你的环境（MinGW）有时只显示 `collect2.exe: error: ld returned 1 exit status`，把 `undefined reference` 那行吞掉了。看到这行就去检查「有没有函数只写了声明没写实现」。

## 六、软考怎么考这部分

| 考法 | 出现位置 | 要点 |
|---|---|---|
| 编译四阶段的顺序和产物 | 基础知识 · 选择题 | `.c → .i → .s → .o → .exe` |
| 区分编译错误与链接错误 | 基础知识 · 选择题 | 语法错 = 编译；找不到定义 = 链接 |
| `main` 函数的返回值含义 | 基础知识 / 应用技术 | 返回 0 表示正常 |
| 头文件的作用 | 基础知识 | 存放**声明**，不是实现 |
