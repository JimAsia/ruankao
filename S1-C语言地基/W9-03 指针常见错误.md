## 一、七个错误速查

| # | 错误 | 后果 |
|---|---|---|
| ① | 未初始化就解引用（野指针） | 写到随机地址，可能崩溃或改坏数据 |
| ② | 空指针解引用 | 立刻崩溃（段错误） |
| ③ | 指针类型不匹配 | 读错字节数，越界 |
| ④ | 数组名当指针赋值 | 编译错误 |
| ⑤ | 返回局部变量的地址 | 悬空指针，读到垃圾 |
| ⑥ | `scanf` 忘写 `&` | 内存被写坏 |
| ⑦ | 混淆 `*p++` 与 `(*p)++` | 逻辑错误 |

## 二、重点讲三个

### 2.1 ⑤ 返回局部变量的地址

```c
int *wrongReturnLocal(void)
{
    int local = 42;
    return &local;      /* ⚠️ local 在函数返回时就销毁了 */
}
```

实测（编译器会警告）：

```text
warning: function returns address of local variable [-Wreturn-local-addr]
```

**为什么错**：`local` 存在栈上，函数返回时栈帧被回收，那个地址已经不属于你了。再访问就是读到别人的垃圾数据。

**三种正确做法**：

```c
/* ① 用 static（值会一直保留） */
int *f1(void) { static int x = 42; return &x; }

/* ② 由调用者传入缓冲区（最常用） */
void f2(int *out) { *out = 42; }

/* ③ 动态分配（本阶段还没学，S2 会讲） */
```

### 2.2 ⑥ `scanf` 忘写 `&`

```c
int n;
scanf("%d", n);         /* ❌ 少了一个 & */
scanf("%d", &n);        /* ✅ */
```

**为什么会出错**：`scanf` 需要「地址」来写入。你给它 `n` 的值（比如 5），它就把输入写到地址 5 那里 —— 那里可能是任何东西。

> 💡 例外：读字符串数组时不用 `&`，因为数组名本身就是地址。
> ```c
> char s[100];
> scanf("%s", s);      /* ✅ 正确 */
> ```

### 2.3 ⑦ `*p++` 与 `(*p)++`

```text
*p++    取当前值，然后指针后移
(*p)++  把指向的值加 1，指针不动
```

因为 `++` 的优先级高于 `*`，所以 `*p++` 是 `*(p++)`。

**记法**：`*p++` 走指针，`(*p)++` 改值。

## 三、指针自查表

写指针代码时，逐条问自己：

| 疑问 | 该检查什么 |
|---|---|
| 它是 NULL 吗？ | 解引用前先判空 |
| 它指向的对象还活着吗？ | 别返回局部变量的地址 |
| 类型对吗？ | 指向 int 的必须是 `int *` |
| 越界了吗？ | 下标 0 ~ n-1，`p < a+n` |
| 改的是指针还是值？ | `*p =` 改值，`p =` 改指向 |

## 四、怎么调试指针问题

| 手段 | 作用 |
|---|---|
| `-Wall -Wextra` | 把警告当错误看，能抓出一大半问题 |
| `-fsanitize=address` | 运行时检测越界、悬空指针、内存泄漏 |
| 所有指针声明时初始化成 `NULL` | 从源头减少野指针 |
| 打印地址 | `printf("%p", (void*)p)` 看它指向哪 |

**编译时加 sanitizer 的例子**：

```bash
gcc -std=c17 -Wall -Wextra -fsanitize=address -g -o test test.c
./test      # 有越界会直接报出具体行号
```

> 📌 这个选项在软考里不会考，但对你实际调试极有帮助。建议以后写指针代码都加上。
