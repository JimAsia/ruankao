# W13-01 位运算进阶：掩码、位域与经典题

> W2 讲了位运算符「是什么」（`& | ^ ~ << >>`），这一节讲「怎么用」。
> 位运算真正的用途是：**用一位存一个状态**。一个 `unsigned int` 能装 32 个开关。

---

## 一、四个基本操作

对第 `n` 位（从 0 起）做操作，只有四个公式：

| 操作 | 公式 | 效果 |
|---|---|---|
| 置位 set | `x \|= (1u << n)` | 第 n 位置 1，其他位不变 |
| 清位 clear | `x &= ~(1u << n)` | 第 n 位置 0，其他位不变 |
| 取反 toggle | `x ^= (1u << n)` | 第 n 位翻转 |
| 测试 test | `(x >> n) & 1u` | 读出第 n 位 |

### 实测过程

以 `x = 10`（二进制 `0000 1010`）为例：

```text
初始 x         = 0000 1010  (10)
置位 bit0      = 0000 1011  (11)
清位 bit3      = 0000 0011  (3)
翻转 bit1      = 0000 0001  (1)

测试 bit1 = 0
测试 bit0 = 1
```

### 为什么清位要写 `&= ~(1 << n)`

```text
1 << n          →  0000 0100    （只有第 2 位是 1）
~(1 << n)       →  1111 1011    （只有第 2 位是 0）
x & ~(1 << n)   →  只有第 2 位被清，其他位保持原样
```

> ⚠️ **用 `1u` 不用 `1`。**
> `1` 是 `int`，左移 31 位会变成负数（有符号溢出，未定义行为）；`1u` 是无符号，`1u << 31` 得到 `0x80000000`，正确。

## 二、位掩码做权限：一字节装 8 种权限

```c
const unsigned int PERM_READ   = 1u << 0;   /* 0000 0001 */
const unsigned int PERM_WRITE  = 1u << 1;   /* 0000 0010 */
const unsigned int PERM_EXEC   = 1u << 2;   /* 0000 0100 */
const unsigned int PERM_DELETE = 1u << 3;   /* 0000 1000 */

unsigned int perm = 0;
perm |= PERM_READ;          /* 加读权限 */
perm |= PERM_WRITE;         /* 加写权限 */
perm &= ~PERM_WRITE;        /* 撤销写权限 */
```

实测输出：

```text
加了读+写    = 0000 0011  (3)
撤销写        = 0000 0001  (1)
加删除        = 0000 1001  (9)
再按一次取消 = 0000 0001  (1)
有读权限 ✓
没有写权限 ✓
```

注意 `perm ^= PERM_DELETE` 的效果：**同一个操作既能加也能取消**。这就是 XOR 的特性。

### 一次判断多个权限

```c
unsigned int need = PERM_READ | PERM_EXEC;
if ((perm & need) == need) {        /* ✅ 两个都有 */
    /* 有权限 */
}
```

> ❌ **不能写 `if (perm & need)`。**
> 那只要求「至少有一个」，`perm` 只有读权限时也会通过。

实测状态（`perm` 只有读权限，`need` 是读+执行）：

```text
权限不足（需要 读+执行）
```

## 三、经典题一：统计二进制中 1 的个数

```c
int countOnes(unsigned int x)
{
    int cnt = 0;
    while (x) {
        x &= x - 1;        /* 每次消掉最低位的 1 */
        cnt++;
    }
    return cnt;
}
```

实测：

```text
0            → 0 个 1
1            → 1 个 1
7            → 3 个 1
15           → 4 个 1
255          → 8 个 1
1023         → 10 个 1
4294967295   → 32 个 1
```

### 为什么 `x & (x-1)` 能消掉最低位的 1

```text
x     = 12 = 1100
x - 1 = 11 = 1011     ← 最低位的 1 变 0，右边全变 1
x & (x-1) = 1000 = 8  ← 最低位的那个 1 没了
```

> ⭐ **循环次数 = 1 的个数**，而不是固定的 32 次。
> 这叫 Brian Kernighan 算法，比逐位检查快。

## 四、经典题二：判断是不是 2 的幂

```c
int isPowerOfTwo(unsigned int x)
{
    return x != 0 && (x & (x - 1)) == 0;
}
```

实测：

```text
1      是
2      是
3      不是
4      是
6      不是
8      是
16     是
100    不是
256    是
1024   是
```

> ⭐ 原理：2 的幂只有一个 1（如 `8 = 1000`），减 1 后变成「0 后面全 1」（`7 = 0111`），两者 `&` 必为 0。

> ⚠️ **`x != 0` 不能省。** `0 & (0-1)` = `0 & 0xFFFFFFFF` = `0`，不加判断会把 0 判成 2 的幂。

## 五、经典题三：异或交换

```c
a ^= b;
b ^= a;
a ^= b;
```

实测：`a = 5, b = 9` → `a = 9, b = 5`。

> ⭐ 原理：`x ^ x = 0`，`x ^ 0 = x`。
>
> ❌ 但**实际工程不要用**：
> - 如果 `a` 和 `b` 是同一个变量，`a ^= a` 会把它清零
> - 可读性差，编译器也不会因此生成更快的代码
>
> 软考偶尔考这个，会做就行，写代码还是用临时变量。

## 六、位域：用位定义结构体成员

语法：`类型 成员名 : 位数;`

```c
struct FlagsPlain {          /* 12 字节 */
    unsigned int isReady;
    unsigned int hasError;
    unsigned int isActive;
};

struct FlagsBit {            /* 4 字节 */
    unsigned int isReady  : 1;
    unsigned int hasError : 1;
    unsigned int isActive : 1;
};
```

实测：

```text
struct FlagsPlain 占 12 字节（3 个 unsigned int）
struct FlagsBit   占  4 字节（3 个 1 位字段）
用 unsigned char 作位域类型：1 字节
```

> ⭐ **为什么是 4 而不是 1？**
> 位域的类型是 `unsigned int`，编译器按 `int` 分配存储单元，剩下的位空着。
> 想真的压到 1 字节，必须写 `unsigned char a : 1;`。

### 位域的五条规则

| 规则 | 说明 |
|---|---|
| 位数决定范围 | 无符号 n 位：0 ~ 2ⁿ-1；有符号 n 位：-2ⁿ⁻¹ ~ 2ⁿ⁻¹-1 |
| 超范围赋值 | 被截断，gcc 给 `-Woverflow` 警告（是警告不是错误） |
| 不能取地址 | `&f.isReady` 编译错误，因为不是字节对齐 |
| 不能整体初始化 | 用 `memset` 清零，别试图 `= {1,0,1}` |
| 布局由实现定义 | 不同编译器可能从低位排也可能从高位 |

### 超范围赋值的实测

```c
struct Range { unsigned int a : 3; signed int b : 3; };

r.a = 7;   /* 最大值 */
r.a = 8;   /* → 0，低 3 位是 000 */
r.a = 15;  /* → 7，低 3 位是 111 */

r.b = 3;   /* 最大值 */
r.b = 4;   /* → -4，3 位有符号，100 就是 -4 */
```

gcc 会警告：

```text
warning: unsigned conversion from 'int' to 'unsigned char:3'
         changes value from '8' to '0' [-Woverflow]
```

> ⚠️ **注意警告里写的是 `unsigned char:3`** —— 不是因为声明错，而是 gcc 内部把 3 位的位域按最小可用单元处理。这属于实现细节，不用深究。

### 位域 vs 位运算

| | 位域 | 位运算 |
|---|---|---|
| 可读性 | 好（`f.isReady`） | 差（`x & 0x01`） |
| 可移植性 | **差**（布局由编译器定） | 好 |
| 取地址 | 不能 | 能 |
| 适合 | 内部状态、寄存器定义 | **协议解析**、跨平台 |

> ⭐ **位域绝对不能用来解析网络协议。** 布局没标准，换个编译器读出来的就是乱数据。
> 那种场合必须手写位运算。

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 位运算结果 | `5 & 3`、`5 \| 2`、`~5`、`-1 >> 1` | 转二进制手算 |
| 移位 | `1 << 4`、`x >> 2` | 左移乘 2、右移除 2 |
| 判奇偶 | 用位运算怎么写 | `x & 1` |
| 清位 | 把第 n 位清 0 | `&= ~(1 << n)` |
| 位域大小 | `struct { unsigned a:1; b:1; }` | 按类型分配，不是 1 字节 |
| 位域取地址 | 能不能 `&` | 不能 |

> 📌 位运算在选择题里通常 1–2 分，但**算法题里可能用到位运算优化**（比如判断 2 的幂）。
> 公式记住四个就够，不必背整张优先级表。
