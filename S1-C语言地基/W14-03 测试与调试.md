## 三、五个真实踩过的坑

### 坑 1：`scanf` 失败导致菜单死循环

**现象**：输入 `abc`，程序疯狂刷菜单，停不下来。

**原因**：`scanf("%d")` 读到 `a` 就失败返回 0，`abc` 留在缓冲区。下一轮又读到同一个 `a`，又失败……无限循环。

**修复**：

```c
if (scanf("%d", &choice) != 1) {
    clearInput();               /* 把这行垃圾吃掉 */
    printf("无效输入\n");
    continue;
}
```

实测修复后输出：

```text
请选择：  无效输入，请输入 0-9
```

然后正常继续，不卡死。

> ⭐ **这是新手写菜单程序最常见的崩点。** 一定要有清缓冲区的函数。

### 坑 2：`g_count` 忘了减 1

**现象**：删了一个学生，列表里最后一行重复出现两次。

**原因**：元素前移做对了，但 `g_count` 没减，最后那个「重复的旧数据」还在有效范围内。

**修复**：

```c
for (int i = idx; i < g_count - 1; i++) g_stu[i] = g_stu[i + 1];
g_count--;                       /* ← 漏了这行 */
```

### 坑 3：删除循环边界写错

```c
for (int i = idx; i < g_count; i++)      /* ❌ */
    g_stu[i] = g_stu[i + 1];
```

最后一次 `i = g_count - 1` 时，执行 `g_stu[g_count-1] = g_stu[g_count]`，把**数组里没意义的旧数据**搬进了有效区。

正确：

```c
for (int i = idx; i < g_count - 1; i++)  /* ✅ */
```

> ⚠️ 这个错**不会崩溃**，也不会警告，只会让最后一条数据变得莫名其妙。
> 属于「最难查」那类 bug。

### 坑 4：中文列不对齐

**现象**：

```text
学号   姓名       成绩   状态
1002     李四       92.0     及格
```

**原因**：`printf("%-12s")` 的宽度按**字节**算。`"姓名"` 在 UTF-8 里是 6 字节，`%-12s` 只补 6 个空格，但显示上「姓名」只占 2 个汉字宽。

**不是 bug，是设计如此。** 知道原因就行，软考数据都是英文，不受影响。

### 坑 5：学号没查重

**现象**：添加两个 1001，之后查找永远只返回第一个，删除也只删第一个。

**修复**：

```c
if (findById(id) >= 0) {
    printf("学号 %d 已存在\n", id);
    return;
}
```

> ⭐ 「唯一键」这个概念在数据库里叫主键。这里是它的手写版本。

## 四、调试方法：三种最实用的

### ① 打印中间状态

最土但最有效。在可疑位置插：

```c
printf("[调试] idx=%d g_count=%d\n", idx, g_count);
```

> ⚠️ 调试完记得删。留着会污染输出。

### ② 用 `-Wall -Wextra` 编译

```bash
gcc -std=c17 -Wall -Wextra -o student student.c
```

本项目编译**零警告**。如果有警告，先解决再运行 —— 警告往往就是 bug 的线索。

### ③ 小数据量手算对照

4 个学生的排序、删除、统计，**自己先用纸算一遍**，再看程序输出是否一致。

> ⭐ 这比盯着代码看有效得多。程序不会撒谎，你的预期可能会错 —— 一对照就知道是谁错。
