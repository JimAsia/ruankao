# W14-02 核心功能实现

> 五个功能是重点：**增、删、查、排、统**。
> 这五个写熟了，换任何题目（图书管理、工资管理、库存管理）都是换字段名而已。

---

## 一、添加：三个校验 + 三次赋值

```c
static void addStudent(void)
{
    if (g_count >= MAXN) { printf("人数已满\n"); return; }

    int id;
    if (!readInt("学号：", &id)) return;

    if (findById(id) >= 0) { printf("学号已存在\n"); return; }

    char name[NAMELEN];
    printf("姓名：");
    if (scanf("%19s", name) != 1) { clearInput(); return; }

    double score;
    if (!readScore("成绩：", &score)) return;

    g_stu[g_count].id    = id;
    strcpy(g_stu[g_count].name, name);   /* ⚠️ 不能 = 赋值 */
    g_stu[g_count].score = score;
    g_count++;                            /* ⚠️ 别忘了加 */
}
```

### 三个易错点

| 错误 | 后果 |
|---|---|
| `g_stu[g_count].name = name` | 编译错误，数组不能赋值 |
| 忘了 `g_count++` | 新数据被下一条覆盖 |
| 没查重 | 出现两个相同学号 |

> ⭐ **`g_count` 的双重身份**：它既是「当前人数」，也是「下一个空位的下标」。
> 所以新元素**永远放在 `g_stu[g_count]`**，加完再 `g_count++`。

## 二、查找：一个函数，三处复用

```c
static int findById(int id)
{
    for (int i = 0; i < g_count; i++)
        if (g_stu[i].id == id) return i;
    return -1;
}
```

查找、修改、删除三个功能都靠它：

```c
int idx = findById(id);
if (idx < 0) { printf("未找到\n"); return; }
g_stu[idx].score = newScore;      /* 修改 */
```

> ⭐ **返回下标而不是返回值**，因为后面还要用姓名、成绩。
> 这个设计在 W11 求最值时已经用过（存下标不存值）。

### 能不能更快？二分查找

如果数组**已按学号排序**，可以用二分，O(log n)。但每次增删都要维持有序，代价更高。

> 📌 软考应用题默认用**顺序查找**（线性查找），代码简单、不用维护有序。
> 只有题目明确说「已按学号升序排列」时才用二分。

## 三、排序：冒泡 + 提前退出

```c
for (int i = 0; i < g_count - 1; i++) {
    int swapped = 0;
    for (int j = 0; j < g_count - 1 - i; j++) {
        if (g_stu[j].score < g_stu[j + 1].score) {
            Student t    = g_stu[j];      /* 整体交换 */
            g_stu[j]     = g_stu[j + 1];
            g_stu[j + 1] = t;
            swapped = 1;
        }
    }
    if (!swapped) break;                  /* 已有序，提前结束 */
}
```

### 为什么用 `Student t` 而不是逐字段

```c
/* ❌ 逐字段：字段一多必漏 */
int  ti = g_stu[j].id;
char tn[20]; strcpy(tn, g_stu[j].name);
double ts = g_stu[j].score;
/* ... 还没写完就容易错 */
```

```c
/* ✅ 整体赋值：结构体支持，一句顶十句 */
Student t = g_stu[j];
```

> ⭐ **结构体可以整体赋值，数组不行。** 这是 W11 强调过的区别，在这里体现得最直接。

### 实测的交换次数

4 个人按成绩降序：`85 92 55 78` → 排序后 `92 85 78 55`，**交换 2 次**。

> 📌 冒泡的总比较次数固定是 `n(n-1)/2`，但交换次数取决于数据。
> 软考问「最坏情况交换几次」时，答 `n(n-1)/2`。

## 四、删除：元素前移

```c
int idx = findById(id);
/* 从 idx 开始，后面的元素逐个前移一格 */
for (int i = idx; i < g_count - 1; i++) {
    g_stu[i] = g_stu[i + 1];
}
g_count--;                       /* ⚠️ 长度必须减 1 */
```

### 三步图解

删除下标 1（李四）：

```text
原：  [0]张三  [1]李四  [2]王五  [3]赵六       count = 4
      i=1: g_stu[1] = g_stu[2]  → 王五搬过来
      [0]张三  [1]王五  [2]王五  [3]赵六
      i=2: g_stu[2] = g_stu[3]  → 赵六搬过来
      [0]张三  [1]王五  [2]赵六  [3]赵六
      count = 3
结果：[0]张三  [1]王五  [2]赵六              ← 前 3 个有效
```

### 三个易错点

| 错误 | 后果 |
|---|---|
| 循环写成 `i < g_count` | `g_stu[g_count - 1] = g_stu[g_count]` 读到**未初始化数据** |
| 忘了 `g_count--` | 最后一个元素被重复显示 |
| 想「清零」被删位置 | 没必要，`g_count` 之外的数据不参与任何操作 |

> ⚠️ **边界必须写 `i < g_count - 1`。**
> 如果写 `i < g_count`，最后一次会访问 `g_stu[g_count]` —— 那是数组的有效内存（容量 100），但里面是**没意义的旧数据**，会被搬进来。

### 另一种写法：从后往前

```c
for (int i = idx; i < g_count - 1; i++) g_stu[i] = g_stu[i + 1];
```

与

```c
for (int i = g_count - 1; i > idx; i--) g_stu[i - 1] = g_stu[i];
```

两种都对。**推荐第一种**（从前往后），因为它和「插入要从后往前」形成对照，不容易记混。

| 操作 | 方向 | 原因 |
|---|---|---|
| 删除 | 从前往后 | 目标位置是空的，可以直接覆盖 |
| 插入 | **从后往前** | 目标位置有数据，必须先腾地方 |

## 五、统计：一次遍历算完所有指标

```c
double sum = 0.0;
int maxIdx = 0, minIdx = 0, passCnt = 0;
int buckets[5] = {0};

for (int i = 0; i < g_count; i++) {
    sum += g_stu[i].score;

    if (g_stu[i].score > g_stu[maxIdx].score) maxIdx = i;
    if (g_stu[i].score < g_stu[minIdx].score) minIdx = i;

    if (g_stu[i].score >= 60.0) passCnt++;

    int s = (int)g_stu[i].score;
    if      (s >= 90) buckets[0]++;
    else if (s >= 80) buckets[1]++;
    else if (s >= 70) buckets[2]++;
    else if (s >= 60) buckets[3]++;
    else              buckets[4]++;
}
```

实测输出：

```text
  人数    ：4
  总分    ：310.0
  平均分  ：77.50
  最高分  ：李四 92.0
  最低分  ：王五 55.0
  及格人数：3 / 4（及格率 75.0%）
  90 以上 1 人  ★
  80-89    1 人  ★
  70-79    1 人  ★
  60-69    0 人
  60 以下 1 人  ★
```

数据核对：`85 + 92 + 55 + 78 = 310`，平均 `77.5`，及格 3 人（85/92/78）。

### 三个设计要点

**① 一趟循环算完所有指标。** 不要写五个循环分别求 sum、max、min…… 一遍 O(n) 比五遍 O(5n) 好。

**② 最值存下标。** 因为输出时要打印「李四 92.0」，只存数值拿不到名字。

**③ 计数数组代替五个变量。**

```c
int buckets[5] = {0};                     /* ✅ */
/* int c90=0, c80=0, c70=0, c60=0, c0=0;  ❌ 加一档改五处 */
```

## 六、文件保存与加载

```c
/* 保存 */
for (int i = 0; i < g_count; i++) {
    fprintf(fp, "%d %s %.1f\n", g_stu[i].id, g_stu[i].name, g_stu[i].score);
}

/* 加载 */
int n = 0;
Student s;
while (n < MAXN && fscanf(fp, "%d %19s %lf", &s.id, s.name, &s.score) == 3) {
    g_stu[n++] = s;
}
g_count = n;
```

> ⚠️ **加载时的 `n < MAXN` 不能省。** 别人给的文件可能有 500 条，不判断就写爆数组。
> 这个「双条件循环」是防御式编程的典型写法。

实测：保存后再启动程序，自动加载 2 条记录，数据完全一致。

## 七、中文对齐的问题（真实踩坑）

用 `printf("%-12s", "姓名")` 输出中文时，列会错位。

原因：**`printf` 的宽度按「字节」算，不是按「显示宽度」算。**

```text
"姓名" 在 UTF-8 里是 6 字节，但只占 2 个汉字宽度
%-12s 补 6 个空格 → 实际看起来比预期窄
```

实测输出（能看到错位）：

```text
学号   姓名       成绩   状态
1002     李四       92.0     及格
```

**解决办法**（按需选）：

| 方案 | 做法 |
|---|---|
| 简单 | 不用 `%-Ns`，改用 `\t` 或固定字符串（本项目部分用了固定宽度） |
| 精确 | 自己算「显示宽度」：中文按 2、ASCII 按 1，手动补空格 |
| 最省事 | 数据全用英文/数字，中文只做标签 |

> 📌 软考不考这个细节（题目数据都是英文），但**你自己写程序时会遇到**。
> 知道「宽度是字节数」这个事实就够了，别以为是 `printf` 有 bug。
