## 一、位运算：直接操作二进制

位运算只对**整数**有效（`float` 不行），因为它操作的是内存里那串 0/1。

| 运算符 | 名称 | 规则 | 12 `&` 10 |
|---|---|---|---|
| `&` | 按位与 | 两位都是 1 才得 1 | `1100 & 1010 = 1000` = 8 |
| `\|` | 按位或 | 有一位是 1 就得 1 | `1100 \| 1010 = 1110` = 14 |
| `^` | 按位异或 | 两位不同才得 1 | `1100 ^ 1010 = 0110` = 6 |
| `~` | 按位取反 | 0 变 1，1 变 0 | `~12` = -13（按有符号读） |

**真实运行 `14_bitwise.c` 的对照输出：**

```text
        1100
      & 1010
      ------
        1000 = 8

        1100
      | 1010
      ------
        1110 = 14

        1100
      ^ 1010
      ------
        0110 = 6
```

### 1.1 异或的两个特殊性质（软考爱考）

```text
n ^ n = 0      任何数异或自己得 0
n ^ 0 = n      任何数异或 0 得自己
```

推论：`a ^ b ^ b = a`。这个性质可以用来做「找出唯一出现一次的数」这类题，也可以不用临时变量交换两个数：

```c
a ^= b;
b ^= a;
a ^= b;         /* 交换完成，同样有溢出风险，工程上不推荐 */
```

### 1.2 移位：左移乘 2，右移除 2

| 写法 | 结果 | 含义 |
|---|---|---|
| `1u << 4` | 16 | 左移 4 位 = 乘 2⁴ |
| `3u << 2` | 12 | 左移 2 位 = 乘 4 |
| `32u >> 3` | 4 | 右移 3 位 = 除以 8 |
| `35u >> 3` | 4 | 右移是**向下取整**，余下的低位直接丢掉 |

> ⚠️ **移位的大坑**：对 32 位 `int` 写 `1 << 32` 是未定义行为，标准没规定结果。安全范围是移动 `0 ~ 31` 位。
> 另外：负数右移的行为由实现定义（算术右移补 1 还是逻辑右移补 0），考试不会考。

### 1.3 三个必须会的套路

```text
n & 1          取最低位       → 1 是奇数，0 是偶数
n | (1 << k)   把第 k 位置 1
n & ~(1 << k)  把第 k 位清零
```

`14_bitwise.c` 的真实输出（n = 7）：

```text
n & 1        = 1    最低位是 1 → 奇数
n | 8        = 15   把第 3 位置 1（7 变 15）
n & ~1       = 6    把最低位清零（7 变 6，即变成偶数）
```

> 💡 为什么 `n & ~1` 能变偶数？`~1` 是 `...11111110`，除了最低位是 0 其余全是 1，与 n 相与就把最低位抹掉了。

## 二、类型转换

### 2.1 隐式转换：编译器自动做的

**规则一：小类型自动提升到大类型（安全）**

```text
char → short → int → unsigned int → long long → float → double
```

```c
5 + 2.0       /* 5 先变成 5.0，结果是 7.0 */
'A' + 1       /* 'A' 变 65，结果是 66 */
```

**规则二：赋值时，右边转成左边的类型**

```c
int  n = 3.9;         /* n = 3，小数部分被截断 */
char c = 300;         /* 超出 char 范围，结果不确定（实现定义） */
```

**规则三：有符号和无符号混算，有符号转成无符号**（坑）

```c
int a = -1;
unsigned int b = 1;
a > b                 /* ❌ 结果是 1（真）！ */
```

原因：`a` 被转成无符号，-1 的补码是全 1，按无符号读就是 4294967295，当然大于 1。

> 📌 这条软考考过。看到「有符号数与无符号数比较」，条件反射想到这个坑。

实测（`-1 > 1u`）编译器会警告：

```text
warning: comparison of integer expressions of different signedness:
         'int' and 'unsigned int' [-Wsign-compare]
```

警告出现了就别写这行代码 —— 这就是 `-Wall` 的价值：它替你记住了这条规则。

### 2.2 强制转换：你主动要求的

```c
(类型)表达式
```

```c
(double)a / b       /* 把 a 临时当 double 用 */
(int)3.9            /* 3，截断，不是四舍五入 */
(int)-3.9           /* -3，向零截断，不是 -4 */
```

> ✅ 强制转换只改变**这一次运算**的解读方式，不改变变量本身的类型。下一句 `a` 还是 `int`。

### 2.3 截断与溢出

| 情况 | 结果 |
|---|---|
| 浮点 → 整数 | 截断小数部分（向零），不是四舍五入 |
| 大类型 → 小类型 | 高位被丢弃，值可能完全变了 |
| 有符号整数溢出 | **未定义行为**，通常回绕成负数 |
| 无符号整数溢出 | 明确定义：对 2ⁿ 取模回绕 |

```c
int max = 2147483647;
max + 1              /* ❌ 溢出，未定义行为，通常变成 -2147483648 */

unsigned char c = 200;
c + 100              /* 300 % 256 = 44，无符号溢出有明确定义 */
```

> 💡 算法题里如果数据接近 21 亿，就要考虑用 `long long`。这是应用题常见的送分/失分点。
