# W17-01 单链表的建立与遍历

> 顺序表的痛点是「插入删除要挪元素」。链表用指针把节点串起来，插入删除只改指针。
> 代价是不能随机访问 —— **这就是两种结构互补的根源。**

---

## 一、节点：数据域 + 指针域

```c
typedef struct Node {
    int          data;      /* 数据域 */
    struct Node *next;      /* 指针域：指向下一个节点 */
} Node;
```

> ⚠️ **`next` 的类型必须是 `struct Node *`，不能写 `Node *`。**
> 因为在结构体内部，`Node` 这个别名还没定义完（typedef 还没生效）。
> 这是 C 语言里一个必须记住的细节。

节点在内存里是**分散的**：

```text
顺序表：[10][20][30][40]     连续内存，地址 +4 就是下一个
链表：  [10|•]→[20|•]→[30|•]→[40|NULL]
        0x100   0x5A0   0x2C8   0x7F0    地址随便，靠指针串
```

---

## 二、头结点（dummy head）为什么有用

```c
typedef struct {
    Node *head;         /* 永远指向头结点 */
    int   length;       /* 元素个数（不含头结点） */
} LinkedList;
```

头结点**不存数据**，只是为了统一操作。

### 不带头结点的麻烦

```c
/* 删除第一个元素时，要改 head 本身 */
if (pos == 0) {
    Node *victim = head;
    head = head->next;      /* 必须改头指针 */
    free(victim);
} else {
    /* 其他位置：改前驱的 next */
    prev->next = victim->next;
}
```

到处是 `if (p == head)` 的特判。

### 带头结点之后就统一了

```text
head → [dummy] → [10] → [20] → [30] → NULL
```

第一个真元素的**前驱就是头结点**，所以：

```c
prev->next = victim->next;      /* 所有位置都一样，不用特判 */
```

> ⭐ 软考题里如果画了头结点，插入删除都按「有前驱」处理。
> 如果没画头结点，删除第一个元素要单独处理。

---

## 三、头插法 vs 尾插法

### 头插法：顺序相反

```c
Node *n = malloc(sizeof(Node));
n->data = value;
n->next = L->head->next;        /* ① 新节点接上原来的第一个 */
L->head->next = n;              /* ② 头结点改指新节点 */
```

实测（输入 10 20 30 40 50）：

```text
50 -> 40 -> 30 -> 20 -> 10 -> NULL
```

> ⚠️ **两句顺序不能反。**
> 写反了变成 `head->next = n; n->next = head->next;`，
> 此时 `head->next` 已经是 `n` 自己，`n->next` 指向自己 → **自环，遍历死循环**。

### 尾插法：顺序一致

```c
Node *p = L->head;
while (p->next != NULL) p = p->next;    /* 走到尾节点 */
p->next = n;
```

实测：`10 -> 20 -> 30 -> 40 -> 50 -> NULL`

> ⚠️ 尾插每次都要走一遍找尾，**建 n 个节点就是 O(n²)**。
> 工程上会维护一个 `tail` 指针，让它变 O(n)（W17-03 的拆分题会用到）。

### 两种建法的用途

| 建法 | 结果顺序 | 用途 |
|---|---|---|
| 尾插 | 与输入一致 | 正常建表（最常用） |
| 头插 | 与输入相反 | **逆序建表**，或用来逆置链表 |

---

## 四、遍历：链表唯一能做的事

```c
for (Node *p = L->head->next; p != NULL; p = p->next) {
    /* 处理 p->data */
}
```

> ⚠️ 起点是 `L->head->next`（跳过 dummy），不是 `L->head`。
> 终点判断是 `p != NULL`，不是 `p->next != NULL`（后者会漏掉最后一个）。

---

## 五、不能随机访问：链表最大的缺点

```c
/* 顺序表：一步到位 */
int v = L.data[500];            /* O(1) */

/* 链表：必须走 500 步 */
Node *p = head->next;
for (int i = 0; i < 500; i++) p = p->next;   /* O(n) */
```

### 为什么

顺序表的元素地址是**连续**的，`a[500]` 的地址 = 首地址 + 500×4，一次乘法搞定。

链表的节点地址**分散**，只能靠 `next` 一个个跳 —— 你不知道第 500 个在哪，只能从第一个开始数。

> ⭐ 这就是「**顺序存储支持随机访问，链式存储只支持顺序访问**」的含义。
> 软考选择题常直接考这句话。

## 六、求长度的两种方式

```c
int lengthByField(const LinkedList *L) { return L->length; }    /* O(1) */

int lengthByWalk(const LinkedList *L) {
    int n = 0;
    for (Node *p = L->head->next; p; p = p->next) n++;
    return n;                                                    /* O(n) */
}
```

> 📌 维护 `length` 字段就是 O(1)，不维护就是 O(n)。
> 工程上都维护，但**软考题如果没给 length 字段，就按 O(n) 算**。

## 七、内存管理：每个 malloc 都要 free

```c
void listDestroy(LinkedList *L)
{
    Node *p = L->head;
    while (p != NULL) {
        Node *next = p->next;       /* ⚠️ 先存后继 */
        free(p);
        p = next;
    }
    free(L);
}
```

> ⚠️ **`Node *next = p->next;` 这句不能省。**
> `free(p)` 之后 `p->next` 就是访问已释放的内存（未定义行为），
> 大多数情况下能跑，但偶尔会崩 —— 这种 bug 极难查。

## 八、顺序表 vs 链表：背诵这张表

| 对比项 | 顺序表 | 链表 |
|---|---|---|
| 存储方式 | 连续内存 | 分散 + 指针 |
| 按位置访问 | **O(1) 随机访问** | O(n) 要走 |
| 按值查找 | O(n) | O(n) |
| 插入删除 | O(n) 要挪元素 | **O(1) 只改指针\*** |
| 额外空间 | 无 | 每节点 1 个指针 |
| 长度 | 固定（或要扩容） | 动态 |
| 缓存友好 | 好（连续） | 差（跳着访问） |

> **\* 关键前提：链表的 O(1) 插入删除，前提是「已经拿到那个位置的指针」。**
> 如果只知道值、要先查找，整体还是 O(n)。**这个前提软考常考。**

### 一句话总结

```text
顺序表「查快改慢」，链表「查慢改快」。
需要频繁随机访问 → 数组
需要频繁插入删除 → 链表
```

## 九、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 节点定义 | `next` 的类型怎么写 | `struct Node *` |
| 头结点 | 有什么好处 | 统一第一个节点的操作 |
| 头插 | 建表后的顺序 | 与输入**相反** |
| 随机访问 | 链表能不能 `L[i]` | 不能，只能顺序访问 |
| 求长度 | 没 length 字段时 | O(n) |
| 插入删除 | 真的都是 O(1) 吗 | 前提是已知前驱指针 |
| 存储密度 | 哪个更高 | 顺序表（链表要多存指针） |

> 📌 「存储密度」= 数据占用 / 总占用。顺序表接近 1，链表 < 1。
