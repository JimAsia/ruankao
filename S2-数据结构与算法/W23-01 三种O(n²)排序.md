# W23-01 三种 O(n²) 排序

> 插入、冒泡、选择 —— 三个最基础的排序。
> 它们复杂度都是 O(n²)，但**细节差别正是选择题的考点**：
> 谁能提前结束、谁与数据无关、谁稳定。

---

## 一、直接插入排序：像整理扑克牌

```c
for (int i = 1; i < n; i++) {
    int key = a[i];             /* 抓一张新牌 */
    int j = i - 1;
    while (j >= 0 && a[j] > key) {   /* 比它大的都往后挪 */
        a[j + 1] = a[j];
        j--;
    }
    a[j + 1] = key;             /* 插到空出来的位置 */
}
```

### 实测（`231_basic_sorts.c`）

```text
乱序：插入 比较 20  移动 22
```

对比冒泡 27/45、选择 28/21 —— 插入排序在乱序数据上**比较次数最少**。

### 关键：已有序时退化成 O(n)

```text
已排序数据：插入 比较 7  移动 7
            冒泡 比较 7  移动 0
            选择 比较 28 移动 0    ← 与数据无关！
```

> ⭐ 插入排序的 `while` 里有 `break` 的等价逻辑（条件不满足就退出），
> 所以数据有序时每个元素只比较 1 次，总共 n-1 次。

### 一趟后的效果

**前 i+1 个元素局部有序**（但不一定在最终位置）。

> ⚠️ 「局部有序」≠「最终位置」。后面的元素插进来时，前面的还会被挤动。

---

## 二、冒泡排序：相邻比较，大的往后浮

```c
for (int i = 0; i < n - 1; i++) {
    int swapped = 0;
    for (int j = 0; j < n - 1 - i; j++) {
        if (a[j] > a[j + 1]) {
            交换;
            swapped = 1;
        }
    }
    if (!swapped) break;        /* 本趟无交换 → 已有序，提前结束 */
}
```

### 实测：优化前后的差距

```text
已排序数据：
  带提前退出：比较 7 次
  不带优化  ：比较 28 次
```

**差 4 倍。** 因为无优化版本不管数据怎样都跑满 n-1 趟。

### 一趟后的效果

**最大的元素到了末尾**（或最小的到了最前，取决于冒泡方向）。

> 每趟把当前最大的「浮」到末尾，所以第 i 趟后，最后 i 个元素已就位。

---

## 三、选择排序：每轮选最小，放前面

```c
for (int i = 0; i < n - 1; i++) {
    int minIdx = i;
    for (int j = i + 1; j < n; j++) {
        if (a[j] < a[minIdx]) minIdx = j;
    }
    if (minIdx != i) 交换;
}
```

### 实测：三种数据的比较次数完全一样

```text
乱序     比较 28  交换 7
已有序   比较 28  交换 0
完全逆序 比较 28  交换 3
```

> ⭐ **比较次数恒为 n(n-1)/2 = 28，与数据完全无关。**
> 因为不管数据怎样，都要扫完才能确定最小值在哪。

### 这是它和插入/冒泡的最大区别

| 排序 | 最好情况 | 是否受数据影响 |
|---|---|---|
| 插入 | **O(n)** | 大 |
| 冒泡 | **O(n)** | 大 |
| 选择 | **O(n²)** | **无** |

### 交换次数最少

**最多 n-1 次交换** —— 三者里最少的。

> ⭐ 所以「交换（写）代价高」时选选择排序，比如写闪存、写磁盘。
> 📌 软考原题：「要求交换次数最少，选哪个排序」→ **选择排序**。

---

## 四、三者对比（这张表要背）

| 排序 | 最好 | 最坏 | 空间 | 稳定性 | 一趟后 |
|---|---|---|---|---|---|
| 直接插入 | **O(n)** | O(n²) | O(1) | **稳定** | 前 i 个局部有序 |
| 冒泡 | **O(n)** | O(n²) | O(1) | **稳定** | 最大到最后 |
| 选择 | O(n²) | O(n²) | O(1) | **不稳定** | 最小到最前 |

---

## 五、稳定性：为什么选择排序不稳定

### 定义

**稳定**：排序后，相同值的元素保持原来的相对顺序。

### 选择排序的反例（实测）

```text
数据：[2#0, 2#1, 1#2, 3#3]      （#0 #1 是原始下标）

第 1 轮：找最小值 1（下标 2），和 a[0] 交换
     [2#0, 2#1, 1#2, 3#3]
       ↑___________↑
     → [1#2, 2#1, 2#0, 3#3]

⚠️ 2#0 被丢到了 2#1 后面 → 相对顺序反转
```

> ⭐ **根源：选择排序的交换是「远距离」的，会跨越中间所有元素。**
>
> 而插入、冒泡只和**相邻元素**打交道，不会跨过相等元素。

### 一个必须注意的细节

插入和冒泡用的是**严格大于**（`>`），不是 `>=`：

```c
while (j >= 0 && a[j] > key)     /* ✅ 稳定 */
while (j >= 0 && a[j] >= key)    /* ❌ 相等时也交换 → 不稳定 */
```

> 📌 这个符号是软考改错题的高频点。

## 六、一趟后的结果怎么判断是哪种排序

软考常给「第一趟后的结果」，问是哪种排序。看**这趟确定了什么**：

| 现象 | 对应排序 |
|---|---|
| 最大值到了末尾 | 冒泡 |
| 最小值到了最前 | 选择 |
| 前 i 个局部有序 | 插入 |
| 某个元素左边全小、右边全大 | 快速 |

> ⭐ 这是最快的判断法。看到「最小值在第一位」就想选择排序，
> 看到「最大值在最后一位」就想冒泡。

---

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 比较次数 | 哪个与数据无关 | **选择排序** |
| 最好情况 | 哪个能到 O(n) | 插入、冒泡 |
| 交换次数 | 哪个最少 | 选择排序（≤ n-1） |
| 稳定性 | 哪个不稳定 | 选择排序 |
| 一趟判断 | 给结果问是哪种 | 看确定了什么 |
| 适用 | n 小或基本有序用什么 | 插入排序 |
