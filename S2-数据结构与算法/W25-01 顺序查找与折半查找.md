# W25-01 顺序查找与折半查找

> 查找这一章的核心只有一个指标：**ASL（平均查找长度）**。
> 考试不问你「能不能找到」，而是问「平均要比几次」。
> 所有公式都能从一张表数出来，不用背。

---

## 一、先定义清楚 ASL

$$
ASL = \sum_{i=1}^{n} p_i \cdot c_i
$$

- `p_i`：查第 i 个元素的概率（题目不说就按等概率 `1/n`）
- `c_i`：找到第 i 个元素需要的**比较次数**

等概率时就退化成最简单的形式：

```text
ASL = (c1 + c2 + ... + cn) / n
```

> ⭐ **ASL 分两种**：查找**成功**的 ASL、查找**失败**的 ASL。
> 题目如果不说明，默认问成功的那个；但只要出现「失败」「不成功」，就要另算。

---

## 二、顺序查找

### 2.1 普通写法

```c
for (int i = 0; i < n; i++) {
    if (a[i] == key) return i;
}
return -1;
```

比较次数：第 i 个元素（从 0 数）要比较 `i+1` 次。
`ASL(成功) = (1+2+...+n)/n = (n+1)/2`。

### 2.2 哨兵写法：少判断一次

```c
a[0] = key;                 /* 哨兵 */
int i = n;
while (a[i] != key) i--;    /* 只比值，不判 i >= 0 */
return (i == 0) ? 0 : i;
```

为什么快：普通版每轮要判**两个**条件（`i < n` 和 `a[i] == key`），哨兵版只判**一个**。
因为 `a[0]` 一定等于 key，循环必然停，不可能越界。

> 这是「用一点空间换判断次数」的经典手法，软考常在**程序填空**里考这一句。

### 2.3 实测（n = 11）

`code/w25/251_sequential_binary.c` 的输出：

```text
下标   值        比较次数
11       96         1
10       84         2
...
1        8          11
总比较次数 = 66，ASL(成功) = 66/11 = 6.00
公式 (n+1)/2 = (11+1)/2 = 6.00  ✓ 完全相等
查一个不存在的 100：比较 12 次 = n+1（含哨兵那一次）
```

> **注意失败的口径**：带哨兵是 `n+1`（哨兵本身也比了一次），不带哨兵是 `n`。
> 两种答案教材里都出现过，看清题目给的代码。

### 2.4 优缺点

| | 说明 |
|---|---|
| 优点 | 对表**没有任何要求**：无序可以、链式存储也可以 |
| 缺点 | O(n)，n 大时太慢 |
| 时间复杂度 | O(n) |
| 适用 | 表小、或查找次数很少、或必须用链表 |

## 三、折半查找（二分查找）

### 3.1 两个硬前提

1. **必须有序**（升序或降序）
2. **必须顺序存储**（数组）

> 第 2 条经常被忽略：**链表不能折半**。因为链表找中间节点要 O(n)，
> 折半的 `O(1)` 取中间这个前提直接崩了。

### 3.2 代码

```c
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == key) return mid;
    if (a[mid] < key) lo = mid + 1;
    else              hi = mid - 1;
}
return -1;
```

三个必须记准的细节：

| 细节 | 正确写法 | 写错的后果 |
|---|---|---|
| 循环条件 | `lo <= hi` | 写 `<` 会漏掉最后一个元素 |
| mid 计算 | `lo + (hi-lo)/2` | `(lo+hi)/2` 在 lo、hi 很大时溢出 |
| 区间收缩 | `mid+1` / `mid-1` | 写成 `mid` 会死循环 |

### 3.3 判定树：ASL 的来源

把「每次比较的 mid」画成二叉树，就是**判定树**：

- 每个元素是**内部节点**
- 每个空隙（失败位置）是**外部节点**（叶子下的空指针）
- **比较次数 = 该节点在树上的层数**

n = 11 的判定树（存的是下标）：

```text
                 5
            /         \
           2           8
         /   \       /   \
        0     3     6     9
         \     \     \     \
          1     4     7     10
```

数一数各层：

| 层 | 节点数 | 理论最多 |
|---|---|---|
| 1 | 1 | 1 |
| 2 | 2 | 2 |
| 3 | 4 | 4 |
| 4 | 4 | 8 |

```text
ASL(成功) = (1*1 + 2*2 + 4*3 + 4*4) / 11 = 33/11 = 3.00
```

### 3.4 两个必背结论

**结论 1：判定树的高度**

```text
h = ⌈log2(n+1)⌉     或等价的  ⌊log2 n⌋ + 1
```

n=11 时 `⌈log2 12⌉ = 4`，与上图一致。**这就是「最多比较 4 次」的出处。**

**结论 2：ASL 的近似公式**

满二叉树（n = 2^h − 1）时精确成立：

```text
ASL = ((n+1)/n) · log2(n+1) − 1
```

n = 15 时代入：`(16/15)×4 − 1 = 49/15 ≈ 3.267`
实测也是 49/15 —— **一分不差**（见 `ex252` 的输出）。

n 不是 2^h−1 时这个公式只是近似。n=11 时公式给 2.91，实测 3.00，
差的那 0.09 来自「最后一层只有 4 个节点、没填满」。

> ⭐ **考试策略**：题目给了具体 n 和具体表，就**画判定树数层数**，最稳。
> 只问量级时才用 O(log n)。

### 3.5 失败的情况

n = 11 有 **12 个空隙**（n+1 个外部节点）。实测：

```text
总比较次数 = 44，ASL(失败) = 44/12 = 3.6667
```

失败时比较次数 = 外部节点的**父节点层数 + 1**，因为最后还要比一次才确认「不在」。

## 四、软考怎么考

### 考法 1：算 ASL（选择题，最高频）

> 对长度为 12 的有序表进行折半查找，查找成功时的平均查找长度约为？

做法：画判定树 → 数各层 → `Σ(层×个数)/n`。**别套公式，直接数。**

### 考法 2：判定树的高度 / 最多比较次数

> 长度为 1000 的有序表折半查找，最多比较多少次？

`⌈log2(1001)⌉ = 10`。这类题答案就是 `⌈log2(n+1)⌉`。

### 考法 3：判断「能不能用折半」

> 下列哪种结构适合折半查找？
> A. 无序数组  B. 有序单链表  C. 有序顺序表  D. 二叉链表

答案 C。**有序 + 顺序存储，两个条件缺一不可。**

### 考法 4：程序填空

折半的 `while (low <= high)`、`mid = (low+high)/2`、`high = mid - 1`
这三个空几乎年年出现。哨兵版常考「循环条件只写 `a[i] != key`」。

### 考法 5：比较次数与 n 的关系

> 顺序查找平均 (n+1)/2，折半查找平均约 log2(n+1)−1。

记住这条**量级差**：n=1000 时顺序平均 500 次，折半约 9 次，差 50 多倍。

## 五、一张表收尾

| | 顺序查找 | 折半查找 |
|---|---|---|
| 前提 | 无 | 有序 + 顺序存储 |
| ASL(成功) | (n+1)/2 | ≈ log2(n+1) − 1 |
| ASL(失败) | n 或 n+1 | ≈ log2(n+1) |
| 时间复杂度 | O(n) | O(log n) |
| 链表能否用 | **能** | **不能** |
| 适用 | 小表、无序、频繁插入 | 静态表、查得多改得少 |

## 六、自测

1. 长度 10 的顺序表，等概率下顺序查找成功的 ASL 是多少？失败呢？
2. 长度 15 的有序表折半查找，判定树有几层？ASL(成功) 是多少？
3. 为什么「有序单链表」不能用折半查找？
4. 带哨兵与不带哨兵，失败查找的比较次数差多少？为什么？

> 答案：1）5.5；10（或 11，看是否带哨兵）2）4 层；49/15≈3.27
> 3）链表取中间节点要 O(n)，折半的 O(1) 定位前提不成立
> 4）差 1 次，哨兵自身也比了一次
