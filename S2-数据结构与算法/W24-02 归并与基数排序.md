# W24-02 归并与基数排序

> 归并排序：**稳定**且**最坏也是 O(n log n)**，代价是 O(n) 空间。
> 基数排序：**不是比较排序**，能做到线性时间。
> 本文最后给一张「所有排序的总表」，这张表是软考选择题的核心。

---

## 一、归并排序：先递归，再合并

```c
void mergeSort(int a[], int lo, int hi) {
    if (lo >= hi) return;
    int mid = (lo + hi) / 2;
    mergeSort(a, lo, mid);          /* 排左半 */
    mergeSort(a, mid + 1, hi);      /* 排右半 */
    merge(a, lo, mid, hi);          /* 合并 */
}
```

### 合并：双指针取小

```c
while (i <= mid && j <= hi) {
    if (a[i] <= a[j]) tmp[k++] = a[i++];    /* ⚠️ <= 保证稳定 */
    else              tmp[k++] = a[j++];
}
while (i <= mid) tmp[k++] = a[i++];         /* 剩余接上 */
while (j <= hi)  tmp[k++] = a[j++];
for (int t = lo; t <= hi; t++) a[t] = tmp[t];   /* 拷回 */
```

### 实测（`242_merge_sort.c`）

```text
拆分 [0..7] → [0..3] 和 [4..7]
  拆分 [0..3] → [0..1] 和 [2..3]
    ...
  归并 [0..0] 和 [1..1] → [38 49]
  归并 [0..1] 和 [2..3] → [38 49 65 97]
  ...
  归并 [0..3] 和 [4..7] → [13 27 38 49 49 65 76 97]

比较 16 次，拷贝 24 次
```

> ⭐ 拷贝 24 次 = n × log₂n = 8 × 3 —— 这个数字正好印证了复杂度。

## 二、归并的三个关键结论

| 项 | 值 | 说明 |
|---|---|---|
| 时间 | **O(n log n)**（最好=最坏=平均） | 不受数据影响 |
| 空间 | **O(n)** | 要辅助数组，最大缺点 |
| 稳定性 | **稳定** | 靠 `<=` 保证 |

### 为什么最坏也是 O(n log n)

```text
树的高度 = log2(n) 层
每层归并的总工作量 = n（每个元素搬一次）
总时间 = n × log2(n)
```

**不管数据长什么样，都要走完 log n 层、每层扫 n 个** —— 所以没有最坏情况。

### 稳定靠哪个符号

```c
if (a[i] <= a[j]) 取左边     /* ✅ 稳定 */
if (a[i] <  a[j]) 取左边     /* ❌ 相等时取右边 → 不稳定 */
```

> 📌 这个符号是软考改错题的高频点，和插入/冒泡的 `>` 是同一类考点。

## 三、归并的两个独特用途

### ① 链表排序（软考原题）

| 为什么快排不行 | 为什么归并合适 |
|---|---|
| 链表不能随机访问，分区要找中点、随机访问元素 | 找中点用**快慢指针** O(n)；合并只用改指针 |

> ⭐ **链表的归并排序空间是 O(1)**，因为不需要额外数组，只改指针。
> 📌 软考问「链表最适合的排序」→ 归并排序。

### ② 外部排序

数据大到内存装不下时：

```text
① 分块读入内存，每块排好序写回磁盘
② 多路归并这些有序块
```

### ③ 统计逆序对（进阶）

归并时如果取右边元素（说明 `a[i] > a[j]`），
那么左边从 `i` 到 `mid` 的所有元素都大于 `a[j]` ——
一次就能统计出 `mid - i + 1` 个逆序对。

> ⭐ 这把 O(n²) 的暴力统计降到 O(n log n)。
> 实测：8 个元素的数组，暴力 15 个、归并 15 个，结果一致 ✓

## 四、基数排序：不比较也能排

### 思路（LSD，最低位优先）

```text
329 457 657 839 436 720 355 123 90 5

按个位分配到 10 个桶，收集：
  → 720 90 123 355 5 436 457 657 329 839

按十位分配，收集：
  → 5 720 123 329 436 839 355 457 657 90

按百位分配，收集：
  → 5 90 123 329 355 436 457 657 720 839  ✓
```

> ⭐ **低位先排、高位后排。** 高位排在后面，优先级更高，
> 会把低位已经排好的顺序「覆盖」掉，所以最终正确。

### 为什么每趟必须「从后往前」放

```c
for (int i = n - 1; i >= 0; i--) {      /* ⚠️ 从后往前 */
    int d = (a[i] / exp) % 10;
    tmp[--bucket[d]] = a[i];
}
```

> ⭐ **为了保证稳定。** 相同的当前位，原来在前面的仍要排在前面。
> 如果从前往后放，相同位的相对顺序会反转 → 不稳定 → **结果可能错**。
>
> 📌 基数排序的稳定性不是「可选项」，是**正确性的前提**。

### 三条结论

| 项 | 值 |
|---|---|
| 时间 | **O(d(n+r))**，d=位数，r=基数 |
| 空间 | **O(n+r)** |
| 稳定性 | **稳定** |

> ⭐ 当 d 是常数时是**线性** O(n)。
> 比较排序的下界是 O(n log n)，基数排序能突破，**因为它不是比较排序**。

### 适用与不适用

| ✅ 适合 | ❌ 不适合 |
|---|---|
| 整数 | 浮点数 |
| 位数不多 | 负数（要分离正负） |
| 范围固定 | 位数差异极大 |

## 五、所有排序总表（这张表是核心）

| 排序 | 最好 | 最坏 | 空间 | 稳定性 | 一趟后 |
|---|---|---|---|---|---|
| 直接插入 | **O(n)** | O(n²) | O(1) | **稳定** | 前 i 个有序 |
| 冒泡 | **O(n)** | O(n²) | O(1) | **稳定** | 最大到末尾 |
| 选择 | O(n²) | O(n²) | O(1) | 不稳定 | 最小到最前 |
| 希尔 | O(n^1.3) | O(n^1.3) | O(1) | 不稳定 | 更接近有序 |
| **快速** | O(nlogn) | **O(n²)** | O(logn) | 不稳定 | **基准归位** |
| **归并** | O(nlogn) | **O(nlogn)** | **O(n)** | **稳定** | 局部有序 |
| **堆** | O(nlogn) | O(nlogn) | **O(1)** | 不稳定 | 堆顶归位 |
| 基数 | O(d(n+r)) | O(d(n+r)) | O(n+r) | **稳定** | 按位有序 |

### 稳定性口诀

```text
稳定：插入、冒泡、归并、基数     → 「插冒归基」
不稳定：选择、希尔、快速、堆     → 「选希快堆」
口诀：插冒归基稳，选希快堆晃。
```

## 六、怎么选排序算法

| 场景 | 选什么 | 为什么 |
|---|---|---|
| n 很小（< 50） | 直接插入 | 简单、常数小、不递归 |
| 数据基本有序 | 直接插入 | 接近 O(n) |
| 要求稳定 | 归并 | 唯一 O(nlogn) 且稳定的 |
| 空间紧张 | 堆排序 | 唯一 O(1) 空间的 O(nlogn) |
| 一般情况最快 | 快速 | 常数小、缓存友好 |
| 链表排序 | 归并 | 空间还能是 O(1) |
| 小范围整数 | 基数 | 线性时间 |

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 归并复杂度 | 最好/最坏 | 都是 O(nlogn) |
| 归并空间 | 多少 | O(n) |
| 归并稳定性 | 靠什么保证 | `a[i] <= a[j]` |
| 链表排序 | 用什么 | 归并 |
| 逆序对 | 怎么快速统计 | 归并 |
| 基数复杂度 | O(d(n+r)) | d 位数 |
| 基数稳定性 | 必须稳定吗 | 是，正确性前提 |
| 总表 | 哪个空间 O(1) | 堆排序 |
