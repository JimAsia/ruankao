# W18-01 栈：受限的线性表

> 栈是**操作受限的线性表**：只允许在一端（栈顶）插入和删除。
> 特性：**后进先出 LIFO**（Last In First Out）。
>
> 「受限」听起来是缺点，其实是优点 —— 正因为限制，所有操作都变成 O(1)。

---

## 一、栈的定义与三个操作

| 操作 | 含义 | 别名 |
|---|---|---|
| `push` | 入栈（压栈） | 插入 |
| `pop` | 出栈（弹栈） | 删除 |
| `top` | 取栈顶 | 读栈顶，不删除 |

软考有时把 `push` 叫 `PUSH`、`pop` 叫 `POP`，还有叫「进栈/退栈」的，都是同一回事。

> ⭐ **栈的操作都在「栈顶」这一端**，栈底是封死的。
> 这就是它和普通线性表的唯一区别。

---

## 二、顺序栈：数组 + top 指针

```c
#define MAXSIZE 8

typedef struct {
    int data[MAXSIZE];
    int top;                /* 栈顶下标，空栈时是 -1 */
} SqStack;
```

### 三个必须记准的判断

```c
判空：top == -1
判满：top == MAXSIZE - 1        /* ⚠️ 不是 MAXSIZE */
元素个数 = top + 1
```

> ⚠️ **判满写成 `top == MAXSIZE` 就已经越界了。**
> 下标从 0 开始，8 个元素的下标是 0..7。当 `top == MAXSIZE` 时，
> `data[top]` 已经指向数组外面 —— 那一刻写进去就是越界写。

### 入栈出栈的两行代码

```c
/* 入栈：先加后赋值 */
S->data[++S->top] = v;

/* 出栈：先取值后减 */
v = S->data[S->top--];
```

> ⭐ **`++` 在前还是后，决定了「先动指针还是先动数据」。**
>
> `++S->top` 是先加再用，所以新元素放在新位置上。
> `S->top--` 是先取再减，所以取的是当前栈顶，然后指针下移。

### 实测过程

`181_stack_array.c` 的真实输出：

```text
初始     栈底[]栈顶   top=-1  size=0
入栈后   栈底[10]栈顶   top=0  size=1
入栈后   栈底[10 20]栈顶   top=1  size=2
入栈后   栈底[10 20 30]栈顶   top=2  size=3

栈顶是 30，取完后栈不变

弹出 30 → 剩余 栈底[10 20]栈顶   top=1  size=2
弹出 20 → 剩余 栈底[10]栈顶   top=0  size=1
弹出 10 → 剩余 栈底[]栈顶   top=-1  size=0
```

**进 10 20 30，出 30 20 10** —— 后进先出。

### 边界测试

```text
空栈出栈：出栈失败：栈空（top=-1）
栈满（8 个）：入栈失败：栈满（top=7）
```

两个边界都要判，否则一个越界读、一个越界写。

## 三、链栈：用链表实现栈

顺序栈有容量上限，链栈没有。**栈顶对应链表的第一个节点**（头插法）。

```c
typedef struct SNode {
    int           data;
    struct SNode *next;
} SNode;

typedef struct {
    SNode *top;             /* 栈顶指针，空栈时为 NULL */
} LinkStack;
```

| 操作 | 实现 |
|---|---|
| 入栈 | 头插：`n->next = top; top = n;` |
| 出栈 | 删第一个：`top = top->next; free(旧top);` |
| 取栈顶 | 读 `top->data` |
| 判空 | `top == NULL` |

> ⭐ **链栈的入栈出栈都在链表头部做，所以都是 O(1)。**
> 如果非要拿链表尾部当栈顶，入栈就变 O(n) 了（要找尾）—— 这是设计上的选择。

### 顺序栈 vs 链栈

| 对比项 | 顺序栈 | 链栈 |
|---|---|---|
| 容量 | 固定 MAXSIZE | 动态 |
| 栈满 | 会溢出 | 不会（除非内存耗尽） |
| 入栈出栈 | O(1) | O(1) |
| 额外空间 | 无 | 每节点 1 个指针 |
| 实现难度 | 简单 | 要管 malloc/free |
| 实际选用 | 容量可预估时 | 容量不确定时 |

## 四、共享栈：两个栈共用一个数组

这是软考常考的一个结构。

```c
typedef struct {
    int data[MAXSIZE];
    int top1;               /* 栈 1 的栈顶，从左往右长 */
    int top2;               /* 栈 2 的栈顶，从右往左长 */
} SharedStack;
```

```text
初始：top1 = -1        top2 = MAXSIZE

     下标  0   1   2   3   4
          [?] [?] [?] [?] [?]
           ↑               ↑
         top1            top2

栈 1 入栈：data[++top1] = v
栈 2 入栈：data[--top2] = v
```

实测（MAXSIZE=8，交替入栈 3 个）：

```text
初始：top1=-1, top2=8
入栈 3 个后：top1=2, top2=5
数组内容：1 2 3 0 0 300 200 100
栈1（左→右）：1 2 3
栈2（右→左）：100 200 300
```

> 📝 中间那两个 `0` 是还没用到的空位（程序里预先清零了）。
> `top1+1 = 3`、`top2 = 5`，中间 `3..4` 两个位置还空着。

### 判满条件

```c
top1 + 1 == top2        /* 两个栈顶撞上了 */
```

实测 `top1+1 = 3`，`top2 = 5`，还没满。

> ⭐ **共享栈的意义**：两个栈此消彼长，只有当**总和**超过 MAXSIZE 时才满。
>
> 对比：两个独立栈各分 MAXSIZE/2，只要一个栈用超一半就溢出，
> 而共享栈可以一个用 90%、另一个用 10%。
>
> 📌 这是「用结构设计省空间」的典型例子，软考选择题考过多次。

### 两个细节

1. **栈 2 的初始 `top2 = MAXSIZE`，不是 `MAXSIZE - 1`**
   因为入栈是 `--top2`，第一次入栈后 `top2 = MAXSIZE-1`，正好是最后一个位置。
2. **两个栈的元素个数分别是 `top1+1` 和 `MAXSIZE-top2`**

## 五、栈的复杂度：全部 O(1)

| 操作 | 复杂度 | 原因 |
|---|---|---|
| 入栈 `push` | **O(1)** | 只改 `top` 和一个位置 |
| 出栈 `pop` | **O(1)** | 只改 `top` |
| 取栈顶 `top` | **O(1)** | 直接读 `data[top]` |
| 判空/判满 | **O(1)** | 看 `top` 的值 |

> ⭐ **这是栈最漂亮的地方。**
> 对比顺序表：插入删除平均要挪 n/2 个元素，O(n)。
> 而栈只在栈顶动，**永远不用挪元素**，所以是 O(1)。
>
> 这就是「限制带来效率」—— 少了一种操作，换来全部操作都变快。

## 六、栈的合法出栈序列（软考必考）

给入栈顺序，问「哪个出栈序列不可能」。

**例：入栈 1 2 3，可能的出栈序列有哪些？**

用穷举法，共 `C(6,3)/4 = 5` 种：

| 出栈序列 | 操作过程 |
|---|---|
| 1 2 3 | 进1出1、进2出2、进3出3 |
| 1 3 2 | 进1出1、进2进3、出3出2 |
| 2 1 3 | 进1进2、出2出1、进3出3 |
| 2 3 1 | 进1进2、出2、进3、出3出1 |
| 3 2 1 | 进1进2进3、出3出2出1 |
| ~~3 1 2~~ | **不可能** |

**为什么 3 1 2 不可能？**

要第一个出 3，必须先把 1 2 3 全进栈。此时栈里是 `[1, 2]`（3 已经出了），
栈顶是 2，下一个只能出 2，不能出 1。

> ⭐ **判断口诀：如果某个元素 x 出栈了，那么在它之前入栈、且还没出栈的元素，
> 必须按「逆序」出栈。**
>
> 具体到 3 1 2：3 出栈时，1 和 2 都还在栈里，所以它们只能按 2 1 出，不能 1 2 出。

### 变形题

> 入栈 1 2 3 4，出栈序列 `4 3 1 2` 是否可能？

4 出栈时，1 2 3 都在栈里（栈顶 3），所以只能按 `3 2 1` 出。
`3 1` 就违反了逆序规则 → **不可能**。

> 📌 这类题只要记住「同一时刻在栈里的元素必须逆序出」，几秒钟就能判完。

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 判空判满 | `top` 的条件 | 空 `-1`，满 `MAXSIZE-1` |
| 元素个数 | `top` 和 n 的关系 | `top + 1` |
| 入栈出栈 | 两行代码 | `data[++top]` / `data[top--]` |
| 共享栈 | 判满条件 | `top1 + 1 == top2` |
| 共享栈 | 栈 2 初始 top2 | `MAXSIZE` |
| 复杂度 | 入栈出栈 | 全 O(1) |
| 出栈序列 | 哪个不可能 | 栈内元素必须逆序出 |
| 链栈 | 栈顶在哪 | 链表头部 |
