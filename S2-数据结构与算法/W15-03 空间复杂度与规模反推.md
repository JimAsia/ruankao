# W15-03 空间复杂度与规模反推

> 时间复杂度和空间复杂度是一对孪生兄弟：**用空间换时间，或用时间省空间**。
> 这一节讲清空间怎么算，以及复杂度最实用的用法 —— **在写代码前判断会不会超时**。

---

## 一、空间复杂度：只算「额外」空间

定义：算法运行时**额外**占用的空间（不含输入数据本身），随 n 增长的量级。

### 三个例子，三种答案

| 函数 | 做了什么 | 时间 | 空间 |
|---|---|---|---|
| `f1` 求和 | 循环累加 | O(n) | **O(1)** |
| `f2` 复制数组 | `malloc(n * sizeof(int))` | O(n) | **O(n)** |
| `f3` 递归求和 | 递归 n 层 | O(n) | **O(n)** |

实测（`ex153`）：

```text
f1 求和      ：时间 O(n)       空间 O(1)
               额外变量只有 sum 和 i，与 n 无关
f2 复制数组  ：时间 O(n)       空间 O(n)
               malloc 了 n 个 int = 4000 字节
f3 递归求和  ：时间 O(n)       空间 O(n)
               递归 1000 层，每层一个栈帧
```

> ⭐ **注意 f1 的输入 `a[]` 有 n 个元素，但它不算 f1 的额外空间。**
> 数组是调用者提供的，f1 自己只开了两个变量。所以是 O(1)。

### 三条判断规则

1. **只用了固定几个变量（含循环变量）→ O(1)**
2. **开了长度与 n 成正比的数组/链表 → O(n)**
3. **递归深度为 d → 至少 O(d) 的栈空间**

> ⚠️ 第 3 条最容易漏。递归函数的每一层都要在栈上保存「返回地址 + 参数 + 局部变量」，
> 这一层还没返回，下一层又压上来 —— 一共压 d 层。
>
> n = 100000 时，每层假设 48 字节就是 4.8 MB，而默认栈通常只有 1~8 MB → **栈溢出**。
> 这就是 S1-W8 讲的「递归深度不能太大」的真正原因。

## 二、常见算法的时空对照（软考高频表）

| 算法 | 时间（平均） | 时间（最坏） | 空间 | 稳定性 |
|---|---|---|---|---|
| 冒泡排序 | O(n²) | O(n²) | **O(1)** | 稳定 |
| 选择排序 | O(n²) | O(n²) | **O(1)** | 不稳定 |
| 插入排序 | O(n²) | O(n²) | **O(1)** | 稳定 |
| 归并排序 | O(n log n) | O(n log n) | **O(n)** | 稳定 |
| 快速排序 | O(n log n) | **O(n²)** | O(log n) | 不稳定 |
| 堆排序 | O(n log n) | O(n log n) | **O(1)** | 不稳定 |
| 顺序查找 | O(n) | O(n) | O(1) | — |
| 二分查找（迭代） | O(log n) | O(log n) | **O(1)** | — |
| 二分查找（递归） | O(log n) | O(log n) | O(log n) | — |

> 📌 这张表在 S2 讲排序时会反复用到。现在先记住两个「反直觉」的点：
> - **归并排序快但费空间**（O(n)），堆排序同样快但省空间（O(1)）
> - **快排最坏是 O(n²)**，不是 O(n log n)

## 三、三种简单排序的实测对比

同样是 8 个数，三种排序的比较和交换次数差别很大（`ex154` 实测）：

### 乱序数据 `64 25 12 22 11 90 45 33`

```text
冒泡     比较 25   交换 14
选择     比较 28   交换  6
插入     比较 18   交换 14
```

### 已排好序的数据 `11 12 22 25 33 45 64 90`

```text
冒泡     比较  7   交换  0
选择     比较 28   交换  0
插入     比较  7   交换  0
```

### 三条结论

**① 选择排序的比较次数与数据无关**

两种数据都是 **28** 次 = `n(n-1)/2`。因为无论数据怎样，内层都要扫完才能确定最小值。

**② 冒泡加了提前退出，有序时只跑 1 趟**

7 次就结束。不加优化的版本永远是 28 次。

**③ 插入排序在近乎有序的数据上退化成 O(n)**

比较 7 次、移动 0 次。

> ⭐ **所以「数据基本有序」时选插入排序**，这是它的最大价值。
> 而「要求交换次数最少」时选选择排序（最多 n-1 次）。

## 四、规模反推：这道题该用什么复杂度

这是复杂度最实用的用途 —— **看题目给的 n，就知道该用什么算法**。

假设评测机每秒 1 亿次基本操作：

| n 的范围 | 可以用的复杂度 | 典型做法 |
|---|---|---|
| n ≤ 10 | O(n!)、O(2ⁿ) | 全排列、暴力枚举 |
| n ≤ 1000 | O(n²) | 双层循环、简单排序 |
| n ≤ 10⁵ | O(n log n) | 归并/快排、二分 |
| n ≤ 10⁷ | O(n) | 一遍扫描 |
| n 任意 | O(log n)、O(1) | 二分、哈希 |

实测预测（`ex156`，按 1 亿次/秒）：

```text
n          O(n)        O(n log n)   O(n^2)      O(2^n)
1000       0.0000秒    0.0001秒     0.0100秒    算不完
10000      0.0001秒    0.0013秒     1.00秒      算不完
100000     0.0010秒    0.0160秒     1.7分钟     算不完
1000000    0.0100秒    0.1900秒     2.8小时     算不完
```

> ⭐ **n = 10⁶ 时，O(n²) 要 2.8 小时** —— 这就是「超时」的具体含义。
> 软考虽然不考「超时」，但应用技术题里问「这个算法适合多大规模的数据」，答案就在这里。

## 五、四个常见误区

**① 以为 O(n log n) 和 O(n) 差不多**

n = 10⁶ 时，`log₂n ≈ 20`，差了 **20 倍**。不是「差不多」，是「差一个数量级」。

**② 以为都是 O(n) 就一样快**

常数可能差 100 倍。比如同样是 O(n)，一个循环体做一次加法，一个做十次乘法。

**③ 以为小数据能跑就没事**

n = 100 时 O(n²) 只要 0.1 毫秒，完全看不出问题。规模一上来就崩。

**④ 把 O(log n) 写成 O(log₂ n)**

大 O 里**底数不写**。`log₂n`、`log₃n`、`ln n` 都写成 `log n`，因为底数只差一个常数因子：
`log₂n = log₃n / log₃2`，那个 `1/log₃2` 是常数。

> 📌 软考如果选项里同时出现 `O(log n)` 和 `O(log₂ n)`，选 **`O(log n)`**（标准写法）。

## 六、多参数的情况

有些算法有两个规模，比如「在 n 个元素的数组里查 m 次」：

```c
for (int k = 0; k < m; k++) {        /* m 次查询 */
    for (int i = 0; i < n; i++) ...  /* 每次 O(n) */
}
/* 复杂度 = O(n * m)，不能写成 O(n²) */
```

> ⚠️ **n 和 m 是两个独立的量，不能合并。**
> 只有当题目说「m 和 n 同阶」时，才能写成 O(n²)。

同理，图的算法常写 **O(V + E)**（顶点数 + 边数），也是两个参数。

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 空间复杂度 | 给算法问空间 | 只看额外空间，不看输入 |
| 递归空间 | 递归函数的空间 | = 递归深度 |
| 排序空间 | 哪个排序最省空间 | 堆排序 O(1) 且 O(n log n) |
| 多参数 | O(n·m) 能不能合并 | 不能，除非同阶 |
| log 底数 | O(log₂n) 写法对不对 | 不写底数 |
| 规模反推 | n=10⁶ 用什么算法 | 只能 O(n) 或 O(n log n) |
