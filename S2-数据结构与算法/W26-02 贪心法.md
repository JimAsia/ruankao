# W26-02 贪心法

> 贪心最像人的直觉：**每一步都选当前看起来最好的，选了就不回头。**
> 它的危险也在这里 —— 直觉经常是错的，而错误往往只在个别数据上暴露。

---

## 一、基本思想

```text
把问题分成若干步，每一步都做「当前最优」的选择，
且这个选择一旦做出就不再更改，最终得到问题的解。
```

关键词是**不回头**。这决定了贪心的两个特点：

- 快：通常 O(n log n)（排序）或 O(n)
- 不一定对：只在满足特定条件时才是最优解

---

## 二、能用贪心的两个条件

| 条件 | 含义 | 怎么验证 |
|---|---|---|
| **贪心选择性质** | 每一步的局部最优能推出全局最优 | 交换论证（把最优解的第一步换成贪心的选择，证明不变差） |
| **最优子结构** | 原问题最优解包含子问题最优解 | 和动规一样 |

> ⚠️ 两个条件**必须同时满足**。只满足最优子结构是不够的 ——
> 0-1 背包就满足最优子结构，但贪心会错。

---

## 三、案例一：活动安排（贪心正确）

n 个活动共用一个场地，每个活动有起止时间，求最多能安排几个不重叠的活动。

**正确策略：按结束时间升序，依次选不冲突的。**

```c
qsort(acts, n, sizeof(Act), cmpEnd);     // 按 end 升序
int cnt = 0, lastEnd = -1;
for (int i = 0; i < n; i++)
    if (acts[i].start >= lastEnd) { cnt++; lastEnd = acts[i].end; }
```

实测（11 个活动，`262`）：

```text
按【结束时间最早】选：4 个 → 1 4 8 11
按【开始时间最早】选：3 个 → 3 7 11
按【持续时间最短】选：4 个 → 2 4 8 11   ← 这组凑巧，但没有最优性保证
```

### 3.1 为什么「结束时间」对，其他都不对

**交换论证**（软考简答题的标准答案）：

```text
设最优解的第一个活动是 A，贪心选的是结束最早的 B。
因为 B.end ≤ A.end，把 A 换成 B 后，剩余可用时间只会更多，
所以仍存在一个同样大的最优解包含 B。
反复替换，贪心解 = 某个最优解。
```

**反例说明「开始时间」为什么错**：

```text
活动：[0,10) [1,2) [2,3) [3,4)
最优：后三个，共 3 个
按开始时间：先选 [0,10)，后面全冲突 → 只有 1 个
实测：按开始时间 = 1，按结束时间 = 3
```

> ⭐ 一个选择标准差之毫厘，结果从 3 掉到 1。

### 3.2 实证验证

`ex263` 用 1000 组随机数据把贪心和暴力枚举对比：

```text
不一致组数：0 / 1000
```

> 注意：**验证不能代替证明**。1000 组都对，只能说明「没找到反例」，
> 真正的正确性要靠上面的交换论证。

## 四、案例二：找零钱（贪心会错）

币值 `{1, 5, 11}`，凑 15 元，求最少硬币数。

```text
贪心（先大后小）：11 + 1 + 1 + 1 + 1 = 5 枚
最优（动规）：    5 + 5 + 5           = 3 枚
```

贪心错了 2 枚。原因：**拿了 11 之后，余数 4 只能用 4 个 1 凑**，
而贪心在拿 11 的那一刻并不考虑「剩下的能不能凑好」。

### 4.1 失效的金额不止一个

实测 1..50 全枚举（`ex264`）：

```text
失效金额：15、20、26、31、37、42、48   共 7 个
最小的是 15，贪心多用了 2 枚
```

### 4.2 人民币为什么可以贪心

人民币面额 `1 / 2 / 5 / 10 / 20 / 50 / 100`，满足「后一个面额 ≥ 前一个的 2 倍」，
这叫**规范币值系统**，贪心保证最优。

`1 / 5 / 11` 不满足（5 到 11 不到 2 倍），所以会出问题。

> ⭐ 软考选择题会问「找零钱能否用贪心」，答案是：**取决于币值是否规范**，
> 不能一概而论。

## 五、案例三：背包问题的分水岭

### 5.1 分数背包（贪心正确）

物品可以切开。按**单位价值**从高到低装，最后一件能装多少装多少。

实测（容量 50）：

```text
A：重 10，价值 60，单位价值 6.00
B：重 20，价值 100，单位价值 5.00
C：重 30，价值 120，单位价值 4.00

贪心：A 100% + B 100% + C 67% → 价值 240.0
```

这就是最优解。因为可以切，**每一份容量都用在当前单位价值最高的物品上**，
不存在「装了 A 就装不下 B+C」的遗憾。

### 5.2 0-1 背包（贪心错误）

同样的数据，物品不能拆：

```text
贪心（按单位价值）：A + B → 重 30，价值 160，余 20 装不下 C
最优：              B + C → 重 50，价值 220
```

贪心少 60。原因：A 的单位价值最高，但它把容量占住了，
导致 B+C 这个组合装不进去。

> ⭐ **这一对比是软考最爱考的**：
> 分数背包可用贪心，0-1 背包必须用动规。

### 5.3 换一组数据，贪心也会错

`ex265` 的例子（容量 8，物品 (2,3)(3,4)(4,5)(5,6)）：

```text
贪心：选物品 1、2（重 5，价值 7），余 3 什么都装不下
最优：选物品 2、4（重 8，价值 10）
```

## 六、三大策略的边界

| | 分治 | 贪心 | 动规 |
|---|---|---|---|
| 思路 | 拆成独立子问题，合并 | 每步取局部最优，不回头 | 枚举所有子问题，存表复用 |
| 子问题 | 互不重叠 | 每步只做一个选择 | 大量重叠 |
| 是否回溯 | 不需要 | **绝不回退** | 隐式枚举所有可能 |
| 正确性 | 结构保证 | **需要证明** | 转移方程保证 |
| 典型 | 归并、快排、快速幂 | 活动安排、Huffman、Prim | 背包、LCS、最短路 |

一句话记忆：

```text
分治：拆开各算，拼起来
贪心：只走一条路，不回头
动规：把所有路都算一遍，但只算一次
```

## 七、已经学过的贪心算法

S2 里其实已经见过四个贪心，只是当时没点明：

| 算法 | 贪心策略 | 在哪一周 |
|---|---|---|
| **哈夫曼编码** | 每次合并权值最小的两个 | W20 |
| **Prim** | 每次选连接已选集合的最小边 | W22 |
| **Kruskal** | 每次选全局最小且不成环的边 | W22 |
| **Dijkstra** | 每次选当前距离最小的未确定点 | W22 |

> ⭐ 这四个都是「贪心正确」的经典例子，考试常问「下列哪个算法用了贪心策略」。
> 反过来，**Floyd 是动规**，不是贪心 —— 这个也常考。

## 八、软考怎么考

### 考法 1：判断能否用贪心

> 下列问题中，贪心法不能保证得到最优解的是？
> A. 活动安排  B. 哈夫曼编码  C. 0-1 背包  D. 最小生成树

答案 C。

### 考法 2：给场景选策略

> 背包容量有限，物品可以分割，求最大价值。宜采用？

**贪心**（分数背包）。如果不能分割，则是动规。

### 考法 3：贪心策略的选择

> 活动安排问题中，按（ ）排序可以得到最优解。
> A. 开始时间  B. 结束时间  C. 持续时间  D. 活动编号

答案 B。

### 考法 4：正确性证明

> 简述活动安排问题贪心算法的正确性。

答「交换论证」：设最优解首选 A，贪心选 B（结束最早）。
因 B.end ≤ A.end，用 B 替换 A 后剩余空间不减，故仍存在包含 B 的最优解。
归纳可得贪心解最优。

## 九、自测

1. 贪心算法一定得不到最优解吗？
2. 活动安排按「持续时间最短」排序，为什么不能保证最优？
3. 0-1 背包为什么不能用贪心？举一个反例。
4. 分数背包的贪心为什么是对的？
5. 下列哪个算法不是贪心：Prim、Kruskal、Dijkstra、Floyd？

> 答案：1）不是，满足两个条件时能得到最优 2）没有交换论证支撑，短活动可能卡住两个长活动
> 3）容量 50，物品 A(10,60) B(20,100) C(30,120)，贪心 A+B=160 < 最优 B+C=220
> 4）可以切分，每份容量都能给单位价值最高的物品，不存在"占了位置就浪费"的情况
> 5）Floyd（它是动规）
