## 三、自测六题

**1. 结构体里的 `next` 为什么必须写 `struct Node *`，不能写 `Node *`？**

**2. 带头结点的链表，遍历的起点和终点判断分别是什么？**

**3. 头插法建表得到的结果与输入顺序是什么关系？为什么？**

**4. 在单链表中插入节点，`n->next = prev->next` 和 `prev->next = n` 两句能不能对调？**

**5. 「链表插入删除是 O(1)」这句话完整吗？缺了什么前提？**

**6. 带头结点的循环单链表，判空条件是什么？**

## 四、答案与解析

**1. 因为在 typedef 还没生效时，`Node` 这个别名还不存在。**

```c
typedef struct Node {
    int          data;
    struct Node *next;      /* ✅ 必须用完整写法 */
} Node;
```

结构体内部引用自己时，`typedef` 那行还没执行完，编译器不认识 `Node`。
写成 `Node *next` 会报 `unknown type name 'Node'`。

> 📌 这是 C 语言独有的问题。C++ 里可以直接写 `Node *next`。

**2. 起点 `L->head->next`，终点 `p != NULL`。**

- 起点要跳过 dummy 头结点，否则会把 dummy 的 `data` 也打印出来
- 终点判断用 `p != NULL`，不是 `p->next != NULL`（后者会漏掉最后一个节点）

**3. 顺序相反。**

因为每次新节点都插在**最前面**，最后一次插的排最前。

```text
输入 10 20 30：
  插 10 → [10]
  插 20 → [20] → [10]
  插 30 → [30] → [20] → [10]
```

> ⭐ 这个「缺点」可以当「特性」用 —— 想逆序建表，直接头插。

**4. 不能对调。**

```c
❌ prev->next = n;          /* 前半段先断了 */
   n->next = prev->next;    /* 此时 prev->next 就是 n 自己 */

结果：n->next 指向 n，形成自环，原来的后半段全部丢失。
```

正确顺序是「先接后断」：

```c
✅ n->next = prev->next;    /* 新节点先抱紧后面 */
   prev->next = n;          /* 前驱再回头拉它 */
```

**5. 不完整，缺了「已经拿到那个位置的指针」这个前提。**

| 情况 | 复杂度 |
|---|---|
| 已知前驱指针，在其后插入 | **O(1)** |
| 只知道位置下标 pos | O(n)（要先找前驱） |
| 只知道值 | O(n)（要先查找） |

> ⭐ 软考选择题常在这挖坑。看到「链表插入是 O(1)」先想：是不是已知前驱？

**6. `head->next == head`。**

```text
空表：head → head（自己指自己）
非空：head → [1] → [2] → head
```

对比记忆：

| 类型 | 判空 |
|---|---|
| 带头结点单链表 | `head->next == NULL` |
| 不带头结点单链表 | `head == NULL` |
| 带头结点循环单链表 | `head->next == head` |
