# W17-03 链表进阶与双向链表

> 这一节四块内容：**快慢指针**（一个套路打四题）、**原地合并**、**双向链表**、**循环链表**。
> 快慢指针是软考和面试共同的高频点，务必掌握。

---

## 一、快慢指针：一个套路，四种题型

慢指针每次走 1 步，快指针每次走 2 步。

| 问题 | 快指针怎么走 | 结束条件 |
|---|---|---|
| 找中间节点 | 每次 2 步 | `fast` 到尾 |
| 判断有环 | 每次 2 步 | `slow == fast` |
| 找环的入口 | 相遇后从头再来一个慢指针 | 再次相遇 |
| 删除倒数第 k 个 | 先走 k+1 步再同步 | `fast` 到尾 |

### ① 找中间节点

```c
Node *slow = head, *fast = head;
while (fast != NULL && fast->next != NULL) {
    slow = slow->next;
    fast = fast->next->next;
}
return slow;
```

实测：

```text
奇数个(7)：1 2 3 4 5 6 7  → 中间是 4
偶数个(6)：1 2 3 4 5 6    → 中间是 4（偏后）
```

**为什么能对上**：快指针速度是慢指针的 2 倍，走同样时间，路程也是 2 倍。快指针走完整条，慢指针正好一半。

> ⭐ 想让偶数个时取**偏前**的，循环条件改成
> `while (fast->next != NULL && fast->next->next != NULL)`。

### ② 判断有没有环

```c
while (fast != NULL && fast->next != NULL) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) return 1;         /* 相遇即有环 */
}
return 0;
```

实测：

```text
正常链表 1 -> 2 -> 3 -> 4 -> 5 → 有环？否
尾指回第 2 个     → 有环？是
```

**为什么一定会相遇**：进环后，快指针每轮比慢指针多走 1 步，相当于「以 1 步/轮的速度追」，环是有限的，一定能追上，不会错过。

> ⚠️ 如果快指针一次走 **3** 步，就可能「跳过」慢指针，不一定相遇。
> 这是软考的一个小陷阱。

> ⚠️ **有环的链表不能直接 destroy**，会死循环。必须先拆环。

### ③ 删除倒数第 k 个

```c
Node dummy; dummy.next = head;
Node *fast = &dummy, *slow = &dummy;

for (int i = 0; i <= k; i++) fast = fast->next;   /* 先走 k+1 步 */

while (fast != NULL) { fast = fast->next; slow = slow->next; }

Node *victim = slow->next;
slow->next = victim->next;
free(victim);
return dummy.next;
```

实测：

```text
[1 2 3 4 5] 删倒数第 1 → [1 2 3 4]
[1 2 3 4]   删倒数第 4 → [2 3 4]      ← 删掉了头节点
[2 3 4]     删倒数第 99 → 不变（k 超长）
```

**为什么要走 k+1 步而不是 k 步**：因为要停在**被删节点的前驱**上，才能改 `prev->next`。

**为什么必须用 dummy**：可能删掉头节点，改 `head` 本身时没有前驱。

> ⭐ 这个「dummy + 双指针」模板，是链表删除类题目的通用解法。
> 不用 dummy 的话，删头节点要单独写一段。

### `while` 条件的顺序也有讲究

```c
✅ while (fast != NULL && fast->next != NULL)
❌ while (fast->next != NULL && fast->next->next != NULL)
```

第一个缺了 `fast != NULL` 时，空表会直接崩（访问 `NULL->next`）。

> ⭐ **两个条件顺序也不能反**：先判 `fast` 非空，才能访问 `fast->next`。
> 这和 S1-W3 讲的「短路求值」是同一件事。

## 二、原地合并两个有序链表

```c
Node dummy; dummy.next = NULL;
Node *tail = &dummy;

while (a != NULL && b != NULL) {
    if (a->data <= b->data) { tail->next = a; a = a->next; }
    else                    { tail->next = b; b = b->next; }
    tail = tail->next;
}
tail->next = (a != NULL) ? a : b;       /* 剩余整段接上 */

return dummy.next;
```

实测：

```text
A        1 -> 4 -> 7 -> 10
B        2 -> 3 -> 8 -> 11 -> 15
合并后   1 -> 2 -> 3 -> 4 -> 7 -> 8 -> 10 -> 11 -> 15
```

### 三个要点

**① 空间 O(1)**：全程只改 `next` 指针，**没有新建节点**，复用了原节点。

> 📌 数组实现合并必须开新数组 O(n+m) 空间，这是链表更强的地方。

**② 剩余部分接一句就够**

不用写两个 `while` 逐个搬 —— 剩余部分本来就是一条完整的链：

```c
tail->next = (a != NULL) ? a : b;
```

**③ dummy 在栈上**

```c
Node dummy;             /* 栈上，函数结束自动回收 */
Node *tail = &dummy;
```

不需要 `free`。如果写成 `malloc` 反而要记得释放。

### 哨兵节点的通用价值

| 没有 dummy | 有 dummy |
|---|---|
| 第一个节点要特判 `if (head == NULL) head = 新节点` | 所有节点统一处理 |
| 删头节点要特判 | 不用特判 |
| 代码里到处是分支 | 最后 `return dummy.next` |

> ⭐ 「合并、拆分、删除头节点」这三类题，一律用 dummy。

## 三、双向链表

### 结构

```c
typedef struct DNode {
    int           data;
    struct DNode *prev;         /* 指向前一个 */
    struct DNode *next;         /* 指向后一个 */
} DNode;
```

实测：

```text
正向：10 <-> 20 <-> 30 <-> 40
反向：40 <-> 30 <-> 20 <-> 10
```

### 插入：改 4 个指针

```c
n->next = p->next;              /* ① 新节点接后 */
n->prev = p;                    /* ② 新节点接前 */
if (p->next != NULL) p->next->prev = n;    /* ③ 后节点回头指新节点 */
else                 L->tail = n;          /* p 是尾 → 更新 tail */
p->next = n;                    /* ④ 前节点指向新节点 */
```

### 删除已知节点：O(1)（这是它的杀手锏）

```c
p->prev->next = p->next;        /* ① 前驱跳过自己 */
if (p->next != NULL) p->next->prev = p->prev;   /* ② 后继回头 */
else                 L->tail = p->prev;
free(p);
```

> ⭐ **单链表删某个节点必须先找前驱，O(n)；双链表有 `prev`，直接删，O(1)。**
>
> 📌 这就是 LRU 缓存、链表节点删除类题目都用双链表的原因。

### 代价

| 项目 | 单链表 | 双链表 |
|---|---|---|
| 每节点指针数 | 1 个 | 2 个 |
| 64 位机每节点 | 16 字节 | 24 字节 |
| 插入要改指针 | 2 个 | 4 个 |
| 删除已知节点 | O(n) | **O(1)** |
| 反向遍历 | 不支持 | 支持 |

> ⭐ 用空间换时间：每节点多 8 字节，换「删除 O(1)」和「反向遍历」。

## 四、循环链表

```text
单链表：  1 -> 2 -> 3 -> NULL
循环链表：1 -> 2 -> 3 -> （回到 1）
```

### 三个要点

**① 判遍历结束不能用 `p != NULL`**

```c
❌ while (p != NULL)          /* 死循环，永远不为 NULL */
✅ while (p != head)          /* 转一圈回到头结点就停 */
```

> ⚠️ 这是循环链表最常见的 bug。

**② 从任意节点出发都能遍历整条链**

这是它的优势。**约瑟夫环**（丢手绢问题）、**轮转调度**都用它。

**③ 只有一个节点的循环链表：`next` 指向自己**

```text
[1|•] ─┐
  ↑    │
  └────┘
```

## 五、四种链表一览

| 类型 | 指针情况 | 典型用途 |
|---|---|---|
| 单链表 | 1 个 `next`，尾指 `NULL` | 普通链式存储 |
| 双链表 | `prev` + `next`，尾指 `NULL` | 需要反向 / 删除 O(1) |
| 循环单链表 | 1 个 `next`，尾指回头结点 | 约瑟夫环、轮转 |
| 循环双链表 | `prev` + `next`，头尾互指 | 双向轮转 |

> 📌 软考最常考**单链表**和**双链表**，循环链表主要考「判空条件」和「结构图识别」。

### 判空条件（选择题高频）

| 类型 | 判空条件 |
|---|---|
| 带头结点单链表 | `head->next == NULL` |
| 不带头结点单链表 | `head == NULL` |
| 带头结点循环单链表 | `head->next == head` |
| 带头结点循环双链表 | `head->next == head`（且 `head->prev == head`） |

> ⭐ 这四行建议直接背下来，软考选择题几乎每年都有。

## 六、软考怎么考

| 考点 | 典型问法 | 要点 |

| 快慢指针 | 找中间怎么做 | 慢 1 快 2 |
