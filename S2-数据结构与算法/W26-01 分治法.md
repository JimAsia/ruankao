# W26-01 分治法

> 分治是三大算法设计策略里最好理解的一个：
> **把大问题拆小，小到能直接算，再把答案拼回去。**
> 难的不是思想，是「怎么拆」和「怎么拼」。

---

## 一、三步走

```text
① 分解（Divide）  ：把原问题拆成若干个规模更小的同类子问题
② 解决（Conquer） ：递归求解。规模足够小时直接算（递归出口）
③ 合并（Combine） ：把子问题的解组合成原问题的解
```

> ⭐ 分治和递归不是一回事：**递归是手段，分治是策略**。
> 递归可以是「减一」（如阶乘），那不叫分治；分治必须是「规模成比例缩小」。

---

## 二、什么时候能用

两个条件：

| 条件 | 含义 | 反例 |
|---|---|---|
| **最优子结构** | 子问题的最优解能拼出原问题的最优解 | — |
| **子问题独立** | 子问题之间不重叠、不互相依赖 | 斐波那契递归（子问题重叠）→ 该用动规 |

第二条是分治与动规的分水岭：

```text
分治：子问题互不相交（归并排序的左半和右半没有交集）
动规：子问题大量重叠（fib(n-1) 和 fib(n-2) 都要算 fib(n-3)）
```

## 三、案例一：快速幂

求 `a^n`。朴素做法乘 n 次，分治做法：

```text
a^n = (a^(n/2))^2          n 为偶数
a^n = (a^(n/2))^2 · a      n 为奇数
```

代码只有一个要点：**只递归一次**。

```c
long long powRec(long long a, long long n, long long m) {
    if (n == 0) return 1 % m;
    long long half = powRec(a, n / 2, m);   // ← 只算一次
    long long r = half * half % m;
    if (n & 1) r = r * a % m;
    return r;
}
```

> ⚠️ 写成 `powRec(a,n/2) * powRec(a,n/2)` 就退化成 O(n) 了 —— 这是最典型的错误。

实测（`261`，mod = 1e9+7）：

| n | 朴素乘法次数 | 快速幂 | 倍数 |
|---|---|---|---|
| 1 000 | 1 000 | 16 | 62 |
| 100 000 | 100 000 | 23 | 4 348 |
| 10 000 000 | 10 000 000 | 32 | 312 500 |

**n 每翻一倍，快速幂只多 1 次乘法** —— 这就是 O(log n)。

### 迭代版（工程常用，无递归栈）

```c
long long r = 1 % m, base = a % m;
while (n) {
    if (n & 1) r = r * base % m;   // 当前二进制位是 1，就乘进去
    n >>= 1;
    if (n) base = base * base % m; // 平方，为下一位准备
}
```

`a^13 = a^(1101₂) = a^8 · a^4 · a^1` —— 这就是二进制拆分的直观解释。

## 四、案例二：最大子段和

给一个可能含负数的数组，求和最大的**连续**子段。

四种解法，复杂度差三个数量级：

| 方法 | 时间 | 思路 |
|---|---|---|
| 三重暴力 | O(n³) | 枚举起点、终点、再求和 |
| 双重暴力 | O(n²) | 枚举起点，边扩展边累加 |
| **分治** | O(n log n) | 左半、右半、跨中点三者取最大 |
| **动规** | O(n) | cur = max(cur + a[i], a[i]) |

### 4.1 分治的关键在「跨中点」

```text
最大值只可能出现在三个位置：
  ① 完全在左半
  ② 完全在右半
  ③ 跨过中点（左半的一段 + 右半的一段）
```

前两种递归求解，第三种必须单独算：

```text
从中点往左扫，求「必须以 mid 结尾」的最大后缀
从中点+1 往右扫，求「必须以 mid+1 开头」的最大前缀
两者相加 = 跨中点的最大子段和
```

实测（`261`，数组 `-2 11 -4 13 -5 -2`，mid=2）：

```text
左半 {-2,11,-4} 最大 = 11
右半 {13,-5,-2} 最大 = 13
跨中点            = 20      ← 11 + (-4) + 13
整体最大         = 20
```

> ⭐ **只看左右最大值会得到 13，少 7。** 这是分治题最常见的失分点：
> 合并时漏掉「跨越分界线」的情况。

### 4.2 实测复杂度

| n | O(n³) | O(n²) | 分治 | 动规 |
|---|---|---|---|---|
| 50 | 22 100 | 1 275 | 286 | 49 |
| 100 | 171 700 | 5 050 | 672 | 99 |
| 200 | 1 353 400 | 20 100 | 1 544 | 199 |
| 400 | 10 746 800 | 80 200 | 3 488 | 399 |

n 涨 8 倍（50→400）：

- O(n³)：涨 **486 倍**
- O(n²)：涨 **63 倍**
- 分治：涨 **12 倍**（≈ 8·log8/log1 → n log n）
- 动规：涨 **8 倍**（严格线性）

## 五、分治的复杂度怎么估

设 `T(n) = a·T(n/b) + f(n)`，其中 `a` 是子问题个数，`b` 是规模缩小倍数，
`f(n)` 是分解与合并的代价。

软考只需要记几个常见结果：

| 递推式 | 复杂度 | 典型算法 |
|---|---|---|
| T(n) = 2T(n/2) + O(n) | **O(n log n)** | 归并排序、最大子段和 |
| T(n) = 2T(n/2) + O(1) | O(n) | 求最大值、二分查找的递归版 |
| T(n) = T(n/2) + O(1) | O(log n) | 二分查找、快速幂 |
| T(n) = 2T(n-1) + O(1) | O(2ⁿ) | 汉诺塔（这是「减一」不是「减半」） |

> ⭐ **判断分治复杂度的口诀**：看「每层总工作量 × 层数」。
> 归并排序每层合并 O(n)，共 log n 层 → O(n log n)。
> 快速幂每层 O(1)，共 log n 层 → O(log n)。

## 六、软考怎么考

### 考法 1：判断「这是不是分治」

> 下列算法中，采用分治法的是？
> A. 冒泡排序  B. 归并排序  C. 插入排序  D. 基数排序

答案 B。冒泡/插入是「减治」（每轮规模减 1），归并/快排是分治。

### 考法 2：递推式求复杂度

> 某算法满足 T(n) = 2T(n/2) + n，其时间复杂度是？

`O(n log n)`。套上表第二行。

### 考法 3：分治三步的填空

> 分治法的三个步骤是（ ）、（ ）、（ ）。

分解、解决（递归求解）、合并。

### 考法 4：合并步骤的设计

> 归并排序的「合并」在做什么？最大子段和的「合并」在做什么？

归并：把两个有序表合并成一个有序表，O(n)。
最大子段和：比较左、右、跨中点三者，跨中点要额外 O(n) 扫描。

### 考法 5：分治 vs 动规

> 分治法与动态规划的主要区别是？

**子问题是否重叠**。分治的子问题互相独立，动规的子问题有重叠、需要记忆化。

## 七、自测

1. 快速幂求 a^100，需要多少次乘法（递归版）？
2. 归并排序的递推式怎么写？解出来是多少？
3. 最大子段和的分治，如果漏掉「跨中点」这一项，会在什么数据上出错？
4. 汉诺塔的递推式 T(n) = 2T(n-1) + 1，为什么不是 O(n log n)？

> 答案：1）约 9~10 次（log₂100 ≈ 6.6，加奇数次的额外乘）2）T(n)=2T(n/2)+O(n) → O(n log n)
> 3）答案跨中点时，例如 `-2 11 -4 13 -5 -2`，会得到 13 而不是 20
> 4）每层只减少 1 而不是减半，层数是 n 层，所以是 O(2ⁿ)
