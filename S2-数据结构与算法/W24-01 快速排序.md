# W24-01 快速排序

> 快排是**平均最快**的排序，也是软考考得最细的一个。
> 两个必考点：**分区过程**、**最坏情况怎么来的**。

---

## 一、分治三步

```text
① 选一个「基准」（pivot）
② 分区（partition）：把数组分成两半，左边都 <= 基准，右边都 >= 基准
   —— 分区后基准就到了【最终位置】
③ 对左右两半递归做同样的事
```

> ⭐ **快排和其他排序最大的不同：分层从上往下（先分区再递归）。**
> 归并是反过来（先递归再合并）。

---

## 二、分区：挖坑法

```c
int partition(int a[], int lo, int hi) {
    int pivot = a[lo];              /* a[lo] 成为第一个「坑」 */
    int i = lo, j = hi;

    while (i < j) {
        while (i < j && a[j] >= pivot) j--;      /* j 找比基准小的 */
        if (i < j) a[i] = a[j];                  /* 填到左边的坑 */

        while (i < j && a[i] <= pivot) i++;      /* i 找比基准大的 */
        if (i < j) a[j] = a[i];                  /* 填到右边的坑 */
    }

    a[i] = pivot;                   /* 基准填进最后的坑 */
    return i;                       /* 返回基准的最终位置 */
}
```

### 实测（`241_quick_sort.c`）

```text
原始：[49 38 65 97 76 13 27 49]
基准 = 49
  a[6]=27 填到 i=0（左边）
  a[2]=65 填到 j=6（右边）
  a[5]=13 填到 i=2（左边）
  a[3]=97 填到 j=5（右边）
基准 49 归位到下标 3

分区后：[27 38 13 49 76 97 65 49]
```

验证：左边 `27 38 13` 都 < 49，右边 `76 97 65 49` 都 >= 49 ✓

> ⭐ **全程只有「赋值」，没有「交换」**，比交换法效率高一点。
> 这个技巧叫「挖坑填数」。

### 一趟后确定了几个元素

**至少 1 个：基准。**

> 📌 软考问「快排一趟后能确定几个元素的最终位置」→ 基准那一个。
> 如果数据凑巧，其他元素也可能就位，但**保证**的只有基准。

## 三、最坏情况：已有序 + 取端点为基准

### 实测对比

```text
数据形态   比较次数     递归深度
随机         13             4
已有序       28             7
完全逆序     28             7
```

**已有序时比较 28 次 = n(n-1)/2 = 28** —— 完全退化成 O(n²)！

### 为什么

```text
数据：13 27 38 49 49 65 76 97

第 1 趟：基准 13（最小值），分区后 → 左边空，右边 7 个
第 2 趟：基准 27，分区后 → 左边空，右边 6 个
...
每次只减少 1 个元素 → 递归 n 层，总比较 n(n-1)/2
```

> ⭐ **快排最怕「已经有序」的数据**，这很反直觉：
> 一道「排好序的数组」，快排反而最慢。

### 三种避免最坏的方法

| 方法 | 做法 |
|---|---|
| 随机化 | 随机选基准 |
| 三数取中 | 取首、中、尾的中位数 |
| 小区间优化 | n < 10 时改用插入排序 |

## 四、关键性质

| 项 | 值 |
|---|---|
| 平均时间 | **O(n log n)** |
| 最坏时间 | **O(n²)**（已有序 + 取端点） |
| 空间 | **O(log n)**（递归栈） |
| 稳定性 | **不稳定** |
| 一趟效果 | 基准归位 |

### 为什么平均快

```text
每次分区大致二分 → 递归 log n 层
每层总共扫 n 个元素
→ n × log n

而且常数因子小：
  - 原地交换，不需要辅助数组
  - 顺序访问，缓存友好
```

> ⭐ 所以实际测试快排普遍比归并和堆排快 1.5~2 倍。
> 标准库的 `sort` 基本都是快排的变体（如 introsort）。

### 为什么不稳定

```text
分区时是「远距离赋值」：a[i] = a[j] 可能跨过相等元素。

例：[2a, 2b, 1]，基准 2a：
    j 找到 1，a[0] = 1 → [1, 2b, 2a]
    2a 和 2b 的相对顺序变了 → 不稳定
```

## 五、一个重要应用：第 k 小（快速选择）

不用完全排序，只递归**一边**：

```c
int kthSmallest(int a[], int n, int k) {
    int lo = 0, hi = n - 1, target = k - 1;
    while (lo <= hi) {
        int p = partition(a, lo, hi);
        if (p == target)     return a[p];
        else if (p > target) hi = p - 1;    /* 在左半找 */
        else                 lo = p + 1;    /* 在右半找 */
    }
    return -1;
}
```

### 为什么是 O(n)

```text
完整快排：递归两边，每层总共 n → O(n log n)
第 k 小  ：只递归一边
          工作量 n + n/2 + n/4 + ... = 2n → O(n)
```

> ⭐ 这个技巧叫 **quickselect**，C++ 的 `nth_element` 就是它。
> 📌 软考/面试常问「找第 k 小，不用完全排序怎么做」。

## 六、快排 vs 归并（结构对比）

| 对比 | 快速排序 | 归并排序 |
|---|---|---|
| 分治顺序 | **先分区，再递归**（从上往下） | **先递归，再合并**（从下往上） |
| 核心操作 | partition（找基准位置） | merge（合并两个有序段） |
| 平均时间 | O(n log n) | O(n log n) |
| 最坏时间 | **O(n²)** | O(n log n) |
| 空间 | O(log n) | **O(n)** |
| 稳定性 | 不稳定 | **稳定** |

> ⭐ 一句话记：**快排「从上往下分」，归并「从下往上合」。**

## 七、软考怎么考

| 考点 | 典型问法 | 要点 |
|---|---|---|
| 分区过程 | 给数组写第一趟结果 | 按指定基准手算 |
| 一趟确定 | 能确定几个元素 | 至少 1 个（基准） |
| 最坏情况 | 什么时候 O(n²) | 已有序 + 取端点 |
| 复杂度 | 平均 / 最坏 | O(n log n) / O(n²) |
| 空间 | 递归栈 | O(log n) |
| 稳定性 | 稳定吗 | 不稳定 |
| 第 k 小 | 怎么做到 O(n) | 只递归一边 |
