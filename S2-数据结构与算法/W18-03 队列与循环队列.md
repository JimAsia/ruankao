# W18-03 队列与循环队列

> 队列也是**操作受限的线性表**：一端（队尾）进，另一端（队头）出。
> 特性：**先进先出 FIFO**。
>
> 它的难点只有一个，但几乎是必考：**假溢出**和**循环队列的判满**。

---

## 一、队列的定义

| 操作 | 含义 | 位置 |
|---|---|---|
| `enqueue` | 入队 | 队尾 `rear` |
| `dequeue` | 出队 | 队头 `front` |

```text
出队 ←  [1] [2] [3] [4]  ← 入队
        front        rear
```

> ⭐ 和栈的区别只有一句话：
> **栈是同一端进出（LIFO），队列是一端进另一端出（FIFO）。**

---

## 二、假溢出：顺序队列的致命问题

### 普通顺序队列的实现

```c
int data[MAXSIZE];
int front = 0;          /* 队头下标 */
int rear  = 0;          /* 队尾下标，指向【下一个空位】 */

入队：data[rear++] = v;
出队：v = data[front++];
判空：front == rear
判满：rear == MAXSIZE      /* ❌ 问题就出在这 */
```

### 实测假溢出（MAXSIZE=5）

```text
入队 1 2 3 4 5：  front=0 rear=5  队列[1 2 3 4 5]

出队 3 个（1 2 3）：front=3 rear=5  队列[4 5]
```

> ⭐ **现在队列里只有 2 个元素，容量 5，但 `data[0] [1] [2]` 三个位置空着用不了。**
>
> 因为 `rear` 已经等于 5，再入队就报「满」：

```text
入队失败：rear 已到 5
```

### 这就是假溢出

| 概念 | 含义 |
|---|---|
| **真溢出** | 数组真的满了（存了 MAXSIZE 个） |
| **假溢出** | 数组前面有空位，但 `rear` 走不回去 |

> ⚠️ 假溢出的根源：**`rear` 只能往后走，不能回头。**
> 而队列的实际需求是「循环使用这块空间」。

---

## 三、循环队列：用取模绕回来

```c
入队：data[rear] = v;  rear = (rear + 1) % MAXSIZE;
出队：v = data[front]; front = (front + 1) % MAXSIZE;
```

### 实测：rear 从 4 绕回 0

```text
入队 1 2 3 4（MAXSIZE=5，最多存 4 个）：
  front=0 rear=1 size=1 [1]
  front=0 rear=2 size=2 [1 2]
  front=0 rear=3 size=3 [1 2 3]
  front=0 rear=4 size=4 [1 2 3 4]

第 5 个失败（少用一个单元）

出队 2 个：
  出队 1 → front=1 rear=4 size=3 [2 3 4]
  出队 2 → front=2 rear=4 size=2 [3 4]

再入队 5 6：
  入队后 front=2 rear=0 size=3 [3 4 5]    ← rear 从 4 绕回 0！
  入队后 front=2 rear=1 size=4 [3 4 5 6]
```

> ⭐ `(4 + 1) % 5 = 0` —— 下标绕回数组开头，**前面的空位重新可用**。
> 假溢出被彻底解决。

## 四、循环队列的三种判满方案（必考）

### 问题：`front == rear` 有两种含义

```text
空队列：front == rear == 0
满队列：front == rear == 0    ← 转了一圈又追上了
```

**两种情况下标完全一样**，所以不能只靠 `front == rear` 判断。

### 方案一：少用一个存储单元（最常见）

```c
判空：front == rear
判满：(rear + 1) % MAXSIZE == front
个数：(rear - front + MAXSIZE) % MAXSIZE
```

MAXSIZE=5 的数组最多存 **4** 个元素。

> ⭐ **代价是浪费一个位置，换来判据简单。** 这是教材和软考的标准答案。

### 方案二：增加计数器 size

```c
入队 size++，出队 size--
判空：size == 0
判满：size == MAXSIZE
```

优点：空间全用上。缺点：多维护一个变量。

### 方案三：增加标志 tag

```c
入队成功 tag = 1，出队成功 tag = 0
判空：front == rear && tag == 0
判满：front == rear && tag == 1
```

原理：用 `tag` 记住「上一次操作是进还是出」，从而区分空和满。

### 三种方案对比

| 方案 | 判满条件 | 空间利用率 | 软考出现频率 |
|---|---|---|---|
| 少用一个单元 | `(rear+1)%MAX == front` | (n-1)/n | **最高** |
| 计数器 size | `size == MAXSIZE` | 100% | 中 |
| 标志 tag | `front==rear && tag==1` | 100% | 中 |

## 五、元素个数公式：为什么要 +MAXSIZE

```c
size = (rear - front + MAXSIZE) % MAXSIZE
```

### 不加 MAXSIZE 会怎样

```text
front = 2, rear = 1（绕过了）
rear - front = 1 - 2 = -1
-1 % 5 在 C 里还是 -1        ← C 的取模结果符号跟被除数一致
```

所以必须先 `+ MAXSIZE` 变成正数，再取模：

```text
(1 - 2 + 5) % 5 = 4 % 5 = 4    ✓
```

实测验证：`front=2 rear=1` 时 `size=4`，队列里确实是 `[3 4 5 6]` 四个元素。

## 六、循环队列的遍历陷阱

```c
❌ for (i = front; i < rear; i++)         /* rear 比 front 小时一个都读不到 */
✅ for (i = 0; i < size; i++)
       读 data[(front + i) % MAXSIZE]
```

> ⚠️ **循环队列里 `front` 和 `rear` 的大小关系不确定**，
> 任何「从头到尾」的操作都必须在「逻辑下标」上做，不能直接比大小。

## 七、链队列

链队列用带头结点的单链表：`front` 指向头结点，`rear` 指向最后一个真节点。

```c
入队：rear->next = n;  rear = n;      /* O(1) */
出队：p = front->next;  front->next = p->next;  free(p);   /* O(1) */
判空：front == rear
```

### 一个致命的坑

```c
/* 出队最后一个节点时 */
if (Q->rear == victim) {        /* ⚠️ 必须判断 */
    Q->rear = Q->front;         /* rear 收回头结点 */
}
```

不写这两行，`rear` 会指向已经 `free` 的节点 —— **野指针**，
下次入队就往已释放的内存里写。

实测验证：

```text
出队 30（最后一个）→ 队列空了吗？是
再入队 99 → 99 -> NULL
→ 没崩，说明 rear 处理正确 ✓
```

> ⭐ 链队列**没有假溢出**，也没有容量上限。
> 但每节点多一个指针，而且每次入队要 `malloc`（比循环队列慢）。

### 顺序循环队列 vs 链队列

| 对比项 | 循环队列 | 链队列 |
|---|---|---|
| 存储 | 数组，连续 | 链式，分散 |
| 长度 | 固定，最多 MAXSIZE-1 | 动态 |
| 判满 | `(rear+1)%MAX == front` | 不存在 |
| 额外空间 | 无 | 每节点 1 个指针 |
| 入队出队 | O(1) | O(1) |
| 缓存友好 | 好 | 差 |
| 选用 | 长度可预估 | 长度不确定 |

## 八、队列的两个经典应用

### ① 杨辉三角（队列法）

```text
思路：队列里放「当前行」。生成下一行时逐个出队，
      边出边把「相邻两数之和」入队到队尾。

第 1 行：   1
第 2 行：   1   1
第 3 行：   1   2   1
第 4 行：   1   3   3   1
第 5 行：   1   4   6   4   1
第 6 行：   1   5  10  10   5   1
```

> ⭐ 关键：**出队和入队互不干扰**（出队从队头、入队到队尾），
> 所以能在一趟里完成整行更新。

### ② 约瑟夫环（循环队列）

```text
n 个人围成一圈，报数到 m 的人出圈，求最后剩下谁。

n=7, m=3 → 出圈顺序 3 6 2 7 5 1，最后剩下 4
n=5, m=2 → 出圈顺序 2 4 1 5，最后剩下 3
```

**思路**：

```text
前 m-1 个人：出队后立刻入队（相当于「跳过」，绕到队尾）
第 m 个人  ：真的出队（出圈）
重复直到只剩 1 个
```

> ⭐ **循环队列天生适合「围成一圈」的问题。**
