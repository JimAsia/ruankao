## 二、必背考点

### 2.1 访问控制

| 修饰符 | 类内 | 派生类 | 类外 |
|---|---|---|---|
| `public` | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✗ |
| `private` | ✓ | ✗ | ✗ |

> ⭐ `protected` 的唯一价值就是「派生类能用，类外不能用」。

### 2.2 构造与析构的顺序 ⭐

**构造**：基类 → 成员对象 → 派生类自身
**析构**：派生类自身 → 成员对象 → 基类

实测（`306`）：

```text
构造① 基类 BasePart
构造② 成员 MemberPart
构造③ 派生类 Derived
——— d 离开作用域 ———
析构③ 派生类 Derived
析构② 成员 MemberPart
析构① 基类 BasePart
```

> ⭐ 一句话记：**构造从"根"往上，析构从"顶"往下** —— 正好相反。
> 为什么？因为派生类可能用到基类和成员，所以必须等它们先构造好；
> 析构时派生类先走，否则基类先没了派生类就没法析构。

### 2.3 拷贝构造的调用时机

| 场景 | 是否拷贝 | 实测 |
|---|---|---|
| 传值传参 `f(t)` | **拷贝 1 次** | 1 |
| 传引用 `f(T&)` | 不拷贝 | 0 |
| 传常引用 `f(const T&)` | 不拷贝 | 0 |
| 用对象初始化另一个对象 `T b = a` | **拷贝 1 次** | 1 |
| 函数返回临时对象 | 通常不拷贝（RVO） | 0 |

> ⭐ 考试常问「哪几种情况会调用拷贝构造函数」，答案就是：
> **用同类型对象初始化新对象**、**函数传值传参**、**函数返回对象（可能被优化）**。

### 2.4 继承方式

| 基类中的访问级别 | public 继承 | protected 继承 | private 继承 |
|---|---|---|---|
| public | public | protected | private |
| protected | protected | protected | private |
| private | 不可访问 | 不可访问 | 不可访问 |

> ⭐ `private` 成员**在任何继承方式下都不可直接访问**，只能通过基类的 public/protected 成员函数。

### 2.5 多态：静态绑定 vs 动态绑定 ⭐⭐

**关键区别：是不是虚函数 + 是不是通过指针/引用调用。**

实测（`306`）：

```cpp
Circle c;
Shape *p = &c;
p->show();    // 非虚 → Shape::show        （静态绑定，编译期定）
p->draw();    // 虚   → Circle::draw        （动态绑定，运行期定）

c.show();     // Circle::show（直接调对象，用对象自己的）
c.draw();     // Circle::draw
```

**三条结论**：

```text
① 非虚函数：看【指针/引用的静态类型】，编译期就定了
② 虚函数 + 指针/引用调用：看【对象的实际类型】，运行期才定
③ 虚函数 + 对象直接调用：不涉及多态，用对象自己的版本
```

**虚析构函数**：

```cpp
class Shape {
public:
    virtual ~Shape() {}     // 基类析构必须是虚的
};
```

> ⚠️ 如果基类析构不是虚的，`delete p`（p 是基类指针指向派生类对象）
> 只会调基类析构，**派生类的资源泄漏**。这是必考的一个坑。

### 2.6 纯虚函数与抽象类

```cpp
class Abstract {
public:
    virtual int area() const = 0;   // = 0 表示纯虚函数
};
```

**两条规则**：

```text
① 含有纯虚函数的类是【抽象类】，不能实例化（不能定义对象）
② 派生类必须实现所有纯虚函数，否则它也是抽象类
```

实测：

```text
Abstract *pa = &s;  pa->area() = 25   ← 通过抽象类指针可以调
Abstract a;                            ← 编译错误
```

### 2.7 重载 / 重写 / 隐藏 ⭐

| 概念 | 发生位置 | 决定时机 | 条件 |
|---|---|---|---|
| **重载**（overload） | **同一个类** | 编译期 | 同名、**参数不同** |
| **重写**（override） | 基类与派生类 | **运行期** | **虚函数**、签名相同 |
| **隐藏**（hide） | 基类与派生类 | 编译期 | 同名但非虚，或签名不同 |

实测：

```text
d.f(3)    = 3       ┐
d.f(3,4)  = 7       ├ 同一类里同名不同参 → 重载
d.f(2.5)  = 2.5     ┘
```

> ⭐ 记法：**重载在类内，重写在类间，隐藏是"名字撞了但没构成重写"**。

### 2.8 静态成员

```cpp
class Counter {
public:
    static int created;         // 声明
    static int get() { return created; }
};
int Counter::created = 0;       // 定义（必须在类外）
```

**三个特点**：

```text
① 属于类，不属于对象 —— 所有对象共享同一份
② 可以用 类名::成员 直接访问，不需要对象
③ 静态成员函数没有 this 指针，不能访问非静态成员
```

实测：创建 3 个对象后 `Counter::get() = 3`。

### 2.9 引用 vs 指针

| | 引用 | 指针 |
|---|---|---|
| 是否必须初始化 | **必须** | 可以不初始化 |
| 能否改变指向 | **不能**（一旦绑定） | 能 |
| 能否为空 | **不能** | 能（nullptr） |
| 是否占额外空间 | 语义上不占 | 占（一个地址大小） |
| 访问方式 | 直接 `r` | 需解引用 `*p` |
| 安全性 | 较高 | 较低（可能野指针） |

### 2.10 运算符重载

```cpp
Complex operator+(const Complex &o) const {
    return Complex(re + o.re, im + o.im);
}
```

**五条不能重载的运算符**：

```text
.   成员访问
.*  成员指针访问
::  作用域解析
?:  三目条件
sizeof
```

> ⭐ 这五个是死记的，考选择题时直接选。

### 2.11 模板与 STL（Standard Template Library，标准模板库）常识

| 容器 | 底层 | 特点 |
|---|---|---|
| `vector` | 动态数组 | 随机访问 O(1)，尾部插入快 |
| `list` | 双向链表 | 插入删除 O(1)，不能随机访问 |
| `deque` | 分段数组 | 头尾插入都快 |
| `map` / `set` | **红黑树** | 有序，查找 O(log n) |
| `unordered_map` | **哈希表** | 无序，平均 O(1) |

> ⭐ 常考：`map` 的底层是**红黑树**（有序），`unordered_map` 是**哈希表**（无序）。

### 2.12 程序设计语言基础

**编译 vs 解释**：

| | 编译型 | 解释型 |
|---|---|---|
| 代表 | C、C++ | Python、JavaScript |
| 过程 | 整体翻译成机器码再执行 | 逐行翻译执行 |
| 速度 | **快** | 慢 |
| 跨平台 | 差（要重新编译） | **好** |
| 错误发现 | 编译期 | 运行期 |

**Java 是混合型**：先编译成字节码，再由 JVM 解释/即时编译执行。

**类型系统**：

```text
静态类型：编译期就确定类型（C/C++/Java）
动态类型：运行期才确定（Python/JS）
强类型：不允许隐式类型转换（Python）
弱类型：允许隐式转换（C/JS）
```

**参数传递**：

```text
传值：拷贝一份，函数内改不影响外面
传引用：传地址，函数内改会影响外面
```

> ⚠️ C 只有传值（指针也是传值，只是值是个地址）；C++ 有真正的引用传递。

**其余术语全称**（主要出现在上方表格中，为避免撑坏列宽未在原处展开）：

- RVO（Return Value Optimization，返回值优化）

## 三、读程序写结果模板

考这类题的固定步骤：

```text
① 看有没有虚函数 → 决定是静态绑定还是动态绑定
② 看调用方式是「指针/引用」还是「对象直接调」→ 决定会不会多态
③ 看构造/析构顺序 → 基类→成员→派生，析构相反
④ 看有没有传值 → 数拷贝构造次数
```

**一道典型题**：

```cpp
class A { public: A(){cout<<"A";} ~A(){cout<<"~A";} };
class B : public A { public: B(){cout<<"B";} ~B(){cout<<"~B";} };
int main() { B b; }
```

输出：`AB~B~A`

> 先 A 后 B（构造从基类到派生），析构 `~B~A`（派生先析构）。

## 四、自测 15 题

**1.** 构造函数的执行顺序是什么？析构呢？

**2.** 基类的析构函数为什么通常要声明为虚函数？

**3.** `public` 继承下，基类的 `protected` 成员在派生类中是什么访问级别？

**4.** 基类的 `private` 成员在派生类中能直接访问吗？

**5.** 什么是抽象类？能实例化吗？

**6.** 重载和重写的区别（三条）？

**7.** 通过基类指针调用非虚函数，实际执行的是哪个版本？

**8.** 哪些情况会调用拷贝构造函数？

**9.** 静态成员属于类还是对象？如何在类外定义？

**10.** 引用和指针的三个区别？

**11.** 哪五个运算符不能重载？

**12.** `map` 和 `unordered_map` 的底层结构分别是什么？

**13.** 编译型语言和解释型语言的核心区别？

**14.** Java 属于编译型还是解释型？

**15.** 下面的代码输出什么？
```cpp
class A { public: A(){ cout<<"A"; } virtual ~A(){ cout<<"~A"; } };
class B : public A { public: B(){ cout<<"B"; } ~B(){ cout<<"~B"; } };
int main() { A *p = new B; delete p; }
```

---

### 答案与解析

**1.** 构造：**基类 → 成员对象 → 派生类自身**；析构：**派生类 → 成员对象 → 基类**（正好相反）。

**2.** 因为通过**基类指针 delete 派生类对象**时，若析构不是虚的，
只会调用基类析构，派生类的资源不会被释放，造成泄漏。

**3.** 仍是 **protected**（public 继承不改变 protected 的级别）。

**4.** **不能**。private 成员在任何继承方式下都不可直接访问。

**5.** 含有**纯虚函数**（`= 0`）的类；**不能实例化**。

**6.** ① 重载在**同一个类**内，重写在**基类与派生类**之间；
② 重载靠**参数不同**区分，重写要求**签名相同**；
③ 重载是**编译期**决定，重写（虚函数）是**运行期**决定。

**7.** **基类自己的版本**（静态绑定，看指针的静态类型）。

**8.** ① 用同类型对象**初始化**新对象；② **传值**传参；③ 函数**返回对象**（可能被 RVO 优化掉）。

**9.** 属于**类**，所有对象共享一份；必须在**类外**定义（`int Counter::created = 0;`）。

**10.** ① 引用必须初始化，指针可以不初始化；② 引用不能改绑，指针可以改指向；
③ 引用不能为空，指针可以是 nullptr。

**11.** `.`、`.*`、`::`、`?:`、`sizeof`。

**12.** `map` 是**红黑树**（有序）；`unordered_map` 是**哈希表**（无序）。

**13.** 编译型先把整个程序翻译成机器码再执行（快、跨平台差）；
解释型逐行翻译执行（慢、跨平台好）。

**14.** **混合型**：先编译成字节码，再由 JVM 解释或即时编译执行。

**15.** 输出 `AB~B~A`。
先构造 A 再构造 B；`delete p` 时因为析构是虚的，先调 `~B` 再调 `~A`。
（如果析构不是虚的，就只会输出 `AB~A`，`~B` 被漏掉 —— 这是经典陷阱。）

## 五、易错清单

1. 构造顺序**基类→成员→派生**，析构**派生→成员→基类**，别写成一样。
2. 基类析构**必须虚**，否则 `delete` 基类指针会漏掉派生类析构。
3. 非虚函数**看指针类型**，虚函数**看对象类型**。
4. 对象直接调用虚函数**不体现多态**（没有指针/引用）。
5. 重载在**类内**，重写在**类间**，隐藏是"同名但没构成重写"。
6. `private` 成员在任何继承方式下都**不可直接访问**。
7. 静态成员函数**没有 this**，不能访问非静态成员。
8. 引用**不能为空、不能改绑**，这是它和指针的本质区别。
9. `map` 是**红黑树**不是哈希表，`unordered_map` 才是哈希表。
10. C 语言**只有传值**（指针也是传值），C++ 才有真正的引用传递。
