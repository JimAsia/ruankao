# S3-05 考点手册 软件工程与项目管理

> 软件工程是 S3 里分值最高的一块（8–10 分），也是**最"套路化"**的一块。
> 题目几乎都在问「这个场景该用哪个模型/哪种测试/哪类维护」，
> 所以最好的复习方式是**对比表 + 判断依据**，而不是背定义。

---

## 一、知识结构

```text
软件工程
├── 生命周期模型 ── 瀑布 / 原型 / 螺旋 / 增量 / 敏捷 / V 模型
├── 需求分析 ───── 结构化（DFD、数据字典）/ 面向对象（UML）
├── 软件设计 ───── 模块化 / 耦合与内聚 / 体系结构
├── 测试 ──────── 黑盒 / 白盒 / 测试阶段 / 集成策略
├── 维护 ──────── 改正性 / 适应性 / 改善性 / 预防性
├── 项目管理 ───── 进度（甘特图、关键路径）/ 风险 / 成本
└── 质量 ──────── McCabe 复杂度 / CMMI / 可靠性
```

## 二、必背考点

### 2.1 生命周期模型 ⭐

| 模型 | 特点 | 适用场景 | 缺点 |
|---|---|---|---|
| **瀑布** | 阶段严格串行、文档驱动 | 需求**明确稳定** | 后期才发现错误，代价大 |
| **原型** | 先做样品给用户看 | 需求**不明确** | 原型可能被误当成品 |
| **螺旋** | 每次循环含**风险分析** | 大型、**高风险**项目 | 成本高、周期长 |
| **增量** | 分批交付、逐步完善 | 可以分批上线 | 需要良好的架构 |
| **敏捷** | 小步快跑、拥抱变化 | 需求**频繁变化** | 文档少，依赖团队水平 |
| **V 模型** | 开发与测试一一对应 | 强调测试 | 仍是串行 |

**判断依据（看到这些词就选它）**：

```text
"需求明确、稳定、不变"     → 瀑布
"需求不明确、需要和用户确认" → 原型
"高风险、大型、需要风险分析" → 螺旋
"分批交付、逐步上线"        → 增量
"需求频繁变化、快速迭代"     → 敏捷
```

> ⭐ **螺旋模型的唯一标志是「风险分析」**，题目里出现这四个字就选螺旋。

### 2.2 需求分析

**结构化分析的核心是 DFD（数据流图）**，四种元素：

| 元素 | 画法 | 含义 |
|---|---|---|
| 外部实体 | 矩形 | 数据的来源或去向（人、系统） |
| 加工（处理） | 圆角矩形/圆 | 对数据做什么 |
| 数据存储 | 开口矩形/双横线 | 数据库或文件 |
| 数据流 | 箭头 | 数据的流动方向 |

**DFD 分层**：顶层图（只有一个加工）→ 0 层图 → 1 层图 …（自顶向下，逐层细化）。

**数据字典**：对 DFD 中每个数据流、数据项、数据存储的**精确定义**。

> ⚠️ DFD 里**没有控制流**，也没有"判断"。它只描述数据怎么流。

### 2.3 UML（Unified Modeling Language，统一建模语言）图

| 分类 | 包含的图 |
|---|---|
| **结构图**（静态） | 类图、对象图、**组件图**、**部署图**、包图、组合结构图 |
| **行为图**（动态） | **用例图**、**时序图**（顺序图）、协作图、**活动图**、**状态图**、交互概览图 |

**四个最常考的画法用途**：

```text
用例图   ：谁（参与者）能做什么（用例）—— 需求阶段
类图     ：类与类的关系（关联、聚合、组合、继承、依赖）
时序图   ：对象之间按【时间顺序】的消息交互
活动图   ：业务流程 / 工作流（类似流程图）
状态图   ：一个对象在生命周期内的状态变化
```

> ⭐ 区分时序图和活动图：**时序图强调"谁和谁、按什么顺序发消息"；
> 活动图强调"流程走到哪一步"**。

### 2.4 耦合与内聚 ⭐⭐

**耦合（模块之间）——越低越好**：

```text
低 ←──────────────────────────────────────→ 高
非直接  数据  标记  控制  外部  公共  内容
```

| 耦合类型 | 含义 | 例子 |
|---|---|---|
| **非直接** | 模块间无任何联系 | 最好的 |
| **数据** | 只传简单数据参数 | `f(int x)` |
| **标记** | 传整个结构体，但其实只用其中一个字段 | `f(Student s)` 只用了 s.id |
| **控制** | 传控制信号（如 flag） | `f(bool isPrint)` |
| **外部** | 共同访问外部设备/格式 | 都读写同一个文件格式 |
| **公共** | 共同访问全局变量 | 都用 global counter |
| **内容** | 一个模块直接访问另一个模块内部 | 最差 |

**内聚（模块内部）——越高越好**：

```text
高 ←──────────────────────────────────────→ 低
功能  顺序  通信  过程  时间  逻辑  偶然
```

| 内聚类型 | 含义 |
|---|---|
| **功能** | 所有部分完成**一个**明确功能（最好） |
| **顺序** | 前一部分的输出是后一部分的输入 |
| **通信** | 都操作**同一组数据** |
| **过程** | 按固定顺序执行，但数据无传递 |
| **时间** | 在同一时间段执行（如初始化） |
| **逻辑** | 逻辑上相关，由参数选择执行哪一个 |
| **偶然** | 毫无关系地凑在一起（最差） |

> ⭐ 设计原则：**高内聚、低耦合**。
> 选择题常给一段描述让你判断是哪种耦合/内聚，按上表对号入座。

### 2.5 测试

**黑盒测试**（不看代码，只看输入输出）：

| 方法 | 思路 |
|---|---|
| **等价类划分** | 把输入分成有效/无效类，每类取一个代表 |
| **边界值分析** | 取边界及其两侧（**最常考**，因为错误常出在边界） |
| **错误推测** | 凭经验猜哪里会错 |
| **因果图** | 输入条件与输出的组合关系 |

**白盒测试**（看代码结构，按覆盖率从低到高）：

```text
语句覆盖 < 判定覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖
```

> ⭐ 覆盖强度递增，**路径覆盖最强**。但注意：覆盖率高 ≠ 发现所有错误。

**测试阶段**：

```text
单元测试 → 集成测试 → 系统测试 → 验收测试
```

**集成策略**：

| 策略 | 特点 |
|---|---|
| 自顶向下 | 需要**桩模块**（模拟下层） |
| 自底向上 | 需要**驱动模块**（模拟上层） |
| 三明治 | 两者结合 |

> ⭐ 记住方向：**自顶向下缺下面 → 用桩；自底向上缺上面 → 用驱动。**

### 2.6 软件维护的四种类型

| 类型 | 触发原因 | 占比（大致） |
|---|---|---|
| **改正性** | 发现**遗留 bug** | 约 20% |
| **适应性** | 环境变了（操作系统、硬件升级） | 约 25% |
| **改善性（完善性）** | 用户提**新需求**、要加功能 | **约 50%** |
| **预防性** | 主动改造，为将来好维护 | 约 5% |

> ⭐ **改善性维护占比最大**（一半以上），这是高频考点。

### 2.7 项目管理

**两种进度图**：

| 图 | 能看出什么 |
|---|---|
| **甘特图** | 任务的起止时间、并行关系；**看不出依赖** |
| **PERT 图（网络图）** | 任务依赖关系、**关键路径** |

**关键路径三句话**：

```text
① 关键路径是【最长】的路径，长度 = 总工期
② 关键活动的总浮动时间 = 0
③ 要缩短工期，只能压缩关键活动
```

### 2.8 软件质量

**McCabe 环形复杂度**：

```text
V(G) = E − N + 2         （E 边数，N 节点数）
V(G) = 判定节点数 + 1
```

含义：**独立的路径条数**，也就是至少需要多少个测试用例才能覆盖所有分支。
一般认为 **V(G) ≤ 10** 时模块可测性良好。

**CMMI（Capability Maturity Model Integration，能力成熟度模型集成）五个等级**（由低到高）：

```text
初始级 → 已管理级 → 已定义级 → 量化管理级 → 优化级
```

**其余术语全称**（主要出现在上方表格中，为避免撑坏列宽未在原处展开）：

- PERT（Program Evaluation and Review Technique，计划评审技术）

## 三、计算题模板

### 模板 1：McCabe 环形复杂度

```text
① 数节点数 N（每个圆圈）
② 数边数 E（每个箭头）
③ V(G) = E − N + 2
④ 或用「判定节点数 + 1」验算
```

**实测**（`305`，一个 while + 一个 if 的函数）：

```text
N = 6，E = 7
V(G) = 7 − 6 + 2 = 3
判定节点 2 个（while、if）→ 2 + 1 = 3  ✓ 两式一致
```

> ⭐ 两条公式结果必须一样。如果不一样，一定是 N 或 E 数错了。

### 模板 2：关键路径

```text
① 正推：ES = 所有前驱 EF 的最大值；EF = ES + 工期
② 总工期 = 所有 EF 的最大值
③ 逆推：LF = 所有后继 LS 的最小值（无后继则为总工期）；LS = LF − 工期
④ 总浮动 = LS − ES，为 0 的就是关键活动
```

**实测**（`305`，8 个活动）：

| 活动 | 工期 | ES | EF | LS | LF | 总浮动 |
|---|---|---|---|---|---|---|
| A | 2 | 0 | 2 | 0 | 2 | **0** ← 关键 |
| B | 3 | 0 | 3 | 1 | 4 | 1 |
| C | 4 | 2 | 6 | 2 | 6 | **0** ← 关键 |
| D | 2 | 2 | 4 | 4 | 6 | 2 |
| E | 5 | 3 | 8 | 4 | 9 | 1 |
| F | 3 | 6 | 9 | 6 | 9 | **0** ← 关键 |
| G | 2 | 9 | 11 | 9 | 11 | **0** ← 关键 |
| H | 4 | 11 | 15 | 11 | 15 | **0** ← 关键 |

```text
总工期 = 15
关键路径 = A → C → F → G → H（2+4+3+2+4 = 15）
另一条路 B → E → G → H = 3+5+2+4 = 14，差 1，所以 B 的浮动是 1
```

## 四、自测 15 题

**1.** 需求明确且稳定、文档驱动的项目，最适合哪种模型？

**2.** 哪种模型的核心是「风险分析」？

**3.** 需求不明确、需要和用户反复确认时，用哪种模型？

**4.** DFD 的四种基本元素是什么？

**5.** UML 中强调对象之间按时间顺序交互的是哪种图？

**6.** 耦合由低到高的顺序是什么？

**7.** 内聚由高到低的顺序是什么？

**8.** 一个模块直接访问另一个模块的内部数据，属于哪种耦合？

**9.** 黑盒测试最常用的两种方法？

**10.** 白盒测试中覆盖最强的准则是什么？

**11.** 自顶向下集成需要什么模块？自底向上呢？

**12.** 软件维护中占比最大的是哪一类？

**13.** 甘特图和 PERT 图的核心区别？

**14.** 某程序流图 N=10，E=13，McCabe 复杂度是多少？意味着什么？

**15.** CMMI 的五个等级从低到高是什么？

---

### 答案与解析

**1.** **瀑布模型**。

**2.** **螺旋模型**。这是它区别于其他模型的唯一标志。

**3.** **原型模型**。

**4.** 外部实体、加工（处理）、数据存储、数据流。

**5.** **时序图**（顺序图）。

**6.** 非直接 → 数据 → 标记 → 控制 → 外部 → 公共 → 内容（由低到高）。

**7.** 功能 → 顺序 → 通信 → 过程 → 时间 → 逻辑 → 偶然（由高到低）。

**8.** **内容耦合**（最差的一种）。

**9.** **等价类划分、边界值分析**（另有错误推测、因果图）。

**10.** **路径覆盖**。

**11.** 自顶向下需要**桩模块**；自底向上需要**驱动模块**。

**12.** **改善性（完善性）维护**，约占一半。

**13.** 甘特图看**起止时间和并行**，看不出依赖；PERT 图能看**依赖关系和关键路径**。

**14.** `V(G) = 13 − 10 + 2 = 5`。表示有 **5 条独立路径**，
至少需要 5 个测试用例覆盖所有分支；5 ≤ 10，模块复杂度可接受。

**15.** 初始级 → 已管理级 → 已定义级 → 量化管理级 → 优化级。

## 五、易错清单

1. 螺旋模型的标志是**风险分析**，不要和增量模型混。
2. 自顶向下用**桩**，自底向上用**驱动** —— 方向别记反。
3. 耦合越低越好，内聚越高越好；**高内聚低耦合**。
4. 内容耦合最差，非直接耦合最好；功能内聚最好，偶然内聚最差。
5. 白盒覆盖强度：语句 < 判定 < 条件 < 判定/条件 < 条件组合 < 路径。
6. **改善性维护占比最大**（约 50%），不是改正性。
7. 甘特图**看不出依赖**，这是它的硬伤。
8. 关键路径是**最长**路径，不是最短。
9. 关键活动浮动时间为 0；压缩非关键活动不能缩短工期。
10. McCabe 的 `E − N + 2` 里，无判定的顺序结构结果是 **1**，不是 0。
